## Backup hooks
Hooks run inside a specific container, matched by label selector:
```yaml
hooks:
  resources:
    - name: <hook-name>
      labelSelector:
        matchLabels:
          <app-label-key>: <app-label-value>
      pre:
        - exec:
            container: <container-name>
            command: ["/bin/bash", "-c", "<lock-command>"]
      post:
        - exec:
            container: <container-name>
            command: ["<unlock-command>"]
```
- `pre` hooks run before backup starts (e.g. lock app for writes, flush DB
  transactions to disk).
- `post` hooks run after backup completes (e.g. remove lock file).
- `Restore` resources support `postHooks` the same way — commonly used to
  remove a lock file left behind after restoring into a new namespace.

## Useful velero CLI commands
```
# convenience alias to reach the velero binary inside its pod
alias velero='oc -n openshift-adp exec deployment/velero -c velero -it -- ./velero'

velero get schedule
velero backup create --from-schedule <schedule-name>
velero get backup
velero backup logs <backup-name>              # add --cacert if custom CA is used
velero get restore
velero delete backup <backup-name>
```

## Restoring into a new namespace
```yaml
apiVersion: velero.io/v1
kind: Restore
metadata:
  name: <restore-name>
  namespace: openshift-adp
spec:
  backupName: <backup-name>
  namespaceMapping:
    <source-namespace>: <target-namespace>
```

## Post-restore app identity cleanup
After restoring into a new namespace, update any deployment env vars that
hardcode the old identity/URL — same idea as the manual `TITLE` change in
Part 1:
```
oc -n <target-namespace> set env deployment/<name> \
  <ENV_VAR_1>=<new-value> \
  <ENV_VAR_2>=<new-value>
```

## Key Gotchas (exam traps)

- OADP backups need label selectors scoped tightly — an unfiltered backup can
  pull in unrelated cluster resources.
- Never run the live app against a volume while importing/restoring data into
  it — risk of corruption.
