## 1. Core Concept

- OAuth LDAP IdP = **authn only** (validates/creates users). It does **NOT** pull group membership.
- **Group Sync** = separate mechanism that mirrors LDAP groups → native OpenShift `Group` objects, so RBAC (RoleBindings) can reference them.
- Sync is **one-way**: LDAP → OpenShift only. Manually-edited synced groups get overwritten on next run.

**4 building blocks for automated sync:**
1. Project (namespace for the sync workload)
2. ServiceAccount
3. ClusterRole (permissions on `groups`)
4. ClusterRoleBinding

Plus: `LDAPSyncConfig` (as ConfigMap), bindPassword Secret, CA ConfigMap, CronJob.

---

## 2. ClusterRole for Sync ServiceAccount

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: ldap-group-sync-acct
rules:
  - apiGroups: ['', 'user.openshift.io']
    resources: [groups]
    verbs: [get, list, create, update]
```
**Why this matters:** Must be **ClusterRole** (not Role) — `Group` objects are cluster-scoped. Note **no `delete`** — sync never removes groups even if they vanish from LDAP.

## 3. LDAPSyncConfig — Client Config Block

```yaml
url: ldaps://1.2.3.4:636
bindDN: cn=administrator,dc=example,dc=com
bindPassword:
  file: /etc/secrets/bindPassword
ca: /etc/config/ca.crt
insecure: false
```
**Why this matters:**
- `insecure: false` is **mandatory** with `ldaps://` — exam gotcha: `insecure: true` + `ldaps://` is a misconfiguration.
- `bindPassword.file` / `ca` paths = wherever the volumes are actually mounted in the pod (commonly `/etc/secrets`, `/etc/config`) — **not** a fixed OpenShift requirement, just convention. Must match `volumeMounts.mountPath` exactly or sync fails with "file not found."

## 4. LDAP Query Definition Block (shared shape for groupsQuery/usersQuery)

```yaml
baseDN: ou=groups,dc=example,dc=com
scope: sub
derefAliases: never
timeout: 0
filter: (objectClass=group)
pageSize: 0
```
| Field | Why this matters |
|---|---|
| `baseDN` | Wrong OU = **silently zero results**, not an error |
| `filter` | Omitted = returns ALL entries — easy accidental over-match |
| `timeout`/`pageSize` | `0` = "unlimited," not "disabled" |

**Maps directly to `ldapsearch`** (validate before wiring into config, same habit as OAuth IdP testing):
```bash
ldapsearch -x -H ldap://1.2.3.4:389 \
  -D "cn=administrator,dc=example,dc=com" -W \
  -b "ou=groups,dc=example,dc=com" -s sub \
  "(objectClass=group)"
```
Zero results here = zero groups in dry-run too. Debug the search params, not the sync config.

## 5. Three Schema Types

| Schema key | `groupsQuery`? | Membership attr | Notes |
|---|---|---|---|
| `rfc2307` | Yes | `member` (on group) | Standard LDAP / 389-DS |
| `activeDirectory` | **No** | `memberOf` (on user) | Groups derived purely from walking users |
| `augmentedActiveDirectory` | Yes | `memberOf` (on user) | AD membership model + richer group attrs via groupsQuery |

**RFC2307** = IETF schema standard (posixGroup/posixAccount, `member` attr).
**389-DS** = a real LDAP server product (Red Hat's) that implements RFC2307 by default.

**Exam trap:** matching `memberOf` under an `rfc2307:` block, or adding `groupsQuery` under plain `activeDirectory:` — wrong schema/direction pairing.

### Full RFC2307 example
```yaml
kind: LDAPSyncConfig
apiVersion: v1
url: ldap://example.com:389
insecure: false
rfc2307:
  groupsQuery: {baseDN: "ou=groups,dc=example,dc=com", scope: sub, derefAliases: never, pageSize: 0}
  groupUIDAttribute: dn
  groupNameAttributes: [ cn ]
  groupMembershipAttributes: [ member ]
  usersQuery: {baseDN: "ou=users,dc=example,dc=com", scope: sub, derefAliases: never, pageSize: 0}
  userUIDAttribute: dn
  userNameAttributes: [ mail ]
  tolerateMemberNotFoundErrors: false
  tolerateMemberOutOfScopeErrors: false
```
**Why this matters (biggest gotcha):** `userNameAttributes` here **must match what the OAuth LDAP IdP uses** as username. Mismatch → sync runs clean, groups get created, but logged-in users don't show as members → RBAC silently doesn't work.

`tolerate*Errors` default to **false** = strict by default. Dangling member refs or out-of-scope users **fail the whole sync** unless explicitly set `true`.

### Active Directory variant
```yaml
kind: LDAPSyncConfig
apiVersion: v1
url: ldap://ad.example.com:389
activeDirectory:
  usersQuery: {baseDN: "ou=users,dc=example,dc=com", scope: sub, derefAliases: never, filter: (objectclass=person), pageSize: 0}
  userNameAttributes: [ mail ]
  groupMembershipAttributes: [ memberOf ]
```

## 6. Running Sync Manually

```bash
oc adm groups sync --sync-config=config.yaml --confirm
```
| Flag | Behavior |
|---|---|
| `--confirm` omitted | **Dry run** — shows what would change, applies nothing |
| `--confirm` present | Actually creates/updates OpenShift Groups |

**Why this matters:** Always dry-run a new config first. `config.yaml` here **is** the full `LDAPSyncConfig` resource itself.

## 7. Automating via CronJob — Full Pipeline

```bash
oc new-project ldap-group-sync
```
ServiceAccount → ClusterRole → ClusterRoleBinding (as above, namespace/name must all line up) → ConfigMap (sync.yaml) → Secret (bindPassword) → ConfigMap (CA cert) → CronJob.

```yaml
kind: CronJob
apiVersion: batch/v1
metadata:
  name: ldap-group-sync-acct
  namespace: ldap-group-sync
spec:
  schedule: "*/30 * * * *"
  concurrencyPolicy: Forbid
  jobTemplate:
    spec:
      backoffLimit: 0
      ttlSecondsAfterFinished: 1800
      template:
        spec:
          containers:
            - name: ldap-group-sync
              image: "registry.redhat.io/openshift4/ose-cli:latest"
              command: ["/bin/bash", "-c", "oc adm groups sync --sync-config=/etc/config/sync.yaml --confirm"]
              volumeMounts:
                - {mountPath: "/etc/config", name: "ldap-sync-volume"}
                - {mountPath: "/etc/secrets", name: "ldap-bind-password"}
                - {mountPath: "/etc/ldap-ca", name: "ldap-ca"}
          volumes:
            - {name: "ldap-sync-volume", configMap: {name: "ldap-group-sync-acct"}}
            - {name: "ldap-bind-password", secret: {secretName: "ldap-secret"}}
            - {name: "ldap-ca", configMap: {name: "ca-config-map"}}
          restartPolicy: "Never"
          serviceAccountName: "ldap-group-sync-acct"
```

**Object roles — don't confuse these:**
| Object | Role |
|---|---|
| Secret (`ldap-secret`) | LDAP/AD bind **authentication** credential |
| ConfigMap (`ca-config-map`) | **TLS CA cert** for validating `ldaps://` connection |
| ConfigMap (`ldap-group-sync-acct`) | The **input file** (`sync.yaml` = full `LDAPSyncConfig`) that `oc adm groups sync` reads — the CronJob just executes the same command you ran manually in step 6, pointed at this file |

**Why this matters:**
- `concurrencyPolicy: Forbid` — stops overlapping runs if a sync takes longer than the schedule interval.
- `ttlSecondsAfterFinished` — should roughly match schedule interval (too short = logs deleted before you can debug; too long = clutter).
- `serviceAccountName` **must match** the SA created + bound earlier — mismatch = pod runs as `default` SA → 403 on `groups`.
- Project name (`ldap-group-sync`) is **not mandatory** — any name works, but `namespace:` fields and `serviceAccountName:` must stay consistent across all objects.

## 8. Practical Additions Beyond Courseware (learned during lab, not in theory doc)

The theory PDF only shows *finished* ConfigMap/Secret YAML — it never shows how to **create** them from real files. Lab requires:

```bash
# ConfigMap for sync config + CA cert together
oc create configmap rhds-config \
  --from-file rhds-sync.yaml=rhds-sync.yaml,ca.crt=rhds_ca.crt

# Secret for bind password
oc create secret generic ldap-secret --from-file=bindPassword=/path/to/password/file
```

**`--from-file` syntax — two forms:**
| Form | Syntax | Behavior |
|---|---|---|
| Implicit key | `--from-file=localfile.txt` | Key = filename as-is |
| Explicit key | `--from-file=key=localfile.txt` | Key = whatever you set on the left, regardless of actual filename on disk |

**Why this matters:** The **key name inside the ConfigMap/Secret becomes the mounted filename** in the pod. It must exactly match what `LDAPSyncConfig` references (e.g., `ca: /etc/config/ca.crt` requires the key to literally be `ca.crt`, even if your local file is `rhds_ca.crt`). Two ways to satisfy this:
- Rename local file to `ca.crt` first, then use implicit form.
- Or keep the original filename and use `ca.crt=rhds_ca.crt` to rename during import.

Both produce identical ConfigMap content — only the **command style** differs.

## Quick Debug Checklist
- [ ] Dry-run (`oc adm groups sync` without `--confirm`) before trusting any new config
- [ ] `ldapsearch` with same `baseDN`/`scope`/`filter` to sanity-check before wiring into YAML
- [ ] `userNameAttributes` in sync config == username format used by OAuth LDAP IdP
- [ ] File paths in `LDAPSyncConfig` (`bindPassword.file`, `ca`) match `volumeMounts.mountPath` + ConfigMap/Secret key names exactly
- [ ] `serviceAccountName` in CronJob matches the bound ServiceAccount
- [ ] Correct schema block (`rfc2307` / `activeDirectory` / `augmentedActiveDirectory`) matches your LDAP server type
