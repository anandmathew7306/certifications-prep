# 4.1 Enabling the RHACM Observability Stack

- **Observability** = unified fleet-wide metrics for cluster/workload health — important for anticipating issues, tuning performance, and postmortems.
- Built on CNCF open-source tools: **Prometheus** (scrapes/stores time-series metrics, runs rules, alerts) · **Thanos** (aggregates data from many Prometheus instances across clusters for global querying; needs S3-compatible long-term storage) · **Alertmanager** (dedupes/groups/routes alerts to Slack/email/PagerDuty, can silence/inhibit) · **Grafana** (v11.1.5, dashboards).
- **Key pods/controllers**: `multicluster-observability-operator` (deployed by `multiclusterhub-operator`; pushes hub data to managed clusters, deploys Thanos Compactor) · `observability-endpoint-operator` (auto-deployed per managed cluster; runs the metrics collector pulling from that cluster's own Prometheus, sends to hub) · **observability add-on controller** (API server updating managed-cluster logs).
- Complements — doesn't replace — the built-in **RHOCP monitoring stack** (self-updating, platform-only by default; can extend to user-defined projects from 4.6+).
- **Not enabled by default** (needs persistent storage/CPU/memory) even though it's always installed on the hub.
- **Prerequisites**: cluster-admin / `cluster-manager-admin` / S3-admin role · a storage class (if no default exists) · direct network access to hub · an S3-compatible object store (AWS S3, GCS, OpenShift Data Foundation, etc.) · ~2701m CPU + ~11972Mi memory.
- **Enable flow (CLI)**: create `open-cluster-management-observability` namespace → create/copy the `multiclusterhub-operator-pull-secret` (or fall back to the cluster's `pull-secret`) → provision object storage (e.g. an `ObjectBucketClaim`) → extract bucket info/credentials → build the `thanos-object-storage` Secret → create the **`MultiClusterObservability`** CR (references that secret, sets storage sizes/class, `enableDownsampling`, `observabilityAddonSpec`, optional `nodeSelector`) → this spins up Thanos/Alertmanager/Grafana pods in the observability namespace.
- Verify via `oc get pods -n open-cluster-management-observability`, checking the `multicluster-observability-operator` deployment, and opening **Grafana** (linked from Infrastructure → Clusters in the console).
