# 5.3 Configuring GitOps for RHACM

- RHACM's operator does **not** bundle Argo CD — you must separately install the **OpenShift GitOps operator** (from OperatorHub), which creates a default Argo CD instance in the `openshift-gitops` namespace. Red Hat recommends installing it via an **RHACM governance policy** rather than manually, for consistency.
- **Push model** → install GitOps operator on the **hub** only. **Pull model** → install it on the hub **and** every managed cluster that will deploy apps.
- You (and other OpenShift admins) get no Argo CD console access by default (`defaultPolicy: ""`) — grant access by adding RBAC policy lines to the `ArgoCD` resource's `spec.rbac.policy` (e.g. mapping an OpenShift group to `role:admin`).
- The default Argo CD instance lacks permissions to manage everything RHACM needs — grant it **cluster-admin** via a `ClusterRoleBinding` to its service account `openshift-gitops-argocd-application-controller`.
- For **private Git servers** with custom-CA certs: add the CA to a ConfigMap in `openshift-gitops` (use the `config.openshift.io/inject-trusted-cabundle: 'true'` label to auto-populate it from the cluster's trust bundle) and mount it into the ArgoCD instance's `repo.volumeMounts`/`volumes`.
- **Registering managed clusters with Argo CD**: create a **`GitOpsCluster`** resource referencing the Argo CD namespace + a **`Placement`** that selects which clusters to register. (You don't need to separately register clusters with Argo CD instances running *on* the managed clusters themselves.)
