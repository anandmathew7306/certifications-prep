# 5.7 Troubleshooting Application Lifecycle Issues

- Start with the RHACM **Topology view** (aggregates errors, click a component for YAML/details); if incomplete, check the **Argo CD console** — hub's instance for Push model, the specific managed cluster's instance for Pull model.
- **App fails to deploy**: usually a bad `ApplicationSet` (wrong Git branch/URL, expired private-repo credentials) or a `Placement` targeting the wrong clusters (check cluster labels match the selector).
- **OutOfSync status**: Argo CD detected a manual/local change but didn't auto-revert it — fix by enabling "Automatically sync when cluster state changes" in the console, or setting `syncPolicy.automated.selfHeal: true` in the ApplicationSet YAML.
- **Dysfunctional resource statuses** (usually a manifest problem in Git): `Not deployed`/`OutOfSync` = OpenShift rejected the resource (often a syntax/schema error) · `Pending` = accepted but waiting on reconciliation (e.g. PVC referencing a missing storage class, deployment waiting on pods) · `Error` = an actively failing resource (e.g. failing readiness/liveness probes).
- **GitOps integration issues**: missing private-repo CA trust, or (Push model at scale) the hub's Argo CD instance running out of CPU/memory — increase its resource allocation.
- Escalation: `oc adm must-gather --image=registry.redhat.io/rhacm2/acm-must-gather-rhel9:v2.13 --dest-dir=...` → archive with cluster ID + timestamp → open a support case.
