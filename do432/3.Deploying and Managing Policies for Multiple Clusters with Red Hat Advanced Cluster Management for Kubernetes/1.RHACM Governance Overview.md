# 3.1 RHACM Governance Overview

- **Governance** = rules/controls/policies that enforce standards; RHACM's is policy-based.
- Use cases: monitor & auto-remediate multi-cluster compliance, check for violations (security, cert expiry, DNS pattern mismatches), works across data centers/private/public cloud.
- **Components**: Governance dashboard (UI) · Policy-based governance framework (creates/deploys policies via placement) · Policy controllers (watch for violations, raise events, report to hub) · community policy examples (`stolostron/policy-collection` on GitHub).
- **Architecture**: on the **hub** — the **Policy propagator controller** replicates root policies into managed-cluster namespaces per Placement/PlacementBinding, and rolls compliance status back up; the **governance policy add-on controller** installs policy controllers on managed clusters. On the **managed cluster** — the **governance policy framework controller** pod contains: Spec Sync (keeps replicated policy in sync), Status Sync (reports compliance status up), Template Sync (updates objects per policy templates), Gatekeeper Sync (records Gatekeeper audit results as compliance events).
- **Policy object structure**: every `Policy` needs ≥1 `policy-templates` entry, a `Placement` (which clusters), and a `PlacementBinding` (binds policy↔placement). You **cannot** create a policy in a cluster's own namespace — RHACM deletes it.
- `spec.remediationAction`: `inform` (report only) or `enforce` (auto-fix).
- **Policy controllers**: Configuration Policy Controller (manages/monitors K8s resources, can enforce), Certificate Policy Controller (flags expiring certs via `minimumDuration`/`maximumDuration`, SAN pattern checks), Policy Set Controller (`PolicySet` groups policies in one namespace, needs its own `PlacementBinding`), Operator Policy Controller (installs/monitors OLM operators via `OperatorPolicy`, needs OLM present).
