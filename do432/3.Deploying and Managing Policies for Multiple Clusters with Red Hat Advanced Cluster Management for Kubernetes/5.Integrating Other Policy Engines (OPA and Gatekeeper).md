# 3.9 Integrating Other Policy Engines (OPA/Gatekeeper)

- **OPA (Open Policy Agent)**: general-purpose policy engine, uses the **Rego** language; works across microservices, K8s, CI/CD, API gateways.
- **OPA Gatekeeper**: OPA specialized for Kubernetes — runs as an **admission controller webhook**, blocking non-compliant API requests at creation/update time.
- RHACM integration is 2 steps: (1) a built-in RHACM policy installs the **Gatekeeper operator** + creates the `Gatekeeper` CR (`enforce` auto-installs); (2) create **ConstraintTemplate** (defines schema + Rego violation logic) + **Constraint** objects (supplies parameter values) inside a Policy's `policy-templates`.
- `Gatekeeper` CR's `spec.config` can exclude namespaces from all/some Gatekeeper processes (`audit`, `webhook`, `sync`, `mutation-webhook`, or `*`); results land in the `Config` object in `openshift-gatekeeper-system`.
- Constraint `enforcementAction`: `dryrun`/`warn`/`deny` — driven by the parent policy's `remediationAction` (`inform`→`warn`, `enforce`→`deny`).
- Can also watch for Gatekeeper-blocked requests via a `ConfigurationPolicy` checking for `Event` objects with `event_type: violation`.
