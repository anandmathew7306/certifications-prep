# 1.1 Multicluster & Hybrid Cloud Landscape

- Enterprises run multiple K8s clusters for scalability, resilience, and hybrid/multi-cloud strategy.
- **Cloud types**: public (shared, internet-accessible), private (internal, secure, self-provisioned), hybrid (mix of on-prem + private + public).
- **Why multiple clusters**: geographic distribution (latency/compliance), workload segmentation (dev/test/prod isolation), HA/DR, scalability (one hub can't manage everything).
- **Challenges**: portability across providers, consistent security/compliance, network complexity, data sync, scaling limits.
- **Multicluster Global Hub**: lets you manage several *hub* clusters (each with its own managed clusters) from one place — used when a single hub can't scale to a large fleet.
  - Key components: **Global Hub Operator** (deploys everything), **Global Hub Manager** (moves data between Kafka/PostgreSQL), **Global Hub Agent** (runs on each managed hub, syncs data back), **Grafana** (dashboards for compliance/health).
  - Uses Kafka (data transport) + PostgreSQL (storage) + HTTPS (secure comms).
  - Evolved from the deprecated **KubeFed** project.
