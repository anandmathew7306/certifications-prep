# 6.1 Introducing OpenShift Virtualization

- **Virtualization basics**: a hypervisor partitions one physical machine into isolated VMs, each with its own OS ("guest"), network, storage. The physical machine + hypervisor = the "host."
- **OpenShift Virtualization** = add-on operator that runs VMs as native Kubernetes objects alongside containers, managed with the same tools (web console, `oc`). Built on **KubeVirt** (CNCF project), which uses the **KVM** Linux-kernel hypervisor + **libvirt** (VM definition) running inside containers, plus a **QEMU guest agent** inside each VM reporting info back to the host.
- **Key features**:
  - **Unified resource control** — same K8s primitives (CPU/memory/storage/network policy) apply to VMs and containers.
  - **Flexible VM creation** — from templates/instance types (predefined or custom), prebuilt boot sources (e.g. RHEL 9, Fedora, auto-updated), or by cloning existing VMs/volumes.
  - **Access** — VNC/serial console, web console, `virtctl`, SSH (Linux), RDP (Windows).
  - **Advanced resource management** — hot-add/remove CPU/memory/disks; node placement rules; the `LongLifecycle` descheduler profile (4.18) balances load and live-migrates VMs.
  - **HA & live migration** — HA via standard K8s readiness/liveness probes (not supported on single-node OpenShift); live migration needs `ReadWriteMany` PVCs (RWO unsupported).
  - **Storage** — standard PV/PVC + CSI drivers (e.g. ODF, IBM Fusion); **Hostpath Provisioner (HPP)** for local/no-network-storage setups; storage-class migration without downtime (Tech Preview in 4.18).
  - **Backup/restore** — VM snapshots (web console/CLI) or the **OADP** operator (also supports third-party tools like Veeam Kasten, Portworx).
  - **Monitoring** — integrates with the Prometheus-based OpenShift monitoring stack.
  - **DR** — supports Metro-DR and Regional-DR.
  - **Migration from other hypervisors** — the **MTV (Migration Toolkit for Virtualization)** operator imports VMs from vSphere, RHV, etc.
