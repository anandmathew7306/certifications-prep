# 2.5 Access Control for Multicluster Management

- Built on standard OpenShift AuthN (who you are) + AuthZ/RBAC (what you can do); a **role binding** links a user/group to a role.
- **Managed Cluster Sets** (`ManagedClusterSet` resource) group clusters for bulk access/actions. `ManagedClusterSetBinding` ties a set to a namespace — granting namespace RBAC effectively grants set access.
  - `default` set: auto-created, catches any cluster not placed elsewhere; can't be deleted/updated.
  - `global` set: auto-created, contains *every* managed cluster, mandatory, can't be deleted/updated.
  - Rule: every cluster is in `global` **plus** either `default` or exactly one user-defined set — never both, never more than one custom set.
  - Clusters get labelled `cluster.open-cluster-management.io/clusterset=<name>`.
- **Key roles**: `cluster-admin` (OCP superuser) · `open-cluster-management:cluster-manager-admin` (RHACM superuser, can create `ManagedCluster`) · `...:admin:<cluster>` / `...:view:<cluster>` (per-cluster, auto-created on import) · `...:managedclusterset:admin/view/bind:<set>` (per-set access) · `...:subscription-admin` (Git-based app subscriptions).
- **Placement**: namespace-scoped resource that dynamically picks managed clusters from one or more bound cluster sets, for app workload targeting. Needs cluster-admin + cluster-set-admin to create.
  - **Predicates**: filter via `labelSelector` / `claimSelector`; `numberOfClusters` caps the selection.
  - **Taints/Tolerations**: a taint on a `ManagedCluster` (e.g. `NoSelect`) excludes it from Placements unless the Placement declares a matching toleration (optionally time-limited via `tolerationSeconds`, useful for auto-failover).
  - **Prioritizers**: score/rank candidate clusters (`Additive` or `Exact` mode; weight range -10 to 10; e.g. by allocatable CPU/memory).
  - **PlacementDecision**: auto-generated result listing the actually-selected clusters; removing a cluster from it removes the workload from that cluster.
- **Identity**: OpenShift's internal OAuth server isn't federated across clusters by default — configure an external identity provider (e.g. LDAP) for centralized user management.
