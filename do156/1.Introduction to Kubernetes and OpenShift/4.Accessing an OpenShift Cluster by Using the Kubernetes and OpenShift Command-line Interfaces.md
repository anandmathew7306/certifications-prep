# 1.7 Accessing an OpenShift Cluster by Using the Kubernetes and OpenShift Command-line Interfaces

- `kubectl` is the native Kubernetes CLI. `oc` is a superset that adds OpenShift features (projects, routes, image streams, `oc login`, `oc new-project`).
- Installing the OpenShift client also gives you a matching `kubectl`. Download from Help -> Command Line Tools or the mirror; verify downloads with `sha256sum -c`.
- Check versions with `kubectl version --client`.
- User types: regular users (User objects), system users, and service accounts (for apps).
- Login methods:
  - Username/password: `oc login -u <user> <api-url>` (prompts for password; avoid `-p` in production).
  - Token: `oc login --token=<token> --server=<api-url>`; best for production and CI/CD. Copy it from the console user menu. Tokens expire after 1 day.
  - Browser: `oc login --web <api-url>`.
- `oc whoami` shows the user; `--show-console` and `--show-server` show the console and API URLs.
- Key commands:
  - `oc new-project myapp`
  - Admin: `oc cluster-info` (add `dump` for debugging), `oc api-versions`, `oc get clusteroperator`
  - `oc get <type> [name]`, add `-o yaml` or `-o json` for full definitions; `oc get all` for a project summary
  - `oc describe`, `oc explain pods.spec.containers.resources` (`--recursive` for all fields)
  - `oc create -f file.yaml`, `oc status --suggest`, `oc delete <type> <name>`
- Gotchas: deleting a managed pod just gets it recreated; deleting a project deletes everything in it. Use `-n <namespace>` to target another project.
- Parse YAML output with `yq`; two different tools share that name and are not compatible.
