# 1.1 Containers and Kubernetes

- OpenShift (RHOCP) is a full platform built on top of containers and Kubernetes. Kubernetes gives building blocks; OpenShift completes them.
- Container = an isolated process created from an image that bundles the app and all its dependencies; runs on any host with a runtime.
  - Isolation comes from Linux kernel features: namespaces (separate processes/resources) and cgroups (limit CPU and memory).
  - OCI standards cover images and runtimes, so OCI-compliant images run on any compliant engine.
- Kubernetes runs containers across many nodes and restarts apps on another node if one fails.
- Declarative model: you describe the desired state in resources (YAML/JSON); controllers keep working until the cluster matches it.
- Pod = smallest unit; one or more containers sharing one node.
- Key features:
  - Service discovery and load balancing (built-in DNS, services spread traffic over pods)
  - Horizontal scaling (add/remove pods based on load)
  - Self-healing (health checks, restart or reschedule failed apps)
  - Automated rollout and rollback of new versions
  - Secrets and config kept outside the image. Gotcha: secrets are not encrypted by default.
  - Operators: packaged apps that manage complex workloads via custom resources.
- Node roles: control plane nodes schedule work and hold cluster state; compute (worker) nodes run user workloads. Up to about 5,000 nodes.
- One uniform API for all resource kinds, including custom ones; `kubectl` works with all of them.
- Namespaces group resources and are the basis for access control.
