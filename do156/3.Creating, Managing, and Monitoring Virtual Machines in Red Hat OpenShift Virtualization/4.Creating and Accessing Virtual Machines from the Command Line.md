# 3.7 Creating and Accessing Virtual Machines from the Command Line

- VMs are `kind: VirtualMachine`, `apiVersion: kubevirt.io/v1`. Create with `oc apply -f vm.yaml`. YAML files also act as config backups.
- `dataVolumeTemplates` with a `sourceRef` to a `DataSource` provides the root disk.
- cloud-init: add a `cloudInitNoCloud` volume under `spec.template.spec.volumes`; its `userData` can set a user, password, `ssh_authorized_keys`, and `runcmd` (runs as root, in order).
- `accessCredentials` keeps SSH keys separate from user data, using a secret:
  - `oc create secret generic my-keys --from-file=key=id.pub`
  - `propagationMethod: noCloud` = set at first boot.
  - `propagationMethod: qemuGuestAgent` = dynamic injection (RHEL 9+); also needs the `virt_qemu_ga_manage_ssh` SELinux boolean on. Updating the secret then updates the keys.
- Generate manifests with `virtctl create vm`:
  - `--name`, `--namespace`, `--memory=2Gi`
  - `--volume-import type:ds,src:ns/name` for the boot disk
  - `--user`, `--password-file`, `--ssh-key "$(cat key.pub)"`
  - `--access-cred=src:my-keys,method:nocloud` (or `method:ga` for dynamic)
- Edit: `oc edit vm vm1`, then `virtctl restart vm1` to pick up changes.
- Lifecycle: `virtctl start|stop|restart vm1`, `oc get vms`, `oc delete vm vm1` (also removes the VMI).
- Access:
  - `virtctl console vm1` (serial; exit with `Ctrl+]`), `virtctl vnc vm1`
  - `virtctl ssh -i key --username user vm1`
  - `virtctl port-forward vm/vm1 8080:80` or `oc port-forward pod/virt-launcher-... 8080:80`
- Port forwarding goes through the API server; avoid it for heavy traffic (big file copies, RDP).
- GUI clients: `remote-viewer` (SPICE/VNC), TigerVNC, TightVNC.
