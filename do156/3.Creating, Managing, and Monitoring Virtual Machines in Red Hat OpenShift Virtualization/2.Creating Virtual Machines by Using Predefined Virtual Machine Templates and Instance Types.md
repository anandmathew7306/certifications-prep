# 3.3 Creating Virtual Machines by Using Predefined Virtual Machine Templates and Instance Types

- Templates: Red Hat ships a catalog (RHEL, CentOS, Fedora, Windows) with OS image, workload and size preset. Create via Virtualization -> Catalog -> Template catalog, then Quick create or Customize.
- Template fields to know:
  - Disk source: template default, PVC clone, registry, URL, upload, blank.
  - Sizes: tiny (1 CPU/1 GiB), small (1/2, default), medium (1/4), large (2/8).
  - Workload: desktop, server (default), high performance.
  - Disk interface VirtIO/SATA/SCSI; access mode RWO/RWX/ROX. Live migration needs RWX.
  - NIC model `virtio` (fast, Windows needs drivers) or `e1000e`. Pod network uses `masquerade`; extra networks use `bridge`.
- Instance types: define CPU and memory (required), cannot be overridden. Series: `cx1` (dedicated compute), `gn1` (NVIDIA GPU), `m1` (memory), `n1` (DPDK network), `o1` (overcommitted), `u1` (general purpose).
  - `oc get vmclusterinstancetypes`
- Preferences (`vmcp` cluster-wide, `vmp` namespaced): optional, overridable defaults such as disk bus. `oc get vmcp`
- Bootable volumes are defined by `DataSource` objects whose labels suggest a default instance type and preference. `oc get datasources -A`
- CLI: `virtctl create vm --name vm1 --instancetype u1.medium --infer-preference --volume-datasource rhel9 > vm1.yaml`
- cloud-init (`userData`) runs on first boot: modules like `users`, `rh_subscription`, `yum_repos`, `write_files`, `runcmd`. Windows uses Sysprep.
- SSH keys are stored in a secret and can be auto-applied to all VMs in the project. Dynamic key injection is RHEL 9+ only and must be enabled at creation.
- Connect with `virtctl ssh -i key user@vm1`.
