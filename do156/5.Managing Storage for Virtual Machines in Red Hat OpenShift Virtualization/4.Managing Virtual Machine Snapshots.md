# 5.7 Managing Virtual Machine Snapshots

- A snapshot captures all VM disks plus the VM config (CPU, memory) at a point in time.
- Live snapshots work on running VMs. The QEMU guest agent freezes file systems so data is consistent. Without the agent, stop the VM first.
- Snapshots depend on the storage back end and its CSI driver (e.g. ODF supports them, NFS does not).
  - Unsupported disks trigger a warning and are not restored.
- Create: VM -> Snapshots -> Take snapshot, or apply a `VirtualMachineSnapshot` (`snapshot.kubevirt.io`) with `spec.source` pointing at the VM.
- List: `oc get virtualmachinesnapshot`.
- Restore: the VM must be stopped. Use the snapshot menu -> Restore, or apply a `VirtualMachineRestore` with `spec.target` (the VM) and `virtualMachineSnapshotName`.
- Restore and disk changes:
  - Disk removed since the snapshot: it is re-created (blank if its storage cannot snapshot, so that data is lost).
  - Disk added since the snapshot: it is removed.
- Create VirtualMachine from a snapshot to make a copy of the VM.
- Delete unused snapshots to free space; no need to stop the VM. `oc delete virtualmachinesnapshot <name>`.
- Each VM snapshot makes one Kubernetes `VolumeSnapshot` per disk. See them with `oc get volumesnapshots` (shows the source PVC).
- A single volume snapshot can be added to a VM as a new disk: Add disk -> Volume snapshot. Stop the VM for virtio; otherwise it is hot plugged as SCSI.
