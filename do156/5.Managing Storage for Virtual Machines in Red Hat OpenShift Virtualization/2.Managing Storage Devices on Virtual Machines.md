# 5.3 Managing Storage Devices on Virtual Machines

- Each attached DataVolume is a disk inside the guest.
- Disk interfaces:
  - SATA: works almost everywhere, slowest, good for CD-ROMs.
  - VirtIO: fastest, needs a driver and a PCIe slot, so limited count. Linux names it `/dev/vdX`.
  - SCSI: uses the virtio-scsi controller, hot pluggable, no slot limit. Linux names it `/dev/sdX`.
- Hot plug on a running VM = SCSI only. For virtio, stop the VM first.
- Disk sources in Add disk:
  - Empty disk (blank): raw unformatted device.
  - Ephemeral disk (container image): no PVC, writes lost on restart.
  - Volume / Clone volume: copies an existing PVC (source must not be in use).
  - Volume snapshot: new disk built from a snapshot.
- Never attach a PVC that another VM is using. ext4/XFS cannot handle shared mounts and will corrupt.
- Detach: Configuration -> Storage -> menu -> Detach. Hot unplug works for SCSI; virtio needs a stop/restart.
- Detached data stays. Delete it by deleting the PVC or `oc delete datavolume/<name>`.
- Reattach: Add disk -> Volume.
- Thin by default: space is allocated as written. Set `preallocation: true` in the DV (or tick the box) to reserve all space (faster writes).
- Resize: expand only, never shrink. Class must have `allowVolumeExpansion: true`.
  - Expand from the VM disk Edit dialog, Storage -> PVC -> Expand PVC, or edit `spec.resources.requests.storage`.
  - Guest sees the new size after restart; grow partitions/file systems yourself.
