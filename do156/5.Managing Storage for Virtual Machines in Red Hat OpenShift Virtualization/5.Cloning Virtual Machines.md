# 5.9 Cloning Virtual Machines

- A clone is a copy of a VM, usually of a prepared "golden" VM.
- Clones keep machine-specific data (Windows SID, SSH host keys, certs, subscriptions). Running both can clash.
- Seal the source VM first to strip unique data (MAC, static IPs, logs, IDs).
- Sealing:
  - Windows: `sysprep.exe` (OOBE), finished on shutdown.
  - Linux: `virt-sysprep` on the stopped VM's disk, not from inside the VM.
  - `virtctl guestfs -n <ns> <pvc>` starts a libguestfs-tools pod with the PVC at `/dev/vda` (one PVC only, VM must be off).
  - `virt-sysprep --list-operations`, `virt-sysprep -a /dev/vda`, `--enable op1,op2` to pick operations.
  - Never boot a sealed VM; it rebuilds the removed data and must be resealed.
- Clone in console: stop VM (recommended), Actions -> Clone, give a name.
- Clone in CLI: `virtctl create clone --source-name golden-vm --target-name new-vm` makes a `VirtualMachineClone` manifest to apply.
- Disk cloning is done by DataVolumes (CDI). StorageProfile `cloneStrategy`:
  - `csi-clone`: back-end clone.
  - `snapshot`: back-end snapshot (smart cloning), the default when possible.
  - `copy`: pods copy the data (host-assisted), slowest.
- CSI and smart cloning need the same storage class and volume mode, and an unused source.
- Cross-namespace cloning needs a ClusterRole and binding for DataVolume actions.
- Clone one disk: DataVolume with `source.pvc` (name, namespace); size at least the source. Stays `CloneInProgress` while the source VM runs.
- DVs from a VM are deleted with the VM; standalone DVs are kept and reusable.
