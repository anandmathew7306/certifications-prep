# 5.5 Exporting and Importing Virtual Machines

- `VirtualMachineExport` exports a VM or snapshot and its disks.
- `ttlDuration` sets how long the export lives; default 2 hours, then it is deleted.
- `oc describe vmexport/<name>` shows download links:
  - External and internal (cluster only) links.
  - Disks come as `raw` or `gzip`.
  - Links are protected by a token in the `export-token-<name>` secret.
- CLI:
  - `virtctl vmexport create <name> --vm=<vm>` creates the export.
  - `virtctl vmexport download <name> --manifest --include-secret --output vm.yml` gets the manifest bundle.
  - `--volume <disk> --output disk.img.gz` downloads a disk instead.
  - `--keep-vme` stops virtctl from deleting the export after download.
  - `virtctl vmexport delete <name>` or `oc delete vmexport` cleans up.
- Manifest bundle = ConfigMap with CA cert, Secret with token, and the VM with a DataVolume that pulls the disk from the source cluster.
- Stop the VM first; a running VM leaves the export Pending. For a running VM, snapshot it and use `--snapshot=<snap>`.
- Import from another OpenShift Virtualization cluster: `oc apply -f vm.yml`. The same namespace must already exist on the target.
- Import a disk image (ISO, raw, qcow2) from KVM, OpenStack, RHV, etc.:
  - `virtctl image-upload dv <name> --size 30Gi --image-path <file> --storage-class <class>`
  - Then make a VM from it, e.g. `virtctl create vm --name <vm> --volume-pvc src:<pvc> | oc apply -f -`.
- virtctl only imports full VM definitions from OpenShift Virtualization. Other hypervisors need the Migration Toolkit for Virtualization.
