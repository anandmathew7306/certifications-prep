# 4.11 Configuring Multihomed Virtual Machines

- A multihomed VM is on the pod network plus one or more secondary networks. Admins prepare them; VM users attach.
- **Kubernetes NMState operator** configures node networking declaratively:
  - `NodeNetworkConfigurationPolicy` (NNCP): desired state for a set of nodes (Linux bridge, OVS bridge, bond, Ethernet). `nodeSelector` picks nodes; without it, all nodes.
  - `NodeNetworkConfigurationEnactment` (NNCE): per-node result. A failed change rolls back automatically.
  - OVS bridges can map to an OVN `localnet` name via `bridge-mappings`.
- **NAD**: namespaced CR that Multus reads to plug the extra interface into the VM. A VM can use NADs in its own namespace; NADs in `default` are usable cluster-wide.
  - OVN NAD uses `type: ovn-k8s-cni-overlay` and a `topology` of `layer2` (cluster-internal overlay) or `localnet` (reaches the physical network).
- Attach in console: VM -> Configuration -> Network Interfaces -> Add Network Interface, pick the NAD.
- Or `oc edit vm`: add an entry in `spec.template.spec.domain.devices.interfaces` (for example `bridge: {}`) and a matching name in `spec.template.spec.networks` with `multus.networkName: <nad>`.
- Restart (or start) the VM to apply.
- **Hot plug**: bridge plus VirtIO interfaces can be added or removed live; SR-IOV can be added only. Apply with a live migration: `virtctl migrate <vm>`.
- For static or DHCP IPs use a bridge-based secondary interface (DHCP needs a server there).
- Static IP via cloud-init `networkData` (for example `enp2s0` with `192.0.2.150/24`).
- The QEMU guest agent must run in the VM for the console to show its IPs.
