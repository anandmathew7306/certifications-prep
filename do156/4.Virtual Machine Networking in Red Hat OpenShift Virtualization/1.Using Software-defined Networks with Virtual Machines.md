# 4.1 Using Software-defined Networks with Virtual Machines

- The SDN has a pod network and a service network. Pods talk across nodes and namespaces.
- The Cluster Network Operator (CNO) manages it, using OVN-Kubernetes (Open vSwitch) by default.
- VMs run inside `virt-launcher` pods, so they are on the pod network by default.
- Pod and VM IPs change on restart, so use a **Service** for a stable IP and DNS name.
- Service types: `ClusterIP` (internal, default), `NodePort`, `LoadBalancer`, `ExternalName`. Routes handle external HTTP.
- View pod/service CIDRs (admin only): `oc get network/cluster -o yaml`.
- DNS name: `<service>.<namespace>.svc.cluster.local`; short names also work.
- Labels for a service selector go in `.spec.template.metadata.labels` of the VM. Only these are copied to the `virt-launcher` pod.
  - Editing the VM does not update the running pod; restart the VM (live migration is not enough).
  - `oc label pod` works as a quick fix but is lost on restart unless the VM spec has it too.
- Quick way: `virtctl expose vmi vm1 --name backend --type ClusterIP --port 80 --target-port 8080` (selects on `vm.kubevirt.io/name`).
- Check with `oc get svc` and `oc get endpoints`; endpoints follow VM IP changes.
- **Headless service** (`clusterIP: None`): no service IP or load balancing; DNS returns the pod/VM IPs directly.
  - Web console creates a `headless` service on the first VM in a project and labels VMs with `network.kubevirt.io/headlessService: headless`.
  - Set `spec.template.spec.subdomain` to the headless service name to reach a VM as `<vm>.<service>.<namespace>.svc.cluster.local`.
