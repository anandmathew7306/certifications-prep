# 4.9 Configuring External Access with Load Balancer Services

- Routes and ingress only handle HTTP-style traffic. For SSH, SMTP, LDAP, databases and similar, use a NodePort or LoadBalancer service.
- **NodePort**: opens the same port (30000-32768 by default) on every node and forwards to the VM.
  - Not recommended: exposes node IPs, odd port numbers.
- **LoadBalancer**: gives a fixed external IP that stays the same when the VM moves to another node.
  - Cloud: the provider creates one load balancer per service (cost).
  - Bare metal: the **MetalLB** operator assigns IPs from an admin pool.
- MetalLB modes: layer 2 (default, gratuitous ARP from one node) and layer 3 (BGP to routers, needs an AS number).
- MetalLB CRs live in `metallb-system`: `MetalLB` (main instance), `IPAddressPool` (IP range), `L2Advertisement` (which pools to announce).
- Expose a VM: `virtctl expose vm vm1 --name vm1-ssh --type LoadBalancer --port 22 --target-port 22`.
  - Selector is `vm.kubevirt.io/name: vm1`. Check with `oc get svc` (EXTERNAL-IP), `oc get endpoints`, then `nc -vz 192.0.2.10 22`.
- `virtctl expose` takes only one `--port`. Add more ports with `oc edit service`; every port needs a `name` when there are several (`--port-name` sets one at creation).
- Console option: enable "SSH over LoadBalancer" in Virtualization -> Overview -> Settings, then set it per VM in Configuration -> SSH.
  - Gotcha: on a running VM the endpoint stays empty until the VM is live migrated, so the new pod gets the matching label.
