# 4.7 Configuring External Access to Virtual Machines

- Ways to reach workloads from outside: `NodePort` service, `LoadBalancer` service (cloud or MetalLB), and the Ingress Controller (routes and ingress).
- The Ingress Controller only handles HTTP, HTTPS, and TLS with SNI. Use NodePort or LoadBalancer for other TCP or UDP traffic.
- **Routes** are OpenShift-specific and run on HAProxy router pods. They map a public hostname to a service.
  - Default hostname: `<route>-<namespace>.<wildcard domain>`. The wildcard DNS record points at the router nodes.
- Steps for a VM: add a label in `.spec.template.metadata.labels`, restart the VM, create a `ClusterIP` service, then the route.
  - Shortcut: `virtctl expose vm web-vm --name web --port 80 --target-port 8080` uses the `vm.kubevirt.io/name` label, so no label or restart is needed.
- Create a route: `oc expose service/web` (options `--name`, `--hostname`, `--path`). View with `oc get route`.
- Path-based routes let one hostname send `/static` and `/api` to different services.
- TLS termination types:
  - Edge: TLS ends at the router; router to backend is plain.
  - Passthrough: router forwards encrypted traffic; the app serves the cert.
  - Re-encrypt: router ends TLS, then opens a new TLS link to the backend.
- `oc expose` only makes plain HTTP routes. Use `oc create route edge|passthrough|reencrypt --service web`, with `--key`/`--cert` for custom certs.
- Insecure traffic policy: `None`, `Allow`, or `Redirect` (HTTP to HTTPS).
- Kubernetes `Ingress` resources work too (`host`, `path`, `pathType: Prefix|Exact`, backend service). OpenShift turns them into routes, but they lack features like re-encrypt.
