# 2.1 OpenShift Virtualization

- Virtualization splits one physical machine into many isolated VMs, each with its own OS, network, and disks.
  - Hypervisor = runs VMs and controls their access to hardware.
  - Host = the physical machine running the hypervisor; guest = the OS inside a VM.
- Cloud builds on virtualization, adding self-service and auto-scaling.
- Containers vs VMs:
  - Containers are processes isolated with kernel namespaces and cgroups; small (MBs) and fast to start.
  - VMs are larger (GBs) but needed for legacy apps not worth containerising, non-Linux guests, a different kernel, or dedicated hardware.
- OpenShift Virtualization is an operator built on the upstream KubeVirt project (a CNCF project).
  - Runs KVM (hypervisor) and libvirt inside containers, so VMs and containers share one cluster and one UI.
  - Adds live migration, HA, snapshots, thin provisioning, and monitoring.
- Key components:
  - HyperConverged Operator (HCO): deploys and manages all other virtualization parts.
  - Containerized Data Importer (CDI): imports and manages VM disk volumes.
  - Hostpath Provisioner (HPP): local node storage for VMs.
  - Cluster Network Addons Operator (CNAO): Multus and Linux bridge for extra VM networks.
  - Scheduling, Scale, and Performance (SSP): VM templates, metrics, node feature discovery.
  - QEMU guest agent: runs inside the VM and reports guest details to the host.
- Rough mapping to other hypervisors:
  - Datastore -> PV/PVC; DRS -> descheduler; NSX -> OVN-Kubernetes + Multus.
  - vMotion -> live migration; host networking -> NMState operator; VMware tools -> QEMU agent.
