# 6.5 Deploying & Managing Multicluster VMs

- **VM vs VMI**: a `VirtualMachine` (VM) object is a template/desired-state (like a Deployment); a `VirtualMachineInstance` (VMI) is the actual running instance (like a ReplicaSet's pod) — if a VMI dies, a VM object regenerates it.
- **Runtime chain**: `virt-controller` (watches for new VMIs) → `virt-handler` daemonset (per node, reconciles VM state, creates the launcher) → `virt-launcher` pod (runs a local `libvirtd`, actually executes the VM process; also handles DHCP/IPv4 routing so you can port-forward to the VMI).
- **Deploying VMs at scale**: same Argo CD `Application`/`ApplicationSet` pattern as any GitOps deployment — one `VirtualMachine` manifest, applied identically across every targeted managed cluster via an `ApplicationSet` + `Placement`. Manifest highlights: `dataVolumeTemplates` (defines the boot disk via a `DataSource` reference + storage size/class), `instancetype`/`preference` (sizing/OS profile), `runStrategy` (`Always` = VMI auto-recreated if it stops; `Manual` = you explicitly start/stop/pause).
- **Console flow**: Applications → Create application → ApplicationSet Push model → General (name/Argo server) → Template (Git repo/branch/path, remote namespace) → Sync policy → Placement (cluster set + optional label filters/cluster count) → Review → Topology view to inspect resulting resources (VM, pods, PVCs, DataVolumes — note: DataVolume/PVC icons showing "unknown" status in Topology is a known cosmetic bug).
- **Removing VMs**: delete the ApplicationSet (Applications → select → Actions → Delete application → "Remove ApplicationSet related resources") — cascades to the VMs and their dependent resources.
- **Infrastructure → Virtual machines** page: fleet-wide VM list (status, cluster, namespace, node, IP, launch links) with per-VM Details/Conditions/YAML/Related-resources tabs; can edit/delete a VM's YAML directly.
- **Enabling VM actions (start/stop/restart/pause) from the console** — a Tech Preview feature, off by default: confirm the `managedserviceaccount` add-on is enabled on the `MultiClusterEngine` resource, then run `oc annotate search search-v2-operator -n open-cluster-management virtual-machine-preview='true'`. Requires the VM's `runStrategy` to be `Manual`. Disable by re-annotating with `'false' --overwrite`.
