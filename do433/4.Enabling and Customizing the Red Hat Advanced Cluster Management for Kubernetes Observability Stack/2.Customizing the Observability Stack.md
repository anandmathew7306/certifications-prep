# 4.3 Customizing the Observability Stack

- Most customization = editing the `MultiClusterObservability` CR (e.g. bump `advanced.receive.replicas` for scale) or adding ConfigMaps for metrics/alerts/dashboards.
- **Prometheus rules** (two types):
  - **Recording rules**: precompute expensive/frequent PromQL expressions into a new named time series (`record` + `expr` + optional `labels`) — speeds up dashboards.
  - **Alerting rules**: define a condition that fires a notification (`alert` + `expr` + optional `for`, `keep_firing_for`, `labels`, `annotations`).
- **Default metrics**: listed in the `observability-metrics-allowlist` ConfigMap (namespace `open-cluster-management-observability`) — **read-only**, cannot be edited.
- **Custom metrics**: add via the `observability-metrics-custom-allowlist` ConfigMap (same namespace) — supports platform metrics (`names:`) and custom `recording_rules:`. Creating/editing it restarts the `metrics-collector-deployment` pod. To scope custom metrics to one managed cluster only, apply the same ConfigMap in the `open-cluster-management-addon-observability` namespace *on that managed cluster*. **User workload metrics** (app-specific) use the same ConfigMap name but placed in the *monitored namespace* with a `uwl_metrics_list.yaml` key.
- **Default alerts**: in `thanos-ruler-default-rules` ConfigMap.
- **Custom alerts**: add via the `thanos-ruler-custom-rules` ConfigMap (same namespace) — restarts the `observability-thanos-rule` pods. Structure: `groups:` → `rules:` (each an `alert` + `expr` + `for` + `labels`/`annotations`). Verify custom alerts in Grafana's Explore page (Metric = ALERTS, filter by `alertname`).
- **Grafana dashboards**: 15+ ship by default (some pulled from the RHOCP monitoring stack, filterable per managed cluster); definitions live in ConfigMaps prefixed `grafana-dashboard-` in the observability namespace. Custom dashboards require setting up a **Grafana developer instance** (build via UI or via ConfigMap).
- **Forwarding alerts externally**: override the `alertmanager-config` secret (in the observability namespace) to add receivers/routes (e.g. Slack). To fully disable alert forwarding for managed clusters, annotate the `MultiClusterObservability` CR with `mco-disable-alerting: "true"`.
