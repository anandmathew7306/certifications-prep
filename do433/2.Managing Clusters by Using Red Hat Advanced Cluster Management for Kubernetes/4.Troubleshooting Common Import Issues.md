# 2.7 Troubleshooting Common Import Issues

- General approach: check Red Hat troubleshooting docs → run `oc adm must-gather` (with the RHACM plug-in image) → open a support case if unresolved.
- **Cluster won't report to RHACM after creation**: usually network (need TCP 6443 & 443 both ways + DNS resolution), untrusted TLS cert (custom CA not in trust bundle), clock skew (chrony), or missing pull secret for image access.
- **Import fails**: check the `managedcluster-import-controller-v2` pods (namespace `multicluster-engine`); check the `<cluster>-import` secret exists in the cluster's namespace; check the klusterlet's `RegistrationDesiredDegraded`/`WorkDesiredDegraded` conditions (must be `False`).
- **Stuck "pending import"**: usually stale leftovers from a previous, improperly-detached hub relationship — clean up klusterlet, `open-cluster-management-agent(-addon)` namespaces, and RHACM CRDs (Red Hat provides a KB cleanup script).
- **Cluster shows Error/Unknown status**: check `.status.conditions` on the `managedcluster` resource; `ManagedClusterConditionAvailable = Unknown` means the agent stopped updating its lease — check the klusterlet status next.
- **Status flapping Unknown ↔ Ready**: unstable network; default offline grace period is 5 minutes, tunable via `.spec.leaseDurationSeconds` on the `ManagedCluster` (real grace period = leaseDurationSeconds × 5 retries).
