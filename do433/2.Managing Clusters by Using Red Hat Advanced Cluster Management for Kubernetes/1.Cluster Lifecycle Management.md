# 2.1 Cluster Lifecycle Management

- **Cluster lifecycle** = create, import, manage, delete (+ hibernate/resume/detach) clusters, all handled by the auto-installed **multicluster engine (MCE)** operator.
- MCE uses the **Hive** operator to provision cloud clusters (AWS, AWS GovCloud, Azure, GCP, vSphere, OpenStack); on-premise clusters use central infrastructure management + assisted installer instead. Supports any CNCF-conformant provider.
- **Infrastructure menu** (console): Clusters (create/import), Automation (Ansible pre/post-hooks — needs AAP operator), Host Inventory (physical/virtual machines to install on), Virtual Machines (manage VMs fleet-wide).
- **Creating a cluster**: `ClusterDeployment` CR (the Hive object controlling the cluster's lifecycle) references a `ClusterImageSet` CR (a reusable, immutable pointer to a specific OCP installer image). This decouples version management from individual cluster manifests — update the image set once instead of every ClusterDeployment.
- **Importing an existing cluster**: creating the `MultiClusterHub` CR auto-imports the *local* cluster. For others: Infrastructure → Clusters → Import cluster → name it → optional cluster set/labels → pick an import mode → generate & run the import command on the target.
  - **Import modes**: Run import command manually / Enter server URL+API token / Kubeconfig / Import from Red Hat OpenShift Cluster Manager (for ROSA).
- **Scaling**: the **SiteConfig operator** uses a `ClusterInstance` CR + templates to generate install manifests, dry-run them, then apply — set `spec.nodes` to scale.
- **Removing a cluster**: Actions → Detach cluster (removes RHACM add-ons/agents). Manual leftover cleanup = klusterlet cluster role, `klusterlet-admin-aggregate-clusterrole`, and the klusterlet cluster role binding.
