# 3.7 Compliance Operator via RHACM

- Compliance = ongoing alignment with org/security/regulatory standards; non-compliance risks legal, trust, and certification consequences.
- **RHOCP Compliance Operator** uses **OpenSCAP** (a SCAP-standard scanner) to scan nodes/objects against **compliance content** (from the `ComplianceAsCode/content` project, shipped as a container image, decoupled from the operator for fast updates).
- RHACM deploys the Compliance Operator itself via a policy → auto-creates a Namespace (`openshift-compliance`), an `OperatorGroup`, and a `Subscription`.
- **Key CRDs**: `ProfileBundle` (points to the content image; can hold multiple Profiles) → `Profile` (read-only rule set for a standard, e.g. E8) → optionally `TailoredProfile` (customize a Profile) → `ScanSetting` (scan schedule/nodes/storage/retention; default one auto-created) → `ScanSettingBinding` (binds ScanSetting to chosen Profiles) → generates `ComplianceSuite` (bundle of scans) → `ComplianceScan` (a single scan run) → results as `ComplianceCheckResult` objects.
- Example: the **E8 (Essential Eight) scan policy** deploys a `ScanSettingBinding` for `ocp4-e8`/`rhcos4-e8` profiles, verifies the `ComplianceSuite` reaches `DONE`, and checks no `ComplianceCheckResult` has `check-status: FAIL`.
