# 5.5 Deploying & Managing Multicluster Apps

- Argo CD app sources: plain YAML/JSON directory, **Kustomize**, or **Helm charts**.
- **Kustomize** pattern: `base/` (shared config) + `overlays/<env>/` (env-specific diffs), each with its own `kustomization.yaml`. Overlays typically reference the base (`resources: [../../base]`) and add/patch resources (e.g. bump `replicas`). Deploy standalone via `kustomize build <dir> | oc apply -f -` or `oc apply -k <dir>` — Argo CD auto-detects and uses Kustomize structure itself.
- **`ApplicationSet`** = the template RHACM/Argo CD uses to stamp out one `Application` per targeted cluster:
  - `generators.clusterDecisionResource` ties it to a `Placement` (via a label match on `cluster.open-cluster-management.io/placement`).
  - `template` defines the per-cluster `Application`, using `{{name}}` / `{{server}}` placeholders substituted per matched cluster.
  - `sources` = the Git repo/path/branch to deploy from.
  - `syncPolicy.automated` with `prune`/`selfHeal` keeps clusters in sync automatically; `syncOptions` can auto-create namespaces etc.
  - Generated `Application` objects live in `openshift-gitops`; query with `oc get applications.argoproj.io -n openshift-gitops` (must specify the `argoproj.io` API group — other controllers also define an `Application` kind).
- **Placement** for apps: selects from a `clusterSets` list, can cap with `numberOfClusters` (random subset if more match), filters via `predicates.requiredClusterSelector.labelSelector` (OR logic across predicates). The referenced cluster set must be bound to the `openshift-gitops` namespace via a `ManagedClusterSetBinding`.
- **Console flow**: Applications → Create application → *ApplicationSet - Push/Pull model* → name → repo/branch/path → sync policy → placement (existing or new) → review/submit. Use the **Topology view** afterward to inspect status/YAML per resource, or the Argo CD console for an equivalent view.
- **Pull model specifics**: Placement must exclude the hub/local cluster; YAML-authored ApplicationSets need extra annotations/labels (`apps.open-cluster-management.io/ocm-managed-cluster`, `.../ocm-managed-cluster-app-namespace`, `argocd.argoproj.io/skip-reconcile: "true"`, and label `apps.open-cluster-management.io/pull-to-ocm-managed-cluster: "true"`). Flow: hub Argo CD creates the `Application` object but doesn't deploy it (skip-reconcile) → RHACM notices the pull-labeled Application → creates a `ManifestWork` in the target cluster's namespace → managed cluster pulls & creates its own `Application` → its local Argo CD deploys it → hub aggregates status via a `MulticlusterApplicationSetReport` for the Topology view.
- **Deleting**: delete the `ApplicationSet` (cascades to its generated `Application`s and their managed resources); RHACM does **not** auto-delete the associated `Placement` — clean that up separately if unused.
