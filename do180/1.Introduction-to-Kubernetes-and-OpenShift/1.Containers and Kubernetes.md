## Quick Summary

Covers what containers and Kubernetes are, how OpenShift builds on Kubernetes' extension points, core Kubernetes features (scaling, self-healing, rollout, secrets, operators), cluster node types, and the declarative, resource-based API/configuration model.

## Key Concepts

- **Container** — a process that runs an application independently from other containers on the host, created from a container image.
- **Container image** — includes all runtime dependencies of the application.
- **cgroups (control groups)** — used by containers for resource management (CPU time, memory).
- **Namespaces (Linux kernel feature)** — isolate a container's processes and resources from other containers and the host system.
- **OCI (Open Container Initiative)** — maintains standards about containers, container images, and container runtimes.
- **Pod** — one or multiple containers that run in the same cluster node.
- **Declarative configuration model** — administrators define workloads; Kubernetes ensures running workloads match the definition.
- **Control plane nodes** — provide global cluster coordination for scheduling workloads; manage cluster configuration state.
- **Compute plane nodes** — run the user workloads.
- **Hosted control plane** — runs the control plane as isolated pods on a separate hosting cluster; popular for sovereign clouds requiring strict multitenant boundaries.
- **Resources** — uniform API objects Kubernetes uses to define workloads; manageable via tools like kubectl, including custom resource types.
- **Declarative resource management** — importing/exporting resource definitions as text files instead of performing manual operation sequences.
- **Controllers** — continuously track cluster state and perform steps to keep the cluster in the intended state.
- **Kubernetes namespaces** — most resources must be created inside one; used for organization and resource-access permissions.



## Operators

- **Operator** — packaged Kubernetes application that manages Kubernetes workloads declaratively; e.g. can define a database resource and, when created, automatically deploy the database, configure replication, and back it up.



## Exam Tips / Gotchas

- Kubernetes does not intend to provide a complete solution — it provides extension points; OpenShift completes/builds on these.
- Note: Kubernetes does not encrypt secrets.
- In-place pod resize (resizing CPU/memory without restarting pods) starts with Kubernetes 1.35 and OpenShift Container Platform 4.22.
- Kubernetes clusters can range from small single-node clusters up to large clusters with up to 5,000 nodes.
- A server can act as both control plane and compute node, but roles are usually separated for stability, security, and manageability.



## Glossary

- **OCI**: Open Container Initiative — maintains container/image/runtime standards.
- **cgroups**: Linux kernel feature used for resource management (CPU, memory) in containers.
- **Pod**: one or multiple containers running in the same cluster node.
- **Control plane node**: node providing cluster coordination and configuration state management.
- **Compute plane node**: node that runs user workloads.
- **Hosted control plane**: control plane run as isolated pods on a separate hosting cluster.
- **Declarative resource management**: describing/managing resources via text file definitions rather than manual operation sequences.
- **In-place pod resize**: feature allowing CPU/memory resize of running pods without restart (K8s 1.35 / OCP 4.22+).
