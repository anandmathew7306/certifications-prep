## Quick Summary
Explains how OpenShift extends Kubernetes with developer workflow tools, observability, and server management features. Covers the difference between cloud (managed) and self-managed OpenShift editions, the products within each self-managed tier, and the support lifecycle for releases.

## Key Concepts
- **S2I (Source-to-Image)** — tool to build artifacts from source repositories into container images.
- **RHEL CoreOS** — immutable operating system optimized for running containerized applications; uses the same kernel/packages as RHEL.
- **Red Hat OpenShift Local** — deploys a cluster on a local computer for testing/exploration; not suitable for production.
- **Developer Sandbox** — 30 days of free access to a shared OpenShift cluster; not suitable for production.
- **Digital sovereignty** — control over data localization, technology independence, operational control over standards/policies, and integrity/security assurance of digital systems.
- **EUS (Extended Update Support)** — longer support window for even-numbered minor releases.
- **Red Hat Site Reliability Engineering (SRE)** — updates managed-service clusters and remedies update issues (customer still participates in scheduling updates).

## Operators
- **Insights Operator** — uploads cluster data to the Red Hat Hybrid Cloud Console, which Lightspeed advisor analyzes to identify and remediate cluster issues.

## Comparisons
| Aspect | Cloud Services Editions | Self-managed Editions |
|---|---|---|
| Responsibility | More responsibilities delegated to Red Hat and cloud provider | Greater control and flexibility, but greater responsibility over the service |
| Infrastructure | Managed service creates/manages all necessary cloud resources | Deployed via installers on physical/virtual infrastructure, on-premise or public cloud |
| Updates | Red Hat SRE teams update clusters and remedy issues (customer schedules updates) | [unclear in source] |

**Self-managed edition tiers (build on each other):**
| Edition | Key Additions |
|---|---|
| OpenShift Virtualization Engine | VM deployment/management/scaling only; virtualization admin console, GitOps, user workload monitoring, platform logging |
| OpenShift Kubernetes Engine | Latest Kubernetes + security hardening/enterprise stability; runs on RHEL CoreOS; uses OpenShift Virtualization for VMs; admin console |
| OpenShift Container Platform | Adds cluster manageability, security, stability, developer console, log management, cost management, metering; adds Serverless (Knative), Service Mesh (Istio), Pipelines (Tekton), GitOps (Argo CD) |
| OpenShift Platform Plus | Adds OpenShift Data Foundation, Advanced Cluster Management, Advanced Cluster Security, Red Hat Quay private registry |

## Exam Tips / Gotchas
- All OpenShift editions use the same code; most course content applies to all editions.
- Local and Developer Sandbox are for testing/exploration only — not suitable for production deployments.
- Even-numbered minor releases (e.g. 4.18, 4.20, 4.22) are designated EUS releases with a longer support window.
- Starting from OpenShift Container Platform 4.14: EUS phase = 24 months total lifecycle on all supported architectures; optional 12-month add-on extends support to 36 months for mission-critical production environments.

## Glossary
- **S2I**: Source-to-Image — builds container images directly from source repositories.
- **RHEL CoreOS**: immutable OS for containerized workloads, same kernel/packages as RHEL.
- **EUS**: Extended Update Support — longer support window for even-numbered releases.
- **Digital sovereignty**: organizational control over data, infrastructure, and security boundaries.
- **SRE**: Site Reliability Engineering (Red Hat team managing cloud-service clusters).
- **Lightspeed advisor**: Red Hat Hybrid Cloud Console service that helps identify/remediate cluster issues using Insights Operator data.
