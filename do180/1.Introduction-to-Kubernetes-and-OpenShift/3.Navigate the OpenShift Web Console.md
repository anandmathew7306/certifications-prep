# Navigate the OpenShift Web Console

## Quick Summary

Introduces the OpenShift web console as a GUI alternative to the CLI, how to access/discover its URL, its unified "Core platform perspective" layout (post-4.19), and basic terminology (pods, deployments, projects, routes, operators) needed to navigate it.

## Key Concepts

- **Web console** — GUI for cluster administration; uses Kubernetes APIs and OpenShift extension APIs; all its menus/tasks/features are also available via CLI.
- **Kubernetes dashboard** — not deployed by default, minimal security permissions, token-only auth, requires a proxy that limits access to the terminal creating it; separate/unrelated to the OpenShift web console.
- **Core platform perspective** — starting OCP 4.19, unifies cluster admin, app deployment, and monitoring into one consistent view (replacing separate Administrator/Developer perspectives).
- **Developer perspective** — optional, restorable by cluster admins via Administration → Cluster Settings → Configuration → Console operator resource → Customize → enable Developer perspective status.
- **Virtualization perspective** — available when the Red Hat OpenShift Virtualization operator is installed; for creating/managing VMs.
- **Sidebar** — primary navigation method; expands into categories for cluster info, configuration, functionality.
- **Home → Overview** — default landing page; quick glimpse of cluster config, docs, general status.
- **Home → Projects** — lists all projects available to the credentials in use.
- **Ecosystem → Software Catalog** — access point for operators, Helm charts, other cluster software; starting OCP 4.19 unifies former OperatorHub and Developer Catalog.
- **Ecosystem → Installed Operators** — view operators already installed on the cluster.
- **+ quick create menu** — upper-right menu for rapidly deploying applications (e.g., from container images or Git repo import).
- **Pods** — smallest unit of a Kubernetes-managed containerized application; one or more containers.
- **Deployments** — operational unit providing granular management of a running application.
- **Projects** — a Kubernetes namespace with additional annotations providing multitenancy scoping for applications.
- **Routes** — networking configuration to expose applications/services to resources outside the cluster.



## Operators

- **Console operator** — configures the web console address; its resource is edited to enable the Developer perspective.
- **Red Hat OpenShift Virtualization operator** — when installed, enables the Virtualization perspective for creating/managing VMs.
- **Operators (general)** — packaged Kubernetes applications that extend cluster functions; can also extend web console features/menus/views/forms.



## Commands


| Command                                        | What it does                                                                         | Key flags/options |
| ---------------------------------------------- | ------------------------------------------------------------------------------------ | ----------------- |
| `oc login -u <USERNAME> <API_ENDPOINT>:<PORT>` | Authenticates to the cluster from a terminal; output includes a Console URL shortcut | `-u` = username   |
| `oc whoami --show-console`                     | Retrieves the direct web console URL                                                 | —                 |




## Exam Tips / Gotchas

- Web console menus/tasks/features are always available via the CLI too.
- Kubernetes dashboard ≠ OpenShift web console — different tools, dashboard is not deployed by default and has limited security/access.
- Starting OCP 4.19: single Core platform perspective replaces separate Administrator/Developer perspectives by default; Developer perspective can be manually re-enabled by admins.
- Starting OCP 4.19: Software Catalog unifies previously separate OperatorHub and Developer Catalog.
- Non-cluster-admin users might need to request permissions for certain administrative features.



## Glossary

- **Pod**: smallest deployable unit in Kubernetes; one or more containers.
- **Deployment**: operational unit for granular management of a running application.
- **Project**: Kubernetes namespace with added annotations for multitenancy scoping.
- **Route**: networking config exposing apps/services outside the cluster.
- **Operator**: packaged Kubernetes application extending cluster functions.
