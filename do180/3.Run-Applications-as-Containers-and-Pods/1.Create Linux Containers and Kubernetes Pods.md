## Key Concepts
- **Container image** — contains immutable data defining an application and its libraries.
- **run command** — creates single pods for interactive debugging or temporary tasks; declarative YAML (e.g. Deployment) is recommended for enterprise applications instead.
- **Pod restart policy** — determines cluster response when containers exit; values: Always (default), OnFailure, Never.
- **UID/GID project annotations** — `openshift.io/sa.scc.uid-range` and `openshift.io/sa.scc.supplemental-groups`, format base/size, defining the block of UIDs/GIDs a project can assign to its containers.
- **Rootless containers** — Red Hat OpenShift assigns a random non-root UID (from the project's uid-range) to a regular user's pod, ignoring the image's USER instruction; primary GID is always 0 (root group), so container-written files/dirs must be group-owned by root with group write permission.
- **Privileged account risk** — cluster administrators' pods do process the image's USER instruction (e.g. UID 0 = root), which is a security risk since a privileged account has unrestricted host access.
- **Pod Security Admission (PSA) controller** — issues a warning when a pod is created without a defined security context; enforces security profiles (privileged, baseline, restricted) at the namespace level.
- **Security Context Constraints (SCC) controller** — OpenShift-specific controller providing safe defaults for pod security; grants pods permissions to meet the enforced PSA profile.
- **Container logs** — stdout/stderr of a container.
- **Graceful termination** — pods try to terminate processes before being forcibly terminated by Kubernetes.
- **CRI-O** — container engine used by RHOCP worker/control plane nodes; purpose-built for Kubernetes (unlike Podman/Docker); meets Kubernetes CRI standards, enabling integration with networking/storage plug-ins.
- **crictl** — CLI to manage containers via CRI-O.
- **Debug pod (node)** — created via `oc debug node/node-name`; named `pod/node-name-debug` in the selected project if privileged SCC is allowed, otherwise created in a temporary `openshift-debug-random-string` namespace.
- **chroot /host** — mounts host root filesystem into `/host` in the debug pod shell, enabling host binaries like crictl.
- **lsns** — lists system namespaces of a container process.
- **nsenter** — enters a specific namespace of a running container using its PID.

## Exam Tips / Gotchas
- `run` command creates containers in the current selected project unless `--namespace`/`-n` is used.
- Restart policy `Always` is the default.
- `--command` must be followed by `--` to separate the run/exec command from the custom command/args.
- Regular cluster users **cannot** choose the USER/UID for their containers — OpenShift ignores the image's USER instruction and assigns a random UID from the project's uid-range.
- Container's primary GID is always 0 (root group) even though UID is non-root — files written must be group-owned by root with group write permission.
- Distinct UID blocks per project ensure containers in different projects never share a UID — a critical security practice.
- Running a container as UID 0 (privileged/root) is a security risk; Red Hat recommends rootless/unprivileged execution.
- PSA controller only issues a **warning** for missing security context — pod security warnings can be ignored in course exercises, but SCC provides the actual enforcement/safe defaults.
- `oc logs`: default `--tail=` value is -1 (no selectors) = shows all log lines.
- `-p`/`--previous=true` on `oc logs` is useful for troubleshooting a pod that failed to start (shows last attempt's logs).
- Forcibly deleting a pod (`--force`) can cause inconsistency or data loss — only use when certain the pod's processes have ended.
- `--now` = shorthand for `--grace-period=1`.
- Only cluster administrators can SSH to nodes or create debug pods for nodes — regular users cannot.
- Debug pod naming/location for a node depends on whether the selected project allows the privileged SCC.
- Node debug session commands/output are recorded in container logs, **including credentials/sensitive info**.
- CRI-O differs from Podman/Docker: purpose-built and optimized specifically for Kubernetes cluster container execution, and meets the Kubernetes CRI standard.

## Glossary
- **PSA**: Pod Security Admission — Kubernetes controller enforcing/warning on pod security profiles.
- **SCC**: Security Context Constraints — OpenShift controller providing safe pod security defaults.
- **CRI**: Container Runtime Interface — Kubernetes standard that CRI-O conforms to.
- **crictl**: CLI tool for managing containers via CRI-O.
- **lsns**: command to list namespaces of a process.
- **nsenter**: command to enter namespaces of a running process/container.
- **UID/GID base/size format**: project annotation format defining the starting ID and block size for UID/GID assignment.
