## Quick Summary
Covers container image fundamentals (images vs instances), the major image registries (Red Hat Registry, Quay.io, private/public registries), how images are identified (registry/name/ID/tag), image build instructions and metadata, Red Hat's Universal Base Images (UBI), the Skopeo and `oc image` tools for inspecting/managing images, root-user risks, and OpenShift's Sigstore-based image signature verification.

## Key Concepts
- **Container image** — immutable, packaged data defining an application and its dependencies; images can exist without containers, but containers depend on images.
- **Container instance** — a running process created from a container image, isolated by kernel namespaces; one image can create many instances.
- **Registry** — content server storing/sharing container images; consists of one or more repositories with tagged images.
- **Repository/Name** — identifies the image's directory/location within a registry (e.g. `ubi10/httpd-24`).
- **ID/Hash (SHA)** — unique, immutable identifier for exact image content.
- **Tag** — version label for an image; delimited by `:`; omitting a tag defaults to the `latest` floating tag.
- **Floating tag** — alias pointing to another (changing) tag, e.g. `latest` or `10.0`.
- **Fixed tag** — points to a specific, unchanging container build.
- **Layer** — result of a build instruction; consists of differences from the previous layer; layers stack to form a read-only image.
- **Metadata (image)** — instructions/documentation for an image; does not affect running container state, can be overridden at creation.
- **Base image** — the foundation image a container image is built on; determines Linux distribution, package manager, init system, filesystem layout, and preinstalled dependencies/runtimes.
- **UBI (Universal Base Image)** — Red Hat's OCI-compliant enterprise base images containing portions of RHEL; distributable without cost/restriction; full Red Hat support only when deployed on a Red Hat platform.
- **Transport (Skopeo/oc image)** — mechanism to transfer images between locations; common transports are `docker` (registries) and `dir` (local directories); `docker` is the default for `oc image` but must be specified explicitly for skopeo.
- **auth.json** — file where Skopeo stores Base64-encoded registry credentials (at `${XDG_RUNTIME_DIR}/containers/auth.json`).
- **Sigstore** — open source project enabling developers to sign container images and administrators to verify signatures at scale; used by OpenShift for image integrity/authenticity verification.
- **ClusterImagePolicy** — RHOCP custom resource configuring cluster-wide image signature verification policies; specifies registries/repositories to verify and the root of trust (public key or Fulcio CA with Rekor transparency log).
- **Root of trust** — can be a public key or a Fulcio certificate authority with a Rekor transparency log, used in signature verification.

## Operators
- **Machine Config Operator (MCO)** — updates `/etc/containers/policy.json` on all cluster nodes when a ClusterImagePolicy resource is created or updated.

## Commands
| Command | What it does | Key flags/options |
|---|---|---|
| `sudo dnf -y install skopeo` | Installs the Skopeo utility (Fedora/CentOS Stream 8+/RHEL 8+) | `-y` = auto-confirm |
| `skopeo login quay.io` | Logs in to a container registry | — |
| `skopeo list-tags docker://registry.access.redhat.com/ubi10/httpd-24` | Lists all available tags in a repository | transport prefix required (e.g. `docker://`) |
| `skopeo inspect docker://IMAGE-NAME` | Views detailed image info (env vars, tags, etc.) | `--config` = view configuration, metadata, history |
| `skopeo inspect --config docker://registry.access.redhat.com/ubi10/httpd-24` | Retrieves configuration info for an image | `--config` |
| `skopeo copy docker://SOURCE docker://DESTINATION` | Copies an image between locations/repositories | — |
| `skopeo delete docker://IMAGE-NAME` | Deletes an image from a repository | — |
| `skopeo sync --src docker --dest docker SOURCE DESTINATION` | Synchronizes all images from source to destination | `--src`, `--dest` = transport types |
| `skopeo login registry.redhat.io` | Authenticates to a protected registry | prompts for username/password |
| `cat ${XDG_RUNTIME_DIR}/containers/auth.json` | Views stored (Base64-encoded) registry credentials | — |
| `oc image info registry.access.redhat.com/ubi10/httpd-24 --filter-by-os amd64` | Inspects/retrieves image info (ID/hash, layers, metadata) | `--filter-by-os` required for multi-arch repos |
| `oc image append` | Adds layers to a container image and pushes it to a registry | — |
| `oc image extract` | Extracts/copies files from an image to local disk without running it | — |
| `oc image mirror` | Copies/mirrors images between registries or to/from disk | — |

## Comparisons
| Aspect | Red Hat Registry | Quay.io | Private Registries | Public Registries (e.g. Docker Hub, Amazon ECR) |
|---|---|---|---|---|
| Content | Only Red Hat and certified provider images | User-published images + Red Hat/certified images | Organization-controlled images | Registry-owner or community-created/maintained images |
| Push access | Rare — users mostly consume trusted images | Users create namespaces and publish freely | Controlled by image creator | Community/registry owners push |
| Security | Red Hat internal team validates all images; rebuilt to avoid known vulnerabilities | Automatic vulnerability scanning offered | Creator-controlled placement/distribution/usage | Risk of malicious code, vulnerabilities, licensing issues |
| Cost | Requires customer portal/Red Hat Developer login | Free for public images; some features paid | — | Free (community-supported) |

| Aspect | oc image command | Skopeo |
|---|---|---|
| Default transport | `docker` (no need to specify) | None — transport must always be specified |
| Privilege requirement | — | Can execute without a privileged (root) account |
| Daemon requirement | — | Does not require a running daemon |
| Registry auth (in-cluster) | Requires explicit login | Requires explicit login (OpenShift itself auto-authenticates for pod pulls) |

| Aspect | ENV / ARG / USER / ENTRYPOINT / CMD / WORKDIR | EXPOSE / VOLUME / LABEL |
|---|---|---|
| Effect | Affect the state of a running container | Informational/documentation only — do not affect running container state |
| Overridable | Yes, at container creation | Yes, at container creation |

## Exam Tips / Gotchas
- OpenShift does **not** honor the USER instruction for regular cluster users — only cluster administrators can run pods with their chosen UIDs/GIDs.
- Container engines are not required to honor image metadata (e.g. USER, EXPOSE); EXPOSE does not automatically bind the port on the host — documentation only.
- Omitting an image tag defaults to the `latest` floating tag.
- A Red Hat subscription is **not** required to use/distribute UBI-based images, but full Red Hat support requires deployment on a Red Hat platform.
- Four UBI variants: standard (full DNF/systemd), init (systemd-managed multi-app), minimal (microdnf), micro (smallest, no package manager).
- Skopeo can run without root privileges and without a running daemon — unlike some other container tools.
- `oc image` defaults to the `docker` transport; skopeo has **no default transport** — must always specify one.
- Non-privileged containers cannot bind to privileged ports (80, 443) or use `ping` by default (requires raw sockets) — use port forwarding instead.
- Running containers as root is a security risk: if an attacker escapes container isolation, root inside the container traditionally maps to root on the host.
- RHOCP's default `ClusterImagePolicy` named `openshift` enforces Sigstore verification for core OpenShift component images — **must not be removed or modified**.
- In RHOCP 4.22, ClusterImagePolicy verifies **every layer** of an image, not just the top-level manifest — closes a supply-chain security gap for compromised intermediate layers.
- Note: Skopeo does not display password characters during `skopeo login`, but it does register every keystroke — type the full password before pressing Enter.

## Glossary
- **UBI**: Universal Base Image — Red Hat's OCI-compliant base images containing RHEL content.
- **Skopeo**: tool to inspect/manage/copy remote container images without a daemon or root privileges.
- **Transport**: mechanism for transferring images (e.g. `docker`, `dir`).
- **Sigstore**: open source project for signing and verifying container image authenticity.
- **ClusterImagePolicy**: RHOCP custom resource configuring image signature verification policy.
- **Fulcio**: certificate authority option usable as a root of trust for image signatures.
- **Rekor**: transparency log associated with a Fulcio-based root of trust.
- **Floating tag**: an alias tag pointing to the latest matching build (e.g. `latest`, `10.0`).
- **Fixed tag**: a tag pointing to one specific, unchanging image build.
