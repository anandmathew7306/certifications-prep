## Quick Summary
Covers CLI tools for inspecting, editing, and troubleshooting running containers/pods: describe, edit, patch, cp, exec, port-forward, logs, rsync, rsh. Also covers copying files, port forwarding, remote shell access, viewing events/logs, and the practice of using an in-cluster "toolbox" container for troubleshooting.

## Key Concepts
- **Immutable/ephemeral containers** — changes to a running container aren't captured in source control; changes should be identified, then rebuilt into a new image and redeployed rather than left as ad-hoc edits.
- **oc describe** — displays resource details.
- **oc edit** — edits a resource configuration using the system editor (set via `KUBE_EDITOR` or `EDITOR` env variable, else OS default).
- **oc patch** — updates a specific attribute/field of a resource.
- **oc cp** — copies files/directories to and from containers; requires the `tar` binary present in the container.
- **oc exec** — executes a command within a specified container.
- **oc port-forward** — configures a port forwarder for a specified container.
- **oc logs** — retrieves logs for a specified container.
- **oc rsync** — synchronizes files/directories to and from containers; uses local `rsync` client, falling back to `tar` archive if rsync is unavailable.
- **oc rsh** — starts a remote shell within a specified container.
- **Port forwarding mechanism** — connections routed through the kubelet; creates a Kubernetes API request and a multiplexed stream (e.g. HTTP/2) with a port header specifying the target pod port; kubelet delivers stream data to/from the target pod and port.
- **Event resource** — a report of an event occurring somewhere in the cluster.
- **Toolbox container** — a custom container image deployed within the cluster containing troubleshooting tools, providing a reliable environment for investigation/remediation from any computer with cluster access; usable by regular cluster users too (e.g. a MySQL client pod to connect to a MySQL server pod).

## Commands
| Command | What it does | Key flags/options |
|---|---|---|
| `oc describe pod dns-default-lt13h` | Retrieves detailed info about a pod | — |
| `oc edit pod mongo-app-sw88b` | Opens a resource in the default/system editor for editing | `KUBE_EDITOR`/`EDITOR` env var sets the editor |
| `oc patch pod valid-pod --type='json' -p='[{"op": "replace", "path": "/spec/containers/0/image", "value":"..."}]'` | Updates a specific field of a resource (e.g. container image) | `--type='json'`, `-p=` = patch payload |
| `oc cp apache-app-kc82c:/var/www/html/index.html /tmp/index.bak` | Copies a file from a container to local disk | `pod_name:path` format, `-c container_name` for multicontainer pods |
| `oc cp /tmp/index.html apache-app-kc82c:/var/www/html/` | Copies a file from local disk to a container | same as above |
| `oc rsync apache-app-kc82c:/var/www/ /tmp/web_files` | Synchronizes files/directories between a container and local disk | requires `rsync` (or falls back to `tar`) locally and in container |
| `oc port-forward RESOURCE EXTERNAL_PORT:CONTAINER_PORT` | Forwards a local port to a pod's port | — |
| `oc port-forward nginx-app-cc78k 8080:80` | Forwards local port 8080 to pod port 80 | — |
| `oc rsh tomcat-app-jw53r` | Connects to a container via a remote shell | `-c container_name` for a specific container |
| `oc exec POD\|TYPE/NAME [-c container_name] -- COMMAND [args...]` | Executes a command in a container | `-c container_name`, `-it` = interactive with STDIN/STDOUT/STDERR |
| `oc exec mariadb-lc78h -- ls /` | Lists root directory contents in a container | — |
| `oc exec -it mariadb-lc78h -- ls /` | Same, but interactive (affects output format) | `-it` |
| `oc logs dns-default-h9vfw` | Retrieves logs for a pod | `-c container_name` for multicontainer pods |
| `oc get events` | Views pod/cluster events in a namespace | — |

## Exam Tips / Gotchas
- Red Hat does **not** generally recommend editing a running container to fix deployment errors — reserve this for troubleshooting; capture identified fixes in version control, rebuild the image, and redeploy.
- `oc cp` requires the `tar` binary to be present in the container, or the operation fails with an error.
- `oc rsync` requires the `rsync` binary locally and in the container; if `rsync` isn't found, it falls back to a `tar` archive method — without both `rsync`/`tar` available, the command fails.
- For `oc cp`, `oc rsync`, `oc exec`, `oc logs`, `oc rsh`: omitting `-c container_name` targets the **first container** in the pod by default.
- `-it` flags on `oc exec` send STDIN to the container and STDOUT/STDERR back to the terminal, and affect the output format.
- Adding troubleshooting tools to a container image has trade-offs: increases image size (performance impact), may need extra update packages/licensing, and could be exploited by attackers if left in production images.

## Glossary
- **Event resource**: a Kubernetes report of an event occurring in the cluster.
- **Toolbox container**: a custom-built container image with troubleshooting tools, deployed in-cluster for reliable diagnostic access.
- **Multiplexed stream**: a single connection (e.g. HTTP/2) carrying multiple data streams, used by `oc port-forward` via the kubelet.
