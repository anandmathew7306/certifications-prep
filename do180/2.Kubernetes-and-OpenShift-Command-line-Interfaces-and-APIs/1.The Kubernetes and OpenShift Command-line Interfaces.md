## Quick Summary
Covers the kubectl and oc CLIs (oc is a superset of kubectl with OpenShift-specific commands), how to install kubectl, user/authentication types, and the core commands for managing RHOCP/Kubernetes resources (get, describe, explain, create, status, delete, etc.).

## Key Concepts
- **kubectl** — native Kubernetes CLI, a thin wrapper over the Kubernetes API.
- **oc** — OpenShift CLI, a superset of kubectl that adds OpenShift-specific commands (e.g. projects, routes, image streams).
- **User object** — RHOCP object representing an entity that can be granted permissions via roles on the user or their groups.
- **Regular users** — most interactive RHOCP users; represented by a User object.
- **System users** — used by infrastructure to interact with the API securely; includes auto-created cluster administrator; unauthenticated requests default to an anonymous system user.
- **Service accounts** — ServiceAccount objects allowing applications to access the API without sharing regular user credentials; auto-created per project; admins can create additional ones.
- **Project** — a Kubernetes namespace with additional annotations providing multitenancy scoping for applications; provides isolation between application resources.
- **rosa CLI** — additional CLI for Red Hat OpenShift Service on AWS (ROSA) clusters.
- **ocm CLI** — additional CLI for Red Hat OpenShift Dedicated (OSD) clusters.

## Commands
| Command | What it does | Key flags/options |
|---|---|---|
| `curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"` | Downloads the latest kubectl binary release | — |
| `curl -LO "https://dl.k8s.io/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl.sha256"` | Downloads the kubectl checksum file | — |
| `echo "$(cat kubectl.sha256)  kubectl" \| sha256sum --check` | Validates kubectl binary against checksum | prints `kubectl: OK` or `kubectl: FAILED` |
| `sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl` | Installs the kubectl binary | `-o`/`-g` = owner/group, `-m` = permissions |
| `kubectl version --client` | Verifies installed kubectl version | `--client` = client version only |
| `sudo yum install -y kubectl` | Installs kubectl on RHEL-based systems (after adding the Kubernetes repo) | `-y` = auto-confirm |
| `kubectl --help` | Lists available kubectl commands | — |
| `kubectl create --help` | Shows detailed help for the create command | — |
| `kubectl explain pod` | Shows detailed info about a resource's attributes | — |
| `oc login -u username api-url` | Authenticates via username/password | prompts for password |
| `oc login --token=your-token --server=cluster-url` | Authenticates via OAuth token | `--token`, `--server` |
| `oc login --web api-url` | Authenticates via web browser | `--web` |
| `oc login -u admin -p redhatocp https://api.lab.example.com:6443` | Login with plaintext password (not secure; course use only) | `-u` = username, `-p` = password |
| `oc new-project myapp` | Creates a new project (namespace) | — |
| `oc cluster-info` | Prints control plane address and cluster services | `dump` = expands output for debugging |
| `oc api-versions` | Prints supported API versions on the server (group/version) | — |
| `oc get clusteroperator` | Lists cluster operators and their status | — |
| `oc get RESOURCE_TYPE` | Displays summary of all resources of a type | `-o yaml`/`-o json` = export resource definition |
| `oc get all` | Retrieves summary of major resource types in current project | — |
| `oc describe RESOURCE_TYPE RESOURCE_NAME` | Retrieves additional detailed info about a resource | — |
| `oc explain pods.spec.containers.resources` | Describes purpose/fields of an API resource field (JSONPath) | `--recursive` = show all fields without descriptions |
| `oc create -f pod.yaml` | Creates resource(s) from a definition file | `-f` = file (JSON or YAML) |
| `oc status` | High-level overview of current project (services, deployments, build configs, issues) | `--suggest` = show additional issue details |
| `oc delete pod quotes-ui` | Deletes an existing resource | requires resource type + name |
| `oc get pods -n openshift-apiserver` | Runs a command against a different project | `--namespace`/`-n` = target project |

## Comparisons
| Aspect | kubectl | oc |
|---|---|---|
| Scope | Native Kubernetes CLI, thin wrapper over Kubernetes API | Superset of kubectl; adds OpenShift-specific commands |
| Included with | Installable independently | Installing oc CLI also installs kubectl (recommended method) |
| Extra commands | — | `oc login`, `oc new-project` not in kubectl |
| Resource management | Standard Kubernetes resources | Also manages RHOCP-exclusive resources: projects, routes, image streams |

| Aspect | Username/Password Auth | Token-based Auth | Web Auth |
|---|---|---|---|
| Method | `oc login -u username api-url`, prompts for password | `oc login --token=your-token --server=cluster-url`; token retrieved from OAuth token request page | `oc login --web api-url`; opens browser, auto-returns token to CLI |
| Recommended for | Course/simplicity only (not secure) | Production, automation, CI/CD pipelines | Browser-based login flow |

## Exam Tips / Gotchas
- kubectl client must be within one minor version of the cluster (e.g. v1.34 client works with v1.33, v1.34, v1.35 control planes).
- Downloading oc from the OpenShift web console (Help → Command Line tools) ensures compatibility with the cluster.
- version, --help, and explain commands work the same for both oc and kubectl since oc is a superset.
- Token-based authentication is the recommended method for production, automation, and CI/CD (avoids storing plaintext passwords).
- Username/password with plaintext password (`-p`) is not secure and not recommended for production — used here only for course simplicity.
- Deleting a managed resource (e.g. a pod) results in automatic creation of new instances (self-healing behavior).
- Deleting a project deletes all resources and applications within it.
- Commands run in the currently selected project unless `--namespace`/`-n` is specified.
- Some commands (e.g. `oc get clusteroperator`) require cluster administrator access.

## Glossary
- **kubectl**: native Kubernetes CLI.
- **oc**: OpenShift CLI, superset of kubectl.
- **User object**: RHOCP object representing a permission-holding entity.
- **ServiceAccount**: object allowing apps to access the API without regular user credentials.
- **Project**: Kubernetes namespace with added multitenancy annotations.
- **rosa CLI**: CLI for ROSA cluster administration.
- **ocm CLI**: CLI for OSD cluster administration.
- **JSONPath**: identifier format used to reference specific resource fields (e.g. in `oc explain`).
