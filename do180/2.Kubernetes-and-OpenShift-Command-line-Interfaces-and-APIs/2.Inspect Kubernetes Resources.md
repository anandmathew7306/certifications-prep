## Quick Summary
Covers how Kubernetes/RHOCP represent state via API resource objects, how to query and explore resources with `oc api-resources` and `oc explain`, the spec/status structure of objects, and the various tools/output formats (YAML, JSON, custom-columns, JSONPath, Go templates, yq, jq) for filtering and parsing resource data.

## Key Concepts
- **API resource objects** — represent the intended state of everything in the cluster; all admin tasks involve creating, viewing, changing them.
- **SHORTNAME** — abbreviated resource name to reduce typing (e.g. `cm` for configmaps).
- **APIVERSION** — API-Group/API-Version format; blank API-Group means a core Kubernetes resource.
- **KIND** — the formal Kubernetes resource schema type.
- **Namespace ↔ Project** — a one-to-one relationship always exists between a Kubernetes namespace and an OpenShift project.
- **spec object** — describes the intended state of a resource; specified at creation.
- **status object** — describes the current state; continuously updated by Kubernetes controllers, not user-provided.
- **Labels** — key-value pairs under `.metadata.labels`; used to target objects via `-l`/`--selector`.
- **describe subcommand** — human-readable detailed output; format may change between versions, so not recommended for scripting.
- **Filtering tools** — yq (YAML, dot notation), jq (complex JSON queries/transformations), JSONPath (simple JSON queries, no install needed), custom columns (readable tables with specific fields), Go templates (advanced formatting with conditional logic).

## Commands
| Command | What it does | Key flags/options |
|---|---|---|
| `oc api-resources` | Lists Kubernetes resources (name, shortname, apiversion, namespaced, kind) | — |
| `oc api-resources --namespaced=true --api-group apps --sort-by name` | Filters resources by namespace scope, API group, sorted by field | `--namespaced=true/false`, `--api-group`, `--sort-by name\|kind` |
| `oc explain pod` | Shows valid fields for the pod object | — |
| `oc explain pod.spec` | Shows details for a specific field via dot-notation path | — |
| `oc get pod --selector group=developers` | Lists pods matching a label selector | `-l`/`--selector` |
| `oc describe TYPE NAME-PREFIX` | Shows detailed info for an exact match or all resources matching a name prefix | — |
| `oc get pods -o yaml` | Returns pods in YAML format | `-o yaml` |
| `oc get pods -o yaml \| yq '.items[0].status.podIP'` | Extracts a specific field from YAML output | yq uses dot notation |
| `oc get pods -o json` | Returns pods in JSON format | `-o json` |
| `oc get pods -o json \| jq '.items[0].status.podIP'` | Extracts a specific field from JSON output | `.items[]` queries all items |
| `oc get pods -o custom-columns=PodName:".metadata.name",...` | Custom tabular output using jq-style field queries | `-o custom-columns=<name>:<query>,...` |
| `oc get pods -o jsonpath='{range .items[]}...{end}'` | Extracts/formats fields using JSONPath query language | `range` operator iterates over items |
| `oc get pods -o go-template='{{range .items}}...{{end}}'` | Formats output using Go templates | Go expressions inside `{{ }}` |

## Config / YAML Snippets
Example pod manifest:
```yaml
apiVersion: v1        # Object schema version
kind: Pod              # Resource schema type
metadata:              # Annotations, labels, name, namespace
  name: wildfly         # Unique pod name
  namespace: my-app      # RHOCP project the resource resides in
  labels:
    name: wildfly          # Label other resources (e.g. a Service) can use to find this pod
spec:                   # Intended state of the resource
  containers:
    - resources:
        limits:
          cpu: 0.5
      image: quay.io/example/todojee:v1   # Container image
      name: wildfly                        # Container name (used in multi-container oc commands)
      ports:
        - containerPort: 8080
          name: wildfly                     # Port the container uses
      env:                                  # Environment variables
        - name: MYSQL_DATABASE
          value: items
        - name: MYSQL_USER
          value: user1
        - name: MYSQL_PASSWORD
          value: mypa55
status:                  # Current state (Kubernetes-generated: runtime status, readiness, images)
  conditions:
  - lastProbeTime: null
    lastTransitionTime: "2026-07-19T12:59:22Z"
    status: "True"
    type: PodScheduled
```

Labels example:
```yaml
kind: Pod
apiVersion: v1
metadata:
  name: example-pod
  labels:
    app: example-pod        # Used with -l/--selector to target objects
    group: developers        # e.g. oc get pod --selector group=developers
```

## Exam Tips / Gotchas
- You do not need to provide the `status` field when creating an object — Kubernetes generates it.
- Every Kubernetes resource contains `kind`, `apiVersion`, `spec`, and `status` fields.
- Secrets differ from ConfigMaps: Secret values are always encoded (not encrypted), with restricted access.
- `describe` output format may change between versions — not recommended for script development; use YAML/JSON output for scripting instead.
- The two `yq` tools (mikefarah vs kislyuk versions) are **not compatible** — commands for one don't work with the other.
- `--api-group=''` shows only core (non-grouped) resources.

## Glossary
- **SHORTNAME**: abbreviated resource type name (e.g. `cm`, `svc`, `rs`).
- **KIND**: formal Kubernetes resource schema type.
- **JSONPath**: query language for extracting/filtering fields from JSON data structures.
- **yq**: tool for processing YAML (and JSON) output using dot notation.
- **jq**: tool for complex JSON queries/transformations.
- **Go template**: Kubernetes output formatting option using Go language expression syntax (`{{ }}`).
- **Condition (resource status field)**: object with Type, Status, Reason, Message, LastTransitionTime describing part of a resource's status.
- **Custom columns**: `-o custom-columns` output option combining jq-style queries with tabular display.
