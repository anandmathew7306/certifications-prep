## Quick Summary
Covers how Kubernetes/RHOCP represent state via API resource objects, how to query and explore resources with `oc api-resources` and `oc explain`, the spec/status structure of objects, and the various tools/output formats (YAML, JSON, custom-columns, JSONPath, Go templates, yq, jq) for filtering and parsing resource data.

## Key Concepts
- **API resource objects** — represent the intended state of everything in the cluster; all admin tasks involve creating, viewing, changing them.
- **SHORTNAME** — abbreviated resource name to reduce typing (e.g. `cm` for configmaps).
- **APIVERSION** — API-Group/API-Version format; blank API-Group means a core Kubernetes resource.
- **KIND** — the formal Kubernetes resource schema type.
- **Namespace ↔ Project** — a one-to-one relationship always exists between a Kubernetes namespace and an OpenShift project.
- **spec object** — describes the intended state of a resource; specified at creation.
- **status object** — describes the current state; continuously updated by Kubernetes controllers, not user-provided.
- **Labels** — key-value pairs under `.metadata.labels`; used to target objects via `-l`/`--selector`.
- **describe subcommand** — human-readable detailed output; format may change between versions, so not recommended for scripting.
- **Filtering tools** — yq (YAML, dot notation), jq (complex JSON queries/transformations), JSONPath
