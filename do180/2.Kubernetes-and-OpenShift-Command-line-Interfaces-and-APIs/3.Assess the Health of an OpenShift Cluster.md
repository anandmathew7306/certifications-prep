## Quick Summary
Covers how to assess RHOCP cluster health: querying cluster operators (CVO-managed) and add-on operators (OLM-managed), examining metrics via CLI (`oc adm top`) and the web console, reading cluster events and Prometheus-based alerts, checking node/pod status and conditions, debugging nodes/pods, and gathering support data with `must-gather`/`inspect`.

## Key Concepts
- **Operators (general)** — automate tasks to keep RHOCP healthy without human intervention; preferred method for packaging, deploying, managing control-plane services; integrate with Kubernetes APIs and CLI tools; provide monitoring, health checks, OTA updates, and state enforcement.
- **Cluster operators** — perform cluster functions, installed by default, managed by the CVO, queried via Kubernetes `clusteroperators` kind.
- **Add-on operators** — optional, managed by OLM, made accessible for users to run in their applications.
- **Resource conditions** — found in a resource's `status`; track the current state of the object.
- **Cluster utilization (web console)** — Overview page section showing current capacity (CPU, memory, storage, network) and top consumers, sortable by project/pod/node.
- **Resource quota** — if created for a project, current request/limit info appears on the Project details page.
- **Events (Kubernetes)** — high-level logging/auditing facility; generated in response to state changes in cluster objects (nodes, pods, containers) to signal significant actions.
- **Node status conditions** — MemoryPressure, DiskPressure, PIDPressure, Ready, NetworkUnavailable, NotReady, SchedulingDisabled — each indicates a specific node health aspect.
- **Debug pod** — a copy of a source pod (or node) used for troubleshooting; labels removed, command changed to `/bin/sh` (or `cmd.exe` on Windows), readiness/liveness probes disabled; deleted when the session ends.
- **must-gather** — collects resource definitions and service logs likely needed for debugging; creates a temp namespace pod; default output to `./must-gather.local.`.
- **inspect** — gathers debugging data for a specified resource (e.g. a clusteroperator); supports `--since` to filter logs by relative duration.

## Operators
- **Cluster Version Operator (CVO)** — manages default-installed cluster operators (queried via `clusteroperators` kind).
- **Prometheus Operator** — in `openshift-monitoring` namespace; creates, configures, and manages Prometheus and Alertmanager instances.
- **DNS operator** — example cluster operator; its pods live in the `openshift-dns-operator` namespace.
- **lvms-operator** — example OLM add-on operator (from `oc get operators` sample output), in `openshift-storage` namespace.
- **metallb-operator** — example OLM add-on operator (from `oc get operators` sample output), in `metallb-system` namespace.

## Exam Tips / Gotchas
- `describe` output format is human-readable but **can change** between RHOCP versions — prefer `-o yaml`/`-o json` for stable, parsable output.
- Node STATUS `Ready` = healthy, can accept new pods; `NotReady` = a condition triggered this status, node not accepting pods.
- In hosted control plane deployments (e.g. ROSA, Azure Red Hat OpenShift), `oc get nodes` shows **only compute nodes** — control plane runs in a separate management cluster.
- Node condition semantics: `MemoryPressure`/`DiskPressure`/`PIDPressure` = true means a problem; `Ready` = false means unhealthy/not accepting pods.
- `NetworkUnavailable` = true → node network is misconfigured; `SchedulingDisabled` = true → pods cannot be scheduled on the node.
- Node logs may contain sensitive output — `oc adm node-logs` access is limited to privileged node administrators.
- `oc logs` requires the pod (hosting the container) to still exist, even though log output persists after the container stops.
- The `-c container-name` flag is optional only if the pod has a single container; required for multicontainer pods.
- Debug pod modifications: pod labels removed, command changed to `/bin/sh`/`cmd.exe`, readiness/liveness probes disabled.
- Debug session on a node: use `chroot /host` for host binaries, or `nsenter -a -t 1` to access host namespaces without chroot.
- Debug session warning: all commands/output in a node debug session are recorded in container logs, **including credentials and sensitive information**.
- Access to Home → Overview metrics requires cluster administrator, `view`, or `cluster-monitoring-view` cluster role.
- All web console metrics are pulled from Prometheus.
- must-gather default output directory: `./must-gather.local.`; use `--dest-dir` to override.
- Support case recommendation: provide must-gather data **and** the unique cluster ID.

## Glossary
- **CVO**: Cluster Version Operator — manages default cluster operators.
- **OLM**: Operator Lifecycle Manager — manages optional add-on operators.
- **CRI-O**: container runtime running on every node.
- **Kubelet**: node service that converts pod manifests into containers via CRI-O.
- **must-gather**: command/tool that collects cluster debugging data into a directory/archive.
- **Alertmanager**: component receiving alerts from Prometheus and routing them to external notification systems via alert receivers.
- **jsonpath**: query expression syntax used to extract specific fields (e.g. from `get node -o jsonpath`).
