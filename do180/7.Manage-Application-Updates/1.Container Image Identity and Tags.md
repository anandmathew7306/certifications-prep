## Quick Summary
Covers how container image names/tags are structured, the risks of floating tags (unpredictable version changes), using SHA image IDs (digests) for immutable image references, the `imagePullPolicy` options controlling when OpenShift pulls images, and how unused images are garbage-collected from cluster nodes.

## Key Concepts
- **Image name structure** — `registry-server/namespace/name:tag` (e.g. `registry.redhat.io/rhel9/nginx-124:9.8`); omitting the tag defaults to `latest` in most container tools.
- **Multiple tags, same image** — several tags (e.g. `9.8`, `latest`, `1`) can point to the same image version simultaneously.
- **Floating tag** — a tag (e.g. `latest`, `1`) that can be reassigned to point to a different image version over time as new versions are published.
- **Floating tag risk** — vendors can reassign a floating tag without notice; deployments using floating tags can silently run a different/newer image version after pod relocation or scale-up, causing inconsistency across replicas.
- **Static image selection methods** — (1) use a tag that doesn't change (non-floating convention), (2) use OpenShift image streams for tight version control, (3) use the SHA image ID instead of a tag.
- **Floating vs non-floating distinction** — a convention, not a technical restriction; developers are discouraged (not prevented) from pushing a different image to an existing tag.
- **SHA image ID (digest)** — unique, immutable identifier computed/assigned by the container registry; most secure way to reference a specific, unchanging image version; referenced as `name@sha256:...` instead of `name:tag`.
- **Multi-architecture image** — references images for multiple CPU architectures via an index; requires `--filter-by-os` to select a specific architecture when inspecting.
- **imagePullPolicy** — deployment attribute controlling when/how OpenShift pulls an image: `IfNotPresent`, `Always`, `Never`.
- **Image pruning/garbage collection** — deleting a pod doesn't remove its image (allows reuse without re-pulling); kubelet's garbage collector runs every 5 minutes, removing oldest unused images when filesystem usage exceeds 85%, stopping when usage drops below 80%.
- **KubeletConfig Custom Resource (CR)** — used to configure/adjust garbage collector thresholds.

## Commands
| Command | What it does | Key flags/options |
|---|---|---|
| `oc image info registry.redhat.io/rhel9/nginx-124:9.8` | Retrieves image info/SHA ID from a tag | `--filter-by-os` required for multi-arch images |
| `oc image info --filter-by-os linux/amd64 registry.redhat.io/rhel9/nginx-124:9.8` | Retrieves the SHA digest for a specific architecture | `--filter-by-os` |
| `skopeo inspect` | Alternative tool to retrieve image info/digest (different output format, similar data) | — |
| `oc debug node/node-name` | Starts a debug session on a compute node (admin only) | — |
| `crictl images --digests --no-trunc registry.redhat.io/rhel9/nginx-124:9.8` | Lists locally available images with full SHA digests | `--digests` = show SHA IDs, `--no-trunc` = show full string |
| `oc get deployment myapp -o yaml` | Views a deployment's YAML, including `imagePullPolicy` | `-o yaml` |
| `crictl imagefsinfo` | Retrieves the filesystem name/usage storing container images on a node | — |
| `crictl rmi` | Removes an unused image from a compute node (not recommended — may interfere with garbage collector) | — |

## Config / YAML Snippets
Deployment with `imagePullPolicy`:
```yaml
apiVersion: apps/v1
kind: Deployment
spec:
  template:
    spec:
      containers:
      - image: registry.redhat.io/rhel9/nginx-124:9.8
        imagePullPolicy: IfNotPresent    # Controls when OpenShift pulls the image
        name: nginx-124
```

## Comparisons
| Aspect | IfNotPresent | Always | Never |
|---|---|---|---|
| Behavior | Uses local image if already on node; otherwise pulls | Always checks registry for the current SHA ID; pulls only if local image doesn't match | Never pulls; expects image already on node (deployment fails otherwise) |
| Floating tag behavior | Won't re-pull even if the floating tag now points to a newer image (if already local) | Queries registry to confirm tag still points to the same version; pulls new version if tag was reassigned | N/A — no registry contact at all |
| Default for | Tag-based or SHA-based image references | `latest` tag, or when no tag is specified | Must be set explicitly |
| Use case | Standard default behavior | Ensuring latest floating-tag image version is used | Prepopulated nodes; improves speed / avoids registry dependency |

## Exam Tips / Gotchas
- Omitting a tag defaults to `latest` in most container tools.
- Floating tags can be reassigned **without notice** — deployments can silently run a newer image version after pod relocation or scale-up, causing version inconsistency across replicas.
- SHA image ID is the **most secure** way to guarantee an unchanging image reference.
- `oc image info` requires `--filter-by-os` for multi-architecture (manifest list) images — omitting it produces an error listing available OS/architecture options.
- `IMAGE ID` from `crictl images` is a **local** container-engine-assigned identifier, **not related to** the SHA image ID/digest.
- OpenShift sets `imagePullPolicy` to **`IfNotPresent` by default** when using a tag or SHA ID; to **`Always` by default** when using the `latest` tag or no tag at all.
- Deleting a pod does **not** remove its associated image from the node — images persist for reuse.
- Garbage collector: runs **every 5 minutes**; triggers removal of oldest unused images when filesystem usage **exceeds 85%**; stops when usage **drops below 80%**.
- Pruning images manually via `crictl rmi` **might interfere** with the garbage collector and kubelet — recommended to rely on the garbage collector instead (configurable via `KubeletConfig` CR).
- `oc debug node` and `crictl` commands **require cluster administrator privileges**.

## Glossary
- **Floating tag**: a tag that can be reassigned to point to different image versions over time (e.g. `latest`).
- **Fixed/non-floating tag**: a tag intended (by convention) to always point to the same image version.
- **SHA image ID / digest**: immutable, registry-computed unique identifier for a specific image version.
- **imagePullPolicy**: deployment field controlling when OpenShift pulls a container image (IfNotPresent/Always/Never).
- **Multi-architecture image**: an image manifest list referencing versions for multiple CPU architectures.
- **Garbage collector (kubelet)**: process that prunes unused images from compute node disk space based on usage thresholds.
- **KubeletConfig CR**: Custom Resource used to configure garbage collector thresholds.
