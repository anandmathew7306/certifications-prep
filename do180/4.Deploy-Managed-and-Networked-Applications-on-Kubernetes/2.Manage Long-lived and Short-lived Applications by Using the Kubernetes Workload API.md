## Quick Summary
Covers the Kubernetes Workloads API resource types — Jobs, CronJobs, Deployments, DaemonSets, StatefulSets — their purposes, how they differ from each other (and from a plain pod), and how to create each via CLI or web console.

## Key Concepts
- **Workloads API** — composed of various Kubernetes APIs/extensions simplifying deployment/management of applications; main resource types: Jobs, CronJobs, Deployments, DaemonSets, StatefulSets.
- **Job** — represents a one-time task executed via pods; retries a specified number of times on pod failure; does not run again after a specified number of successful completions.
- **`oc run` vs Job** — a pod created via `oc run` is not managed by a higher-level controller: not rescheduled if its node fails, not automatically restarted if it exits with an error.
- **CronJob** — builds on Job by allowing scheduled/recurring execution using Cron format; creates a Job resource based on the configured time zone on the control plane node running the cron job controller.
- **Deployment** — creates a replica set to maintain pods; pods are re-created after a crash/deletion (unlike Jobs).
- **DeploymentConfig** — deprecated (starting OCP 4.14) OpenShift extension to Deployment with extra features like automatic build/image-change triggers; new workloads should use standard Kubernetes Deployment objects.
- **ReplicaSet** — maintains a specified number of pod replicas; uses selectors (e.g. labels) to identify member pods; not managed directly — deployments manage them indirectly.
- **Label** — resource metadata as string key-value pairs indicating a common trait (e.g. `layer=frontend`).
- **Selector** — a query object describing attributes of matching resources; used by resources like ReplicaSets to find their pods.
- **DaemonSet** — ensures all (or some) nodes run a copy of a pod; pods added as nodes join, garbage-collected as nodes leave; deleting the DaemonSet cleans up its pods.
- **StatefulSet** — manages a set of pods based on a container spec, but each pod is unique (e.g. unique network identifier or persistent storage); used for stateful pods, whereas Deployments are used for stateless pods.

## Commands
| Command | What it does | Key flags/options |
|---|---|---|
| `oc create job date-job --image registry.access.redhat.com/ubi9/ubi -- /bin/bash -c "date"` | Creates a job resource | `--image` = container image, `--` separates the command to run |
| `oc create cronjob date-cronjob --image registry.access.redhat.com/ubi9/ubi --schedule "*/1 * * * *" -- date` | Creates a cron job resource | `--schedule` = Cron-format schedule, `--image`, `--` = command |
| `oc create deployment my-deployment --image registry.access.redhat.com/ubi9/ubi --replicas 3` | Creates a deployment resource | `--image`, `--replicas` = number of pod instances |
| `oc delete pod -l environment=testing` | Deletes all pods matching a label | `-l` = label selector |
| `oc create -f daemonset.yaml` | Creates a daemon set from a YAML manifest | `-f` = file |

## Comparisons
| Aspect | Job | CronJob | Deployment | DaemonSet | StatefulSet |
|---|---|---|---|---|---|
| Purpose | One-time task | Recurring/scheduled task (Cron format) | Long-lived, stateless app via replica set | Ensures a pod copy runs on all/some nodes | Long-lived app with unique, stateful pods |
| Pod re-creation on failure | Retries up to specified count; doesn't rerun after success count reached | Creates new Job per schedule | Yes (via replica set) | Yes, tied to node lifecycle | Yes, preserving pod identity |
| Pod uniqueness | N/A | N/A | Pods identical (match template) | Pods identical per node | Each pod unique (e.g. network ID, storage) |

| Aspect | oc run (plain pod) | Job |
|---|---|---|
| Higher-level controller | None | Yes |
| Rescheduled on node failure | No | Yes (via retries) |
| Auto-restart on error exit | No | Yes (per job retry policy) |

| Aspect | Deployment | DeploymentConfig (deprecated) |
|---|---|---|
| Status | Standard Kubernetes object; recommended | OpenShift-specific extension; deprecated starting OCP 4.14 |
| Extra features | — | Automatic triggers for builds and image changes |
| Recommendation | Use for new workloads (upstream alignment, future compatibility) | Avoid for new workloads |

## Exam Tips / Gotchas
- A Job differs from a plain `oc run` pod: Job pods are managed (rescheduled/retried); a bare `oc run` pod is not rescheduled if its node fails and is not auto-restarted on error exit.
- DeploymentConfig is **deprecated starting OpenShift Container Platform 4.14** — use standard Kubernetes Deployment objects instead.
- Starting OpenShift Container Platform 4.22, CronJob schedules can specify a time zone for consistent timing regardless of node location.
- ReplicaSets are not managed directly — always managed indirectly through Deployments.
- Deployments are for **stateless** pods; StatefulSets are for pods requiring **state** (unique identity/storage).
- Deleting a DaemonSet cleans up all pods it created.

## Glossary
- **Job**: one-time task resource executed via pods.
- **CronJob**: scheduled/recurring Job resource using Cron-format scheduling.
- **DeploymentConfig**: deprecated OpenShift-specific deployment extension (replaced by standard Deployment).
- **ReplicaSet**: resource maintaining a specified number of identical pod replicas.
- **DaemonSet**: resource ensuring a pod copy runs on all/some cluster nodes.
- **StatefulSet**: resource managing pods with unique, persistent identities/storage.
- **Label**: string key-value metadata pair attached to a resource.
- **Selector**: query object matching resources by their attributes (e.g. labels).
