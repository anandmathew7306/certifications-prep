## Quick Summary
Covers OpenShift's OVN-Kubernetes SDN, how pods get ephemeral IPs on a shared flat subnet, why services provide stable IPs/load balancing via label selectors to solve the pod-IP-instability problem, how cluster DNS resolves services by FQDN, and the Cluster Network Operator that configures cluster networking.

## Key Concepts
- **SDN (Software-defined networking)** — implemented via OVN-Kubernetes, the default network provider for OpenShift.
- **OVN-Kubernetes** — open source, fully featured Kubernetes CNI plug-in using Open Virtual Network (OVN), a community-developed, vendor-independent network virtualization solution; creates a virtual network spanning all cluster nodes, accessible only to Kubernetes-managed pod processes (not from outside the cluster or by regular node processes).
- **Pod IP instability** — Kubernetes assigns each pod an IP, but pod IPs are unstable because pods are ephemeral (created/deleted continuously, e.g. during redeploys).
- **Shared pod networking** — all containers in a pod share the pod's IP/MAC address; can reach each other's ports via `localhost`, but those ports are not accessible to containers outside the pod.
- **Flat shared networking namespace** — by default, pods can communicate across nodes/namespaces; every pod gets a unique IP from a CIDR range placing all pods on the same subnet, enabling node-to-node pod communication without NAT.
- **Service subnet** — links a service's stable IP to a set of pods; traffic forwarding/routing rules are handled by an OVN-Kubernetes-managed agent based on service selectors.
- **Service** — provides a stable, permanent IP address (unchanged until the service is deleted) for a set of pods; acts as a virtual network load balancer; service endpoints update automatically as pods restart/replicate/reschedule.
- **Label selector matching** — a pod must carry labels matching each of a service's selector fields to be included as a service endpoint.
- **Cluster DNS / DNS operator** — deploys CoreDNS, creates a CoreDNS service resource, configures kubelet so pods use the CoreDNS service IP for name resolution; assigns DNS records to services (even those without a cluster IP, resolving to backing pod IPs).
- **Service FQDN format** — `SVC-NAME.PROJECT-NAME.svc.CLUSTER-DOMAIN`.
- **/etc/resolv.conf (in pods)** — contains `nameserver` (cluster DNS IP), `search` domains (enabling shorter service name resolution), and `options ndots` (dots required in a name to trigger an initial absolute query).
- **Cluster Network CIDR** — defines the IP address range for all pods in the cluster.
- **Service Network CIDR** — defines the IP address range for all services in the cluster.

## Operators
- **DNS operator** — implements the DNS API from the `operator.openshift.io` API group; deploys CoreDNS, creates its service resource, configures kubelet for pod DNS resolution, and assigns DNS records to services.
- **Cluster Network Operator (CNO)** — configures OpenShift cluster networking; loads and configures CNI plug-ins; in cloud services editions like ROSA, it's managed by the cloud provider and not directly accessible to cluster administrators.

| `oc expose deployment/<deployment-name> [--selector <selector>] [--port <port>] [--target-port <target port>] [--protocol <protocol>] [--name <name>]` | Creates a service for a deployment | `--selector` = label selector (defaults to matching the deployment's replica set/RC if omitted); `--port` = service listening port (copied from deployment if omitted); `--target-port` = container port name/number; `--protocol` = TCP by default; `--name` = service name (defaults to deployment name) |

## Comparisons
| Aspect | Pod IP | Service IP |
|---|---|---|
| Stability | Unstable — changes when pod restarts/reschedules/is replaced | Stable — permanent until the service itself is deleted |
| Scope of use | Direct container-to-container reference (fragile) | Referenced by other pods for reliable communication |
| Assignment | Automatically assigned per pod from cluster CIDR | Assigned once to the service resource |

## Exam Tips / Gotchas
- OVN-Kubernetes network is accessible only to Kubernetes-managed pod processes — not accessible from outside the cluster or by regular processes on cluster nodes.
- Pods on the same subnet can communicate across nodes **without NAT** by default.
- Containers within a pod share the pod's IP/MAC and can reach each other only via `localhost` — not accessible to containers outside the pod.
- If `--port` or `--target-port` are omitted from `oc expose`, values are copied from the deployment configuration.
- If `--selector` is omitted from `oc expose`, it defaults to matching the replication controller/replica set.
- `--protocol` defaults to TCP if not specified.
- If `--name` is omitted, the service uses the same name as the deployment.
- A pod's labels must match **each** selector field of a service to be included as an endpoint (partial match is not sufficient).
- In cloud services editions such as ROSA, the CNO is managed by the cloud provider and is **not** directly accessible to cluster administrators.
- FQDN shortcuts: `SVC-NAME.PROJECT-NAME` works cluster-wide via the `svc.cluster.local` search entry; `SVC-NAME` alone works only for pods in the same RHOCP project (since a project = a namespace).

## Glossary
- **SDN**: Software-Defined Networking.
- **CNI**: Container Network Interface — plug-in standard OVN-Kubernetes implements.
- **OVN**: Open Virtual Network — community-developed, vendor-independent network virtualization solution.
- **CIDR**: Classless Inter-Domain Routing — notation for defining IP address ranges (used for both Cluster Network and Service Network).
- **FQDN**: Fully Qualified Domain Name — format used for service DNS names.
- **CoreDNS**: the DNS server deployed by the DNS operator for cluster service discovery.
- **CNO**: Cluster Network Operator — configures cluster networking and CNI plug-ins.
- **ndots**: resolv.conf option specifying how many dots a name needs before triggering an initial absolute DNS query.
