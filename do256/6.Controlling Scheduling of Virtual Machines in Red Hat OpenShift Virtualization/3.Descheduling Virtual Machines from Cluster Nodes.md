# 6.5 Descheduling Virtual Machines from Cluster Nodes

- The scheduler only picks a node at start; the descheduler rebalances later by evicting pods (similar to vSphere DRS).
- Evicting a VM's `virt-launcher` pod triggers a live migration if the VM eviction strategy is `LiveMigrate`.
- Gotcha: usage is calculated from resource requests, not real load.
- Kube Descheduler Operator installs from OperatorHub into `openshift-kube-descheduler-operator`; then create a `KubeDescheduler` instance.
- Profiles safe for VMs:
  - `LongLifecycle`: strategies `LowNodeUtilization`, `RemovePodsHavingTooManyRestarts`, `PodAffinity`. Needs `devEnableEvictionsInBackground` with VMs so it does not wait on migrations.
  - `DevKubeVirtRelieveAndMigrate` (Tech Preview): tuned for VMs, background evictions on, allows evicting pods with PVCs/local storage.
  - Cannot use both together. Avoid other profiles that evict pods with volumes.
- Strategies:
  - `LowNodeUtilization`: moves work from nodes above high threshold (50%) to nodes below low threshold (20%); needs both kinds of node.
  - `RemovePodsHavingTooManyRestarts`: evicts crash-looping pods; guest OS reboots do not count.
  - `PodAffinity`: evicts pods that break affinity rules.
- Opt a VM in with annotation `descheduler.alpha.kubernetes.io/evict` under `spec.template.metadata.annotations` (any value works), or the Descheduler switch in Scheduling. Restart running VMs.
- Key `KubeDescheduler` settings:
  - `mode`: `Predictive` (default, simulate only) or `Automatic` (really evicts).
  - `deschedulingIntervalSeconds`: default 3600.
  - `profiles`, `profileCustomizations` (thresholds, include or exclude namespaces, not both). System namespaces are always skipped.
- Check the descheduler pod logs; settings changes recreate the pod.
