# 6.3 Live Migrating a Virtual Machine

- Live migration moves a running VMI to another node with no downtime (like vMotion). Target node follows the VM's placement rules.
- Node drains trigger it for VMs whose eviction strategy is live migrate.
- Requirements:
  - PVC must be `ReadWriteMany`; set defaults per storage class in the `StorageProfile` (`claimPropertySets`). Only affects new PVCs.
  - Pod network must not use bridge binding.
  - Ports 49152-49153 free in the `virt-launcher` pod.
  - A node that supports the VM's CPU model, plus enough spare RAM and bandwidth.
- Tune in `HyperConverged` CR, `spec.liveMigrationConfig` (`oc edit hco -n openshift-cnv kubevirt-hyperconverged`):
  - `parallelMigrationsPerCluster` (5), `parallelOutboundMigrationsPerNode` (2), `bandwidthPerMigration` (0 = unlimited), `completionTimeoutPerGiB` (150), `progressTimeout` (150).
  - `network`: name of a NAD for a dedicated migration network (bridge built with NMState, NAD in `openshift-cnv`). Recommended.
- Strategies:
  - pre-copy (default): copy memory while guest runs on source, then switch.
  - post-copy (`allowPostCopy`): guest moves first, pages pulled on demand; less bandwidth, slower, state lost if either side crashes.
  - auto-converge (`allowAutoConverge`): pre-copy plus CPU throttling until it finishes.
  - Use post-copy or auto-converge for busy VMs such as databases.
- `MigrationPolicy` CR applies settings to VMs matched by namespace and VMI label selectors.
- Start: `virtctl migrate <vm>` or create a `VirtualMachineInstanceMigration` (`spec.vmiName`).
- Monitor: `oc get vmim`, `oc describe vmi`, console Migrations tab.
- Cancel: `virtctl migrate-cancel <vm>` or delete the `vmim` object.
