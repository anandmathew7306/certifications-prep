# 6.1 Controlling the Placement of Virtual Machines on Cluster Nodes

- Run strategy (`spec.runStrategy`) decides what happens to the VMI:
  - `Always`: keep it running, restart after failure, guest shutdown or VMI deletion.
  - `RerunOnFailure`: restart only on failure, not after a clean guest shutdown.
  - `Halted`: keep it stopped.
  - `Manual`: no automatic restarts; you start/stop with `virtctl` or the console.
  - The old `spec.running` boolean is deprecated.
- Placement rules live under `spec.template.spec` of the VM. Console: VM > Configuration > Scheduling. Restart a running VM to apply them.
- Conflicting rules leave the VM unschedulable.
- `nodeSelector`: node must have every listed label (exact match).
- Node affinity (`affinity.nodeAffinity`): label matching with operators `In`, `NotIn`, `Exists`, `DoesNotExist`.
  - `requiredDuringSchedulingIgnoredDuringExecution` = hard rule.
  - `preferredDuringSchedulingIgnoredDuringExecution` = soft rule with `weight` 1-100.
- Workload affinity / anti-affinity (`podAffinity`, `podAntiAffinity`): place a VM near or away from other VMs/pods by their labels (from `spec.template.metadata.labels`).
  - `topologyKey` sets the domain: `kubernetes.io/hostname` (per node) or a zone label (per zone).
- Affinity rules only act at scheduling time; running VMs are not moved if rules break later.
- Taints on nodes repel VMs without a matching toleration (`spec.template.spec.tolerations`).
  - Effects: `NoSchedule`, `PreferNoSchedule`, `NoExecute` (also evicts existing VMs).
  - Operators: `Equal` (key, value, effect) or `Exists` (no value).
  - A toleration allows a node, it does not force it.
- Place OpenShift Virtualization components via the `HyperConverged` CR: `spec.infra.nodePlacement` and `spec.workloads.nodePlacement`. VMs cannot run where workload placement excludes them.
