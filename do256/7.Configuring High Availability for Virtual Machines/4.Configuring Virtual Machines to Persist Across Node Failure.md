# 7.7 Configuring Virtual Machines to Persist Across Node Failure

- Three HA layers: application (probes, watchdog), node (reschedule VMs off failed nodes), site (RHACM plus replication for Metro-DR or Regional-DR).
- Watchdog actions: `poweroff` (VM restarts unless run strategy is `Manual`), `reset` (hard reboot), `shutdown` (graceful).
- Scheduler profiles (`spec.profile` in the `Scheduler` CR named `cluster`):
  - `LowNodeUtilization` (default): spread evenly.
  - `HighNodeUtilization`: pack onto few nodes.
  - `NoScoring`: fastest, no scoring.
- Eviction strategy per VM in `spec.evictionStrategy`, else the HyperConverged cluster value.
  - Gotcha: `LiveMigrate` on a non-migratable VM stalls the drain and can block a cluster upgrade. Use `LiveMigrateIfPossible` or `None`.
- Node failure: `virt-handler` heartbeats stop; up to about 5 minutes before the node is `NotReady`/`Unknown`.
- Node Health Check (NHC) operator: `NodeHealthCheck` CR detects, then calls a remediation template.
  - SNR: local reboot.
  - FAR: power fencing via IPMI/BMC.
  - MDR: deletes the Machine for a new node (IPI only).
- Machine Health Check: `MachineHealthCheck` CR, Machine API/IPI only, detection and remediation coupled.
  - Only machine-set nodes; one at a time; stops if `maxUnhealthy` is exceeded.
  - Power-based remediation reboots bare-metal nodes instead of reprovisioning; needs BMC access.
- Manual remediation (no NHC/MHC): VMs need run strategy `Always` or `RerunOnFailure`.
  - Power off the node out of band, cordon, drain with `--force`, `oc delete node`, check `oc get vmis -A`.
  - Skipping power-off risks split brain and disk corruption.
