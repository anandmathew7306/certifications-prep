# 7.5 Preparing for Node Maintenance

- Maintenance = cordon (stop new scheduling) + drain (move pods and VMs away).
- Check first: `oc describe node <node>` for workloads, `oc adm top nodes` for spare capacity.
- CLI way:
  - `oc adm cordon <node>`: status becomes `Ready,SchedulingDisabled`.
  - `oc adm drain <node> --ignore-daemonsets --delete-emptydir-data --force` (drain also cordons).
  - `--delete-emptydir-data`: emptyDir workloads restart with an empty volume. `--force`: allow unmanaged pods.
  - `oc adm uncordon <node>` to finish.
- Node Maintenance operator: `NodeMaintenance` CR with `spec.nodeName` and optional `reason`.
  - It cordons and drains; phase goes Running to Succeeded (`oc describe nodemaintenance <name>`).
  - Delete the CR to end maintenance.
- Workloads do not move back afterwards.
- Eviction strategy (`spec.template.spec.evictionStrategy`, or cluster-wide in HyperConverged):
  - `LiveMigrate` (default): a VM that cannot migrate blocks the drain until shut down by hand.
  - `LiveMigrateIfPossible`: migrate, else stop the VM.
  - `None`: no migration; run strategy decides.
  - Console offers only LiveMigrate or None. Restart the VM after changing.
- Live migration needs RWX storage. Non-migratable VMs show a "Not migratable" badge; set them to `None`.
- PodDisruptionBudget (`minAvailable` or `maxUnavailable`) limits voluntary disruptions. KubeVirt creates one per VMI so `virt-launcher` stays until migration ends.
  - Drain retries every 5 s until the PDB allows eviction. Inspect with `oc get pdb`.
