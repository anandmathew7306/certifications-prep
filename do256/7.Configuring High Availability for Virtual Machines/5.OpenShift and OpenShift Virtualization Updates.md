# 7.9 OpenShift and OpenShift Virtualization Updates

- The Cluster Version Operator (CVO) asks the OpenShift Update Service (OSUS) for an update path from the chosen channel. Offline clusters can run a local OSUS.
- Channels (per minor, for example `stable-4.18`): `stable` (default, production), `fast` (earlier), `eus` (long support, even minors only), `candidate` (pre-release).
- Reaching the next minor may first need a specific patch version.
- Update types: full cluster (default, rolling) or Control Plane Only (workers stay behind, for short windows).
- Console: Administration > Cluster Settings; watch the ClusterOperators tab.
- Machine Config Operator updates RHCOS as one image, cordoning and draining each node so VMs migrate.
  - `MachineConfig` = node customisation (Ignition). `MachineConfigPool` = node group; `maxUnavailable` sets parallel updates.
  - Progress: `oc get mcp`. History: `oc describe clusterversion version`.
- OpenShift Virtualization operator version must match OpenShift; automatic approval is recommended.
- Operator updates do not stop VMs; new `virt-launcher` parts (libvirt, qemu) reach VMs via `workloadUpdateStrategy` in HyperConverged:
  - `workloadUpdateMethods`: `LiveMigrate` (default; non-migratable VMs stay outdated) and/or `Evict` (restart per run strategy).
  - `batchEvictionSize` (default 10), `batchEvictionInterval` (default 1m).
- Outdated VMs: `oc get vmi -A -l kubevirt.io/outdatedLauncherImage`.
- Troubleshoot: `oc adm must-gather`; `--image` for the CNV plug-in, `--dest-dir` for the output folder.
