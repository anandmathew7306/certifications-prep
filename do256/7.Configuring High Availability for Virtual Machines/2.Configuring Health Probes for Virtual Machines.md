# 7.3 Configuring Health Probes for Virtual Machines

- Probes are periodic health checks; they work for VMs as well as pods.
- Readiness probe: on failure the VM IP leaves the service; it is added back once healthy. Good for slow starts or busy periods.
- Liveness probe: on failure the VMI is deleted and a new one starts. Good for hung apps.
- Check types:
  - `httpGet`: path and port; pass = HTTP code 200-399.
  - `tcpSocket`: pass if a TCP connection opens (databases, file servers).
  - Guest agent ping: Tech Preview, out of scope.
- Set under `spec.template.spec.readinessProbe` / `livenessProbe` of the VirtualMachine (console YAML tab or `oc edit vm`).
- Gotcha: restart a running VM for probe changes to apply.
- Tuning fields (defaults):
  - `initialDelaySeconds` (0)
  - `periodSeconds` (10)
  - `timeoutSeconds` (1)
  - `failureThreshold` (3)
  - `successThreshold` (1)
- Watchdog: emulated timer (default 30 s) that the guest OS keeps resetting; if the OS hangs, it fires.
  - Detects OS hangs only. Prefer liveness probes; use a watchdog only when the app cannot be probed.
  - Add under `spec.template.spec.domain.devices.watchdog` with `i6300esb` (only model supported) and an `action`.
  - Actions: `poweroff` (then restart per run strategy), `reset`, `shutdown`.
  - Guest needs the 6300ESB driver; RHEL loads it automatically.
