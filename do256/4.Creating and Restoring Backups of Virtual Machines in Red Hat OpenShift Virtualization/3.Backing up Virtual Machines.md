# 4.5 Backing up Virtual Machines

- A `Backup` CR (`velero.io/v1`) in `openshift-adp` starts a one-time backup.
- Backups sync with object storage (only `Completed` ones), so other clusters can see them.
- Flow: Velero exports resources, CSI snapshots the volume, Data Mover uploads it with Kopia, temp objects are removed.
- `includedResources` is an exact list: only `kubevirt.io/virtualmachine` skips PVCs and data volumes.
- Better: label the VM and use `labelSelector`.
- Include the `Namespace` so UID/GID ranges come back on restore (label it, or use `kubernetes.io/metadata.name`).
- Resources are always a full backup; PVs are full first, then incremental.
- Hooks: `pre` failing gives `Failed`; `post` failing gives `PartiallyFailed`. Run in a container (e.g. `compute`) of pods matched by label.
  - The `Pod` type must be in the backup or hooks are silently skipped.
  - Running VMs get automatic freeze/unfreeze hooks.
- Kopia file-system backup for volumes without snapshot support: `defaultVolumesToFsBackup: true`, or annotation `backup.velero.io/backup-volumes: vol1,vol2`. Done by the `node-agent` pods.
- Kopia keeps one repository per namespace under `<prefix>/kopia/<ns>`, tracked by a `BackupRepository` CR.
- Velero CLI: `alias velero='oc -n openshift-adp exec deployment/velero -c velero -it -- ./velero'`.
  - `velero get backup`, `velero describe backup <name> --details`, `velero backup logs <name>`.
  - grep logs for `hookPhase` to debug hooks.
- Delete with `velero delete backup <name>`; deleting only with `oc` gets re-synced back.
- Default TTL 30 days, minimum 1 hour. Repository data can take up to 24 hours to be removed.
