# 4.1 OpenShift APIs for Data Protection

- OADP operator = built-in backup and restore for OpenShift, based on upstream Velero.
- Backs up Kubernetes resources, PV data and internal registry images; also covers VMs and their disks.
- Main parts:
  - Velero: runs backup/restore jobs and calls plug-ins.
  - CSI plug-in: takes volume snapshots through the CSI snapshot API.
  - Kopia: copies volume data to remote object storage (dedup, encryption, compression).
  - Data Mover: moves CSI snapshot content to object storage using Kopia + CSI.
- Supported for VMs: CSI backups, and CSI backups with Data Mover. Incremental backups only work with Data Mover.
- Resources can be filtered by namespace, resource type or label.
- Snapshots are preferred (fast, consistent), but some drivers keep snapshots on the same storage as the volume. Use Data Mover to get a copy offsite for disaster recovery.
- Plug-ins: `aws` (S3-compatible), `gcp`, `azure`, `openshift` (OpenShift resources and images), `kubevirt` (VMs, required for Virtualization), `csi`.
  - Data Mover needs `csi`, `kubevirt` and `openshift`, plus one storage plug-in.
- OADP API resources:
  - `DataProtectionApplication` (DPA): main config of OADP.
  - `BackupStorageLocation`: one per storage location in the DPA.
  - `VolumeSnapshotLocation`: one per snapshot location in the DPA.
  - `Backup`, `Restore`: ask Velero to back up or restore.
  - `Schedule`: recurring backups using cron syntax.
  - `BackupRepository`: tracks Kopia backup repositories.
- Hooks: commands run in a pod before or after a backup or restore.
