# 4.9 Scheduling Virtual Machine Backups

- A `Schedule` CR (`velero.io/v1`) in `openshift-adp` makes recurring backups, like a cron job.
- Create it from the OADP operator page (Schedule tab) or YAML. The form lacks some options, such as `matchLabels`.
- Key fields:
  - `schedule`: cron string, e.g. `"0 7 * * *"`.
  - `template`: same fields as a `Backup` spec (`includedNamespaces`, `labelSelector`, `ttl`).
  - `ttl`: retention, e.g. `720h0m0s` = 30 days.
  - `paused: true` disables it.
  - `skipImmediately: true` stops an instant backup when created or unpaused (default `false`).
- Labels on the Schedule are copied to the backups it makes.
- Cron fields: minute, hour, day of month, month (1-12 or JAN-DEC), day of week (0-6 or SUN-SAT).
  - `*` = every; `*/30 * * * *` = every 30 minutes.
- Deleted backup data may stay in the repository up to 24 hours until maintenance runs.
- `velero get schedule` shows status (`Enabled`, or `New` if created paused), cron, TTL and last backup.
- On-demand backup from a schedule template: `velero create backup <name> --from-schedule <schedule>`; other filters are ignored.
  - Tip: keep a paused schedule as a reusable backup template.
- Backups from a schedule are named `<schedule>-<timestamp>` and labelled `velero.io/schedule-name`.
- Find them with `velero get backup -l app=<label>` or `-l velero.io/schedule-name=<schedule>`.
- `openshift-adp` holds backups for every app, so labels are key for finding yours.
