# 3.1 Migrating Virtual Machines from Other Hypervisors

- Migration Toolkit for Virtualization (MTV) moves VMs into OpenShift Virtualization from vSphere, RHV, OpenStack, another OpenShift Virtualization cluster, or VMware OVA files.
  - Operator lives in `openshift-mtv`; after install, create a `ForkliftController`.
- Key CRs (in `openshift-mtv`):
  - `Provider`: endpoint and credentials. Local cluster provider is created automatically.
  - `NetworkMap` / `StorageMap`: source network/datastore to OpenShift network/storage class. Both required.
  - `Plan`: VMs from one provider, target namespace, mappings.
  - `Migration`: runs a plan and tracks phases (Initialize, DiskAllocation, ImageConversion, DiskTransferV2v, VirtualMachineCreation).
- Validation service flags risky or unsupported VM settings as concerns.
- Transfer network: pod network by default; a NAD in `openshift-mtv` isolates migration traffic.
- Each extra source network needs a NAD on the target.
- Cold (default): VM off, copy, power on. A VM already off stays off.
- Warm: precopy with CBT snapshots while running, then cutover (manual or scheduled). Needs CBT on VM and disks.
- Options: preserve static IPs (target network must support it), disk decryption passphrases.
- Hooks: pre-migration (source VM) and post-migration (before first boot), as Ansible playbook or custom image. A failed hook stalls the migration.
- Importer pod copies disks; conversion pod runs `virt-v2v` to add drivers.
- Archive the plan to remove temporary pods and PVCs; deleting without archiving leaves them.
- Performance: max 20 concurrent transfers, about 10 per ESXi host; use VDDK for VMware.
- Troubleshoot: provider, concerns, `oc describe migration -n openshift-mtv <plan>`, pod logs, quotas.
