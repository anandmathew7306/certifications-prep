# 3.3 Migrating Virtual Machines from VMware

- Source can be vCenter or a standalone ESX/ESXi host.
- Prerequisites:
  - Supported vSphere version; user with minimum MTV privileges.
  - Guest OS supported by OpenShift Virtualization and `virt-v2v`.
  - VMware Tools needed for pre-migration hooks.
  - Warm migration needs CBT on VM and disks (`ctkEnabled=TRUE`).
  - No hibernated VMs; plan ahead for in-guest iSCSI or NFS.
- VDDK image:
  - Recommended; without it migrations can be slow or fail.
  - Extract the VDDK tarball on a file system that keeps symlinks, build a UBI image that copies it to `/opt`, push with `podman`.
  - Private registry only (license); set pull secrets.
- More than 10 VMs from one ESXi host per plan: raise NFC `maxMemory` in `/etc/vmware/hostd/config.xml`, restart `hostd` (no reboot).
- vSphere Provider fields: name, endpoint type (vCenter shows all VMs, ESXi only its own), URL ending in `/sdk`, VDDK init image, credentials, optional skip TLS check.
- Plan wizard as for other providers; max 500 VMs or 500 disks per plan.
- Cold migration: power VMs off first; MTV tries anyway.
- Errors:
  - `warm import retry limit reached`: 28 CBT snapshots hit; delete some, restart.
  - `Unable to resize disk image to required size`: EXT4 on block storage; raise CDI file system overhead above 10%.
- `oc adm must-gather --image=<mtv-must-gather image>` collects MTV data (cluster-admin).
  - Filter with `-- NS=<ns> /usr/bin/targeted`, `PLAN=<plan>`, or `VM=<vm> NS=<ns>`.
