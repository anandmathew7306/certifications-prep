# 2.1 Creating Cluster User-defined Networks for Virtual Machines

- User-defined networks (UDNs) are a simpler, validated alternative to NADs; OVN-Kubernetes turns UDN CRs into NADs.
- Two CRDs:
  - `UserDefinedNetwork` - namespaced, made by project admins, isolates one namespace.
  - `ClusterUserDefinedNetwork` (CUDN) - cluster-scoped, made by cluster admins, joins several namespaces into one tenant network.
- Primary UDN replaces the pod network for every pod in the namespace; secondary UDN adds an extra interface.
- Topologies: layer 3 (per-node subnets, IP changes on move) and layer 2 (one flat subnet, IP kept across nodes).
- For VMs (4.18): only primary role and only `Layer2` topology. Layer 2 keeps the VM IP, so live migration works.
- Namespace must be created with label `k8s.ovn.org/primary-user-defined-network: ""`.
  - Cannot add it to an existing namespace.
  - Can be added to the project request template.
  - Labelled namespace with no UDN = pods fail to start ("invalid primary network state").
- CUDN spec key fields: `namespaceSelector` (`matchLabels` or `matchExpressions`), `network.topology: Layer2`, `layer2.role: Primary`, `subnets` (one IPv4, optional IPv6), `ipam.lifecycle: Persistent` (needed for live migration).
- Gotchas:
  - CUDN creates a NAD with the same name in each matched namespace; an existing NAD with that name makes it fail. Use unique names.
  - 4.18 web console bug gives the CUDN a random name; the CLI does not.
- Check: `oc describe clusteruserdefinednetwork <name>` (Conditions), `oc get net-attach-def -A -l k8s.ovn.org/user-defined-network`.
