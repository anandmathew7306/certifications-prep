# 2.7 Connecting a Virtual Machine to External Storage

- Each VM disk is its own PVC (no shared datastore as in VMware).
- No provisioner? Use static provisioning: admins declare existing volumes as PVs, PVCs bind to them.
- Two ways to give a VM external storage:
  - Mount it inside the guest OS (NFS, SMB, iSCSI) with the OS's own tools.
  - Wrap it in a PV/PVC and attach it as a VM disk.
- If storage sits on a dedicated network: NMState configures the node side, Multus adds a VM interface on that network.
- Static PV notes:
  - PVs are cluster-scoped; only cluster admins create them.
  - `claimRef` reserves the PV for one named PVC.
  - `Block` mode preferred for VM disks; `Filesystem` stores a disk image file.
- Backend specifics:
  - iSCSI: RWO or ROX only, so no live migration. Block or Filesystem.
  - NFS: supports RWX (live migration works); Filesystem only.
  - Fibre Channel: RWO, Block only, nodes need HBAs.
- PVC for a static PV: size at most the PV size, same access mode and volume mode, `storageClassName: ""`.
- Deleting the PVC keeps the PV. To reuse it, admin removes `uid` from the PV's `claimRef`.
- Prefill with an IMG/ISO/QCOW2 image: `virtctl image-upload pvc <pvc> --image-path=<file> --no-create`.
- Attach in console: VM > Configuration > Storage > Add disk > Volume, source PVC.
- Gotcha: hot plug to a running VM needs the SCSI interface; `virtio` requires stopping the VM.
