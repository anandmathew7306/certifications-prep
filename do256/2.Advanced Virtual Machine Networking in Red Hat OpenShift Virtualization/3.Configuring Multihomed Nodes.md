# 2.5 Configuring Multihomed Nodes

- Kubernetes NMState operator: declarative node network config, applied without reboot. After install, create an `NMState` instance named `nmstate`.
- NMState configures nodes; Multus attaches extra interfaces to pods/VMs.
- NMState resources:
  - `NodeNetworkState` (NNS) - current network state per node. `oc get nns/<node> -o yaml`.
  - `NodeNetworkConfigurationPolicy` (NNCP) - desired state (bridges, bonds, Ethernet, STP, IPv4). Applies to all nodes unless `nodeSelector` is set. `oc get nncp`.
  - `NodeNetworkConfigurationEnactment` (NNCE) - per-node result of a policy; failed nodes roll back and NNCE holds the traceback. `oc get nnce`.
- Removing an interface: set `state: absent`. Ports under a removed bridge/bond go down, so in the same policy set the NIC `up` with DHCP or static IP.
- Gotcha: absent or deleting an NNCP does not restore the old config; write a new policy for that.
- Linux bridge vs OVS bridge:
  - Linux bridge: in-kernel, simple, stable, no network isolation.
  - OVS bridge: more features (isolation, QoS, tunnels), harder to troubleshoot.
- OVN layer-2 overlay secondary networks: east-west only, no traffic leaves the cluster.
- Localnet topology: links a secondary network to a physical network so VMs reach outside devices. Needs an OVS bridge plus `ovn.bridge-mappings` (`localnet` name -> bridge) in an NNCP.
- Different NIC names per node type: label nodes, one NNCP per type via `nodeSelector`.
- Then create a NAD with `type: ovn-k8s-cni-overlay`, `topology: localnet`, `netAttachDefName: <ns>/<name>`, name matching the localnet.
- NADs in `default` are usable by all VMs.
