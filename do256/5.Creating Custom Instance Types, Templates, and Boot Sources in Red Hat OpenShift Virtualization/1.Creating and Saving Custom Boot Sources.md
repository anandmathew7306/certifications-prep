# 5.1 Creating and Saving Custom Boot Sources

- Golden image = a ready-made VM disk (OS, drivers, apps) used as the starting point for new VMs. Usually a QCOW2 or RAW file.
- Boot source chain: registry image -> `DataImportCron` (scheduled import) -> `DataSource` (points to the golden image, shows in Bootable volumes) -> `DataVolume` (clone request) -> VM disk PVC.
- Build a container disk from a QCOW2:
  - Containerfile: `FROM scratch` and `ADD --chown=107:107 image.qcow2 /disk/` (107 = qemu user).
  - `podman build -t <registry>/<repo>:tag .`, then `podman push`.
- Registry without TLS: add it to `spec.storageImport.insecureRegistries` in the `hco kubevirt-hyperconverged` resource (`openshift-cnv`).
- `enableCommonBootImageImport` feature gate = true pulls Red Hat images into `openshift-virtualization-os-images`.
- DataSource labels set defaults: `instancetype.kubevirt.io/default-instancetype` and `default-preference`. The preference label is needed for the console to list the volume.
- Useful commands: `oc get datasource -A`, `oc get dataimportcron -n openshift-virtualization-os-images`.
- Scope:
  - Volumes in `openshift-virtualization-os-images` are usable by everyone.
  - Volumes in any other namespace are usable only there.
- Console: Bootable volumes > Add volume. Sources are upload, clone PVC/snapshot, or registry (registry creates a DataImportCron).
- Authenticated registry: console cannot do it (4.18), so write a `DataImportCron` YAML:
  - `source.registry.url` (`docker://...`) and `secretRef`.
  - `managedDataSource` auto-creates the DataSource; `schedule`, `importsToKeep`, `garbageCollect: Outdated`.
  - Gotcha: create the registry secret in both `openshift-virtualization-os-images` and `openshift-cnv`.
- Change the default boot image namespace with `spec.commonBootImageNamespace` in the HyperConverged resource (feature gate must be on).
