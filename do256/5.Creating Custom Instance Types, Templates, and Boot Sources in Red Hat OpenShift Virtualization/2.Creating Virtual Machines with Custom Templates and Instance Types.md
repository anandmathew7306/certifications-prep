# 5.3 Creating Virtual Machines with Custom Templates and Instance Types

- A VM template is an OpenShift `Template` holding a `VirtualMachine` with `${VAR}` placeholders.
- Template parts: `metadata` (name, namespace, labels), `objects` (the VM, often with `dataVolumeTemplates`), `parameters`.
  - Parameters can be required, have a default, or be generated (`generate: expression` with a regex in `from`).
  - The DataVolume name must match the disk name under `volumes`.
- Built-in templates: `oc get templates -n openshift -l template.kubevirt.io/type=base`.
- Built-in templates cannot be edited, only cloned. Custom templates are visible only in their own project.
- Console edit tabs include Scheduling, Network interfaces, Disks, Scripts (cloud-init, sysprep, SSH keys), Parameters.
- CLI workflow:
  - Export: `oc get template <name> -n openshift -o yaml > t.yaml`.
  - List variables: `oc process --parameters -f t.yaml`.
  - Create VM: `oc process -f t.yaml -p NAME=vm1 | oc create -f -`.
- Instance types set CPU and memory (both required).
  - Kinds: `VirtualMachineClusterInstancetype` (cluster-wide) and `VirtualMachineInstancetype` (namespaced).
  - Gotcha: a VM using an instance type cannot override its CPU and memory.
  - `virtctl create instancetype --name x --cpu 2 --memory 2Gi | oc apply -f -`. Add `--namespaced` for the namespaced kind.
- Preferences set preferred devices (disk bus, NIC, machine type, storage class).
  - Kinds: `VirtualMachineClusterPreference` and `VirtualMachinePreference`.
  - `virtctl create preference` covers only some fields; edit the YAML for the rest.
- Console: Catalog > InstanceTypes > User provided tab for custom instance types; Template catalog > User templates for custom templates.
