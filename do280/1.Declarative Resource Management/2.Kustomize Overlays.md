## Quick Summary
Covers Kustomize, a configuration management tool for applying declarative customizations to a common base of Kubernetes manifests across multiple environments (overlays), including patches, generators for ConfigMaps/Secrets, and rendering/applying/deleting resources via `oc kustomize`/`oc apply -k`/`oc delete -k`.

## Key Concepts
- **Kustomize** — configuration management tool for making declarative changes to app configs/components while preserving original base YAML files; integrated into both `kubectl` and `oc`.
- **kustomization.yaml** — file at the root of a Kustomize directory defining resources, customizations, patches, generators, etc.
- **Base** — a directory with a `kustomization.yaml` listing all common resource files (e.g. configmap, deployment, secret, service, route) shared across environments.
- **Overlay** — a directory with its own `kustomization.yaml` referencing one or more base directories, applying patches/customizations without modifying the original base files; multiple overlays can share a common base.
- **namespace field** — sets a specific namespace for all resources in a kustomization.
- **namePrefix / nameSuffix** — add a prefix/suffix to the name of all resources.
- **labels field** — adds labels to all resources and selectors; replaces the deprecated `commonLabels` key.
- **commonAnnotations field** — adds annotations to all resources and selectors.
- **commonLabels (deprecated)** — old key behaving like `labels`; encountered in existing files; `kustomize edit fix` (standalone binary only, not integrated into oc/kubectl) can convert it, or manually replace with `labels` + `pairs`.
- **patches field** — unified key (Kustomize v5+) replacing deprecated `PatchesJson6902` and `PatchesStrategicMerge` keys; supports JSON Patch and strategic merge patch formats; each patch entry has a `patch` (or `path` to a file) and a `target` (kind/name of resource to patch).
- **allowNameChange option** — enables a patch file to change a resource's name via the `options` field on a patch.
- **oc kustomize** — renders manifests from a kustomization directory without applying them to the cluster.
- **oc apply -k** — applies (creates or updates) resources defined by a kustomization directory.
- **oc delete -k** — deletes resources that were deployed via a kustomization directory.
- **configMapGenerator** — Kustomize field generating a ConfigMap resource; appends a hash suffix to the generated name; any content change creates a new hash/name, triggering a rolling update; can source data from `literals`, `files`, or `envs` (`.env` file).
- **secretGenerator** — works like `configMapGenerator` but for Secrets; also performs required Base64 encoding of the data; supports `files`, `envs`, `literals`.
- **generatorOptions** — alters default generator behavior; can disable the hash suffix (`disableNameSuffixHash: true`) and add labels/annotations to generated resources.
- **Hash suffix rationale** — workload resources (e.g. Deployments) don't detect content changes to ConfigMaps/Secrets on their own; the generator's hash-based renaming (new name on content change) is what triggers a rollout.
- **Operators auto-observing secrets** — some operators (e.g. the OpenShift OAuth operator for htpasswd secrets) apply changes immediately without needing a hash-triggered rollout — disabling the hash suffix may be appropriate in such cases.

## Operators
- **OpenShift OAuth operator** — automatically applies changes to htpasswd secrets without requiring a rollout trigger (an example of an operator that observes ConfigMap/Secret content directly).

## Commands
| Command | What it does | Key flags/options |
|---|---|---|
| `oc kustomize overlays/production` | Renders manifests from a kustomization directory without applying | — |
| `oc apply -k overlays/production` | Applies (creates/updates) resources from a kustomization directory | `-k` |
| `oc delete -k overlays/production` | Deletes resources deployed via a kustomization directory | `-k` |
| `oc kustomize .` | Renders manifests for the current kustomization directory | — |

## Config / YAML Snippets
Base kustomization.yaml:
```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:                   # Lists all resource files in the base
- configmap.yaml
- deployment.yaml
- secret.yaml
- service.yaml
- route.yaml
```

Overlay (development) kustomization.yaml:
```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
namespace: dev-env             # Sets namespace for all resources
resources:
- ../../base                    # References the base directory
```

Overlay (testing) with inline patches:
```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
namespace: test-env
patches:                        # List of patches
- patch: |-
    - op: replace                 # Renames the frontend deployment
      path: /metadata/name
      value: frontend-test
  target:                          # Kind/name of resource to patch
    kind: Deployment
    name: frontend
- patch: |-                       # Updates replica count
    - op: replace
      path: /spec/replicas
      value: 15
  target:
    kind: Deployment
    name: frontend
resources:
- ../../base
labels:                            # Adds env: test label to all resources
- pairs:
    env: test
```

Overlay (production) with external patch file:
```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
namespace: prod-env
patches:
- path: patch.yaml                 # References an external patch file
  target:
    kind: Deployment
    name: frontend
  options:
    allowNameChange: true            # Allows the patch file to rename the resource
resources:
- ../../base
labels:
- pairs:
    env: prod
```

patch.yaml (external patch file content):
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: frontend-prod       # Renames the deployment (requires allowNameChange: true)
spec:
  replicas: 5                 # Sets replica count
```

configMapGenerator example:
```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
namespace: hello-stage
resources:
- ../../base
configMapGenerator:
- name: hello-app-configmap
  literals:                       # Literal key-value data
    - msg="Welcome!"
    - enable="true"
```

Deployment referencing generated ConfigMap:
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: hello
  labels:
    app: hello
    name: hello
spec:
    spec:
      containers:
      - name: hello
        image: quay.io/hello-app:v1.0
        env:
        - name: MY_MESSAGE
          valueFrom:
            configMapKeyRef:
              name: hello-app-configmap    # References generator-created ConfigMap by base name
              key: msg
        - name: MSG_ENABLE
          valueFrom:
            configMapKeyRef:
              name: hello-app-configmap
              key: enable
```

configMapGenerator with multiple source types:
```yaml
configMapGenerator:
- name: configmap-1
  files:
    - application.properties      # Sourced from a .properties file
- name: configmap-2
  envs:
    - configmap-2.env              # Sourced from a .env file
- name: configmap-3
  literals:
    - name="configmap-3"           # Sourced from literal key-value pairs
    - description="literal key-value pair"
```

secretGenerator example:
```yaml
secretGenerator:
- name: secret-1
  files:
    - password.txt                 # Sourced from a file
- name: secret-2
  envs:
    - secret-mysql.env               # Sourced from a .env file
- name: secret-3
  literals:                           # Sourced from literal key-value pairs
    - MYSQL_DB=mysql
    - MYSQL_PASS=root
```

generatorOptions example:
```yaml
configMapGenerator:
- name: my-configmap
  literals:
    - name="configmap-3"
    - description="literal key-value pair"
generatorOptions:
  disableNameSuffixHash: true        # Disables the hash suffix on generated resource name
  labels:
    type: generated-disabled-suffix    # Added to generated resource
  annotations:
    note: generated-disabled-suffix     # Added to generated resource
```

## Comparisons
| Aspect | configMapGenerator | secretGenerator |
|---|---|---|
| Purpose | Generates ConfigMap resources | Generates Secret resources |
| Data sources | `literals`, `files`, `envs` | `literals`, `files`, `envs` |
| Encoding | None (plain data) | Performs Base64 encoding automatically |
| Hash suffix | Appended by default (triggers rollout on change) | Appended by default (triggers rollout on change) |

| Aspect | Base | Overlay |
|---|---|---|
| Purpose | Common resource set shared across environments | Environment-specific customizations/patches on top of a base |
| Modifies original files? | N/A (defines them) | No — applies patches without modifying base files |
| Can reference multiple? | N/A | Multiple overlays can share one common base |

## Exam Tips / Gotchas
- `commonLabels` is **deprecated** — replace with `labels` + `pairs`; `kustomize edit fix` (standalone binary only, not in oc/kubectl) can help convert.
- `PatchesJson6902` and `PatchesStrategicMerge` are **deprecated in Kustomize v5** — replaced by the unified `patches` key (same underlying patch formats still supported: JSON Patch and strategic merge).
- Workload resources (e.g. Deployments) do **not** automatically detect content changes to ConfigMaps/Secrets — the **hash-suffix rename mechanism** in generators is what triggers a rollout when content changes.
- Some operators (e.g. **OpenShift OAuth operator** for htpasswd secrets) apply Secret/ConfigMap content changes immediately without needing the hash-based rollout trigger — in these cases `disableNameSuffixHash: true` may be appropriate.
- `allowNameChange: true` is required in the `options` field of a patch entry if the patch file is meant to change a resource's `metadata.name`.
- `oc kustomize` only **renders** manifests (no changes applied); `oc apply -k` actually applies/creates resources.

## Glossary
- **Kustomize**: declarative configuration management tool for customizing Kubernetes manifests without modifying originals.
- **Base**: directory containing the common, shared set of resource manifests.
- **Overlay**: directory containing environment-specific patches/customizations referencing one or more bases.
- **configMapGenerator**: Kustomize field that generates a ConfigMap resource (with a hash-suffixed name by default).
- **secretGenerator**: Kustomize field that generates a Secret resource (Base64-encoded, hash-suffixed name by default).
- **generatorOptions**: field controlling generator behavior (e.g. disabling hash suffix, adding labels/annotations).
- **disableNameSuffixHash**: generatorOptions setting to omit the hash suffix from a generated resource's name.
