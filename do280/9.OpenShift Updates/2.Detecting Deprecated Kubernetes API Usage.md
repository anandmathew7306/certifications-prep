## Quick Summary
Covers the OpenShift-to-Kubernetes version mapping, the Kubernetes API deprecation policy (alpha/beta/stable maturity levels and deprecation/removal timelines), how to detect deprecated API usage via `oc get apirequestcounts` and Prometheus alerts, and specific deprecated/removed features in recent Kubernetes and OpenShift releases.

## Key Concepts
- **OpenShift-Kubernetes version mapping** — OCP 4.16 → Kubernetes 1.29; OCP 4.17 → Kubernetes 1.30; OCP 4.18 → Kubernetes 1.31.
- **API maturity categories** — `v1alpha1` (Alpha, experimental), `v1beta1` (Beta, pre-release), `v1` (Stable, generally available).
- **Deprecation-to-removal timeline** — when a stable version of a feature is released, its beta versions are marked deprecated and removed after **three Kubernetes releases**; exact timeline varies per API.
- **Deprecation warning behavior** — using a deprecated (but still available) API version returns a **warning** from the API server (naming the current replacement version) but the resource is still created.
- **Removed API behavior** — using a **removed** API version returns an **error** ("no matches for kind... ensure CRDs are installed first") — the resource is NOT created.
- **apirequestcounts** — resource tracking API usage; lists deprecated APIs currently in use by the cluster, with a `REMOVEDINRELEASE` column indicating the Kubernetes version that will remove that API.
- **Per-user/action filtering of apirequestcount** — JSONPath can extract verb/username/userAgent info from a specific `apirequestcount` resource to identify who/what is using a deprecated API.
- **Deprecated feature (OpenShift)** — a feature not recommended for new deployments because a future release will remove it.
- **APIRemovedInNextReleaseInUse alert** — fires when a workload uses an API that OpenShift will remove in the **next release**.
- **APIRemovedInNextEUSReleaseInUse alert** — fires when a workload uses an API that OpenShift EUS will remove in the **next EUS release**.
- **Prometheus-based alert extraction** — deprecated API alerts can be queried directly from the Prometheus stateful set's API and filtered with `jq`; an empty JSON array `[]` means no such alerts are currently firing.

## Commands
| Command | What it does | Key flags/options |
|---|---|---|
| `oc api-resources \| grep -E '^NAME\|cronjobs'` | Shows the current API version for a resource type | — |
| `oc create -f plc-beta3.yaml` | Creates a resource; shows a deprecation warning if using a deprecated (but supported) API version | — |
| `oc create -f plc-beta2.yaml` | Fails with an error if the API version has been fully removed | — |
| `oc get apirequestcounts` | Lists deprecated APIs currently in use, with their removal release version | — |
| `oc get apirequestcount <resource.version.group> -o jsonpath="<filter>"` | Extracts per-user/verb usage details for a specific deprecated API resource | `-o jsonpath` |
| `oc exec -it statefulset/prometheus-k8s -c prometheus -n openshift-monitoring -- curl -fsSL 'http://localhost:9090/api/v1/alerts' \| jq . > alerts.json` | Extracts all firing Prometheus alerts to a JSON file | `-c` = container, `-n` = namespace |
| `jq '[.data.alerts[] \| select(.labels.alertname=="APIRemovedInNextReleaseInUse" or .labels.alertname=="APIRemovedInNextEUSReleaseInUse")]' < alerts.json` | Filters alerts to only deprecated-API-usage alerts | — |

## Exam Tips / Gotchas
- Using a **deprecated but still available** API version → **warning only**, resource is still created.
- Using a **removed** API version → **error**, resource creation fails entirely.
- Beta APIs are typically removed **three Kubernetes releases** after a stable version is released — but the **exact timeline varies per API**.
- Kubernetes 1.31 (OCP 4.18) stopped serving several previously-deprecated API versions, e.g. `flowcontrol.apiserver.k8s.io/v1beta2` → replaced by `v1`.
- `oc get apirequestcounts`'s `REMOVEDINRELEASE` column tells you exactly which Kubernetes version will drop support for that deprecated API — use this for upgrade planning.
- An **empty JSON array `[]`** from the alert-filtering `jq` command means **no deprecated API alerts are currently firing** — not an error.
- Know the specific OCP 4.16→4.17→4.18 deprecation table: e.g. `node-role.kubernetes.io/master` label on compute nodes is **fully removed** in 4.18; `DeploymentConfig` has been deprecated since 4.16; `runC` is deprecated in 4.18 (crun is now default for new clusters).

## Glossary
- **v1alpha1**: experimental (Alpha) API maturity level.
- **v1beta1**: pre-release (Beta) API maturity level.
- **v1**: stable, generally available API maturity level.
- **apirequestcounts**: resource tracking cluster API usage, including deprecated API usage and removal timelines.
- **APIRemovedInNextReleaseInUse**: alert for deprecated API usage slated for removal in the next OpenShift release.
- **APIRemovedInNextEUSReleaseInUse**: alert for deprecated API usage slated for removal in the next EUS release.
