## Quick Summary
Covers Kubernetes NetworkPolicy (NP) and OpenShift AdminNetworkPolicy (ANP) resources for restricting pod/VM network traffic using label selectors instead of IP addresses, including default-deny patterns, namespace-to-namespace rules, logical AND/OR selector combinations, allowing access from cluster services (ingress/monitoring), and cluster-wide ANP priority/evaluation behavior.

## Key Concepts
- **Default open communication** — by default, all pods/VMs in a project are accessible from other pods/VMs/endpoints in the cluster, including across namespaces.
- **NetworkPolicy (NP)** — Kubernetes resource controlling traffic between pods using **labels** instead of IP addresses; namespace-scoped; does not require administrative privileges — developers can define their own; policies are additive (union of all matching policies determines allowed traffic).
- **Host networking exception** — network policies do NOT block traffic from pods using host networking to pods on the same node; a single-node "deny all" policy won't stop ingress pods using host network strategy from reaching application pods on that node; policies only control internal traffic from non-host-networking pods — traffic leaving a node has no such exception.
- **AdminNetworkPolicy (ANP)** — cluster-scoped resource; lets cluster administrators enforce cluster-wide network rules that individual namespace users **cannot override**; evaluated with **higher precedence** than NP.
- **ACL Tiers (OVN-Kubernetes)** — Tier 1 evaluates ANP objects, Tier 2 evaluates NP objects; evaluated in descending order (Tier 1 → Tier 2); if traffic matches an ANP rule, NP rules are skipped; if no ANP match (or an ANP "pass" rule matches), evaluation proceeds to Tier 2 (NP).
- **default-deny policy** — a common first step: empty `podSelector: {}` with no ingress rules applies to all pods in the namespace and blocks all traffic; explicit allow policies are then needed to permit desired traffic.
- **No-match behavior** — if a pod doesn't match ANY network policy, OpenShift does NOT restrict traffic to it — to fully lock down a namespace, an explicit default-deny policy is required.
- **podSelector (top-level, under spec)** — defines which pods the policy itself applies to (the policy's "destination" pods).
- **ingress.from selectors** — define which source pods/namespaces are allowed to send traffic to the selected pods.
- **namespaceSelector + podSelector combination logic** — nested (combined in one `from` list item) = logical AND; listed as separate items in the `from` list = logical OR.
- **Namespace labeling for network policies** — administrators label namespaces (e.g. `oc label namespace network-1 network=network-1`) so network policies can reference them via `namespaceSelector`.
- **Explicit access for cluster services** — pods protected by network policies may still need explicit policies to allow traffic from OpenShift router pods (ingress/routes) and the monitoring service (if exposing metrics endpoints).
- **AdminNetworkPolicy priority** — determines evaluation order; lower values evaluated first (range 0–1000); ANPs override conflicting namespace-scoped NPs when using Allow/Deny actions, based on priority — careful priority assignment is needed to avoid unintended overrides.
- **ANP subject field** — specifies which namespaces/pods the ANP applies to; an empty `namespaces: {}` selector applies cluster-wide.
- **ANP action types** — `Allow`, `Deny` (and implicitly `Pass`, referenced in evaluation logic) — `action` and `name` fields are required per ANP rule.
- **ANP networks field (egress)** — selects external peers by CIDR block for traffic leaving the cluster.
- **Layer 2 (VLAN) limitation** — managing security between projects with VLANs is impractical due to lack of dynamic control; network policies provide more flexible, label-based, least-privilege access control between projects.

## Config / YAML Snippets
Default-deny NetworkPolicy:
```yaml
kind: NetworkPolicy
apiVersion: networking.k8s.io/v1
metadata:
  name: default-deny
spec:
  podSelector: {}    # Empty selector = applies to all pods in this project; no ingress rules = blocks all traffic
```

NetworkPolicy allowing specific pod/namespace/port combination (AND logic via nesting):
```yaml
kind: NetworkPolicy
apiVersion: networking.k8s.io/v1
metadata:
  name: network-1-policy
  namespace: network-1
spec:
  podSelector:                    # Required: defines which pods this policy applies to
    matchLabels:
      deployment: product-catalog
  ingress:                          # List of ingress rules for the selected pods
  - from:                             # Sources allowed to send traffic (not limited to this namespace)
    - namespaceSelector:
        matchLabels:
          network: network-2
      podSelector:
        matchLabels:
          role: qa
    ports:                             # Destination ports traffic is allowed on
    - port: 8080
      protocol: TCP
```

NetworkPolicy allowing all pods from a labeled namespace (less restrictive):
```yaml
kind: NetworkPolicy
apiVersion: networking.k8s.io/v1
metadata:
  name: network-2-policy
  namespace: network-2
spec:
  podSelector: {}                # Applies to all pods in the network-2 namespace
  ingress:                         # Ingress-only policy (no egress field = only inbound restricted)
  - from:
    - namespaceSelector:
        matchLabels:
          network: network-1        # Allows ingress from any pod in a network-1-labeled namespace
```

Logical AND example (nested selectors — namespace AND pod label both required):
```yaml
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          network: dev
      podSelector:                 # Nested under same list item = AND
        matchLabels:
          app: mobile
```

Logical OR example (separate list items — either condition allowed):
```yaml
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          network: dev
    - podSelector:                 # Separate list item = OR
        matchLabels:
          app: mobile
```

Allowing OpenShift ingress and monitoring access:
```yaml
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-from-openshift-ingress
spec:
  podSelector: {}                   # Applies to all user application pods in the namespace
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          policy-group.network.openshift.io/ingress: ""   # Targets the openshift-ingress namespace
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-from-openshift-monitoring
spec:
  podSelector: {}
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          network.openshift.io/policy-group: monitoring   # Targets the openshift-monitoring namespace
```

AdminNetworkPolicy blocking untrusted namespaces cluster-wide:
```yaml
apiVersion: policy.networking.k8s.io/v1alpha1   # ANP API group
kind: AdminNetworkPolicy
metadata:
  name: block-untrusted
spec:
  priority: 100                 # Lower values evaluated first (range 0-1000)
  subject:
    namespaces: {}                # Empty selector = applies cluster-wide
  ingress:
  - from:
      - namespaces:
          matchLabels:
            untrusted: "true"       # Matches traffic from any namespace labeled untrusted=true
    action: Deny                     # Traffic matching this rule is dropped
    name: deny-untrusted-ingress       # Required unique rule identifier
```

AdminNetworkPolicy denying all ingress to sensitive namespaces:
```yaml
kind: AdminNetworkPolicy
apiVersion: policy.networking.k8s.io/v1alpha1
metadata:
  name: deny-sensitive-ingress
spec:
  priority: 10
  subject:
    namespaces:
      matchLabels:
        sensitive: true
  ingress: []          # Empty ingress = denies all ingress traffic to selected namespaces
```

AdminNetworkPolicy allowing egress to a specific CIDR:
```yaml
kind: AdminNetworkPolicy
apiVersion: policy.networking.k8s.io/v1alpha1
metadata:
  name: allow-frontend-egress
spec:
  priority: 20
  subject:
    namespaces:
      matchLabels:
        app: frontend
  egress:
  - action: Allow                 # Required; permits the matched traffic
    name: allow-db-egress
    to:
    - networks:                     # Selects external peers by CIDR block
      - 10.0.0.0/24
    ports:
    - portNumber:                    # Matches a specific port/protocol
        port: 3306
        protocol: TCP
```

## Comparisons
| Aspect | NetworkPolicy (NP) | AdminNetworkPolicy (ANP) |
|---|---|---|
| Scope | Namespace-scoped | Cluster-scoped |
| Who defines it | Developers / namespace administrators | Cluster administrators |
| Overridable by namespace users | Yes (it IS the namespace-level rule) | No — enforces rules users cannot override |
| Evaluation precedence | Evaluated after ANP (Tier 2 ACLs) | Evaluated first (Tier 1 ACLs), highest precedence |
| Requires admin privileges | No | Yes |
| Has priority field | No | Yes (0–1000, lower = evaluated first) |

## Exam Tips / Gotchas
- Network policies do **not** block traffic from pods using **host networking** to pods on the **same node** — a "deny all" policy won't stop host-network ingress pods from reaching app pods on that node; this exception does **not** apply once traffic leaves the node.
- If a pod matches **no** network policy, OpenShift does **not** restrict its traffic — you must define an explicit **default-deny** policy to fully lock down a namespace.
- **ANP is evaluated before NP** — if traffic matches an ANP rule, that rule's Allow/Deny action applies and any matching NP rules are **skipped**.
- ANP `priority` range is **0–1000**, with **lower values evaluated first**.
- ANPs **override conflicting NPs** when using Allow/Deny actions, based on priority — assign priorities carefully to avoid unintended overrides.
- Selector nesting determines logic: **nested under the same `from` list item = AND**; **separate items in the `from` list = OR**.
- Explicit policies are commonly needed to allow traffic from **OpenShift router pods** (ingress/routes) and the **monitoring service** — these are not automatically exempted from network policy restrictions.
- The `name` field is **required** for each ANP rule (unlike standard NP rules) to provide a unique identifier.
- Layer 2 technologies (VLANs) are **impractical** for inter-project security compared to network policies, due to lack of dynamic control.

## Glossary
- **NetworkPolicy (NP)**: namespace-scoped Kubernetes resource controlling pod traffic via label selectors.
- **AdminNetworkPolicy (ANP)**: cluster-scoped OpenShift resource enforcing non-overridable cluster-wide network rules.
- **ACL Tier**: OVN-Kubernetes evaluation layer — Tier 1 for ANP, Tier 2 for NP.
- **podSelector**: field selecting which pods a policy applies to (or, within `from`, which source pods are allowed).
- **namespaceSelector**: field selecting which namespaces are matched by label for a policy rule.
- **priority (ANP field)**: numeric value (0–1000) determining ANP evaluation order; lower = first.
- **subject (ANP field)**: specifies which namespaces/pods an ANP applies to.
