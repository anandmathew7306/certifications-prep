## Quick Summary
Covers connecting pods to secondary/custom networks via the Multus CNI plug-in: NetworkAttachmentDefinition (NAD) resources for existing/custom networks (host device, bridge, IPVLAN, MACVLAN), and OpenShift's newer User-Defined Networks (UDN) and Cluster User-Defined Networks (CUDN) for simpler, isolated, and consistent-IP networking — including how pods attach to these networks and how to verify their status.

## Key Concepts
- **Pod network** — default Kubernetes network interface for pods, providing communication between all pods by default.
- **Service network** — provides stable addressing for services running on pods.
- **Multus CNI plug-in** — attaches pods to custom (secondary) networks, either existing external networks or networks internal to the cluster; benefits include improved performance (dedicated resources), different security properties, and simplified outgoing traffic control.
- **NetworkAttachmentDefinition (NAD)** — namespaced custom resource defining a secondary network; available only to pods in its own namespace; can create/manage virtual network devices (e.g. bridges) or use existing node network interfaces; can also perform additional network configuration.
- **NAD types** — Host device (attaches a network interface to a single pod), Bridge (uses/configures a bridge interface; attached pods can communicate via the bridge and any networks connected to it), IPVLAN (Linux driver-based network attached to an interface), MACVLAN (Linux driver-based network attached to an interface).
- **Bridge vs IPVLAN vs MACVLAN** — similar purposes but differ in MAC address usage, filtering capabilities, and other features; e.g. IPVLAN uses fewer MAC addresses than MACVLAN, useful in networks with MAC address limits.
- **IPAM (IP Address Management) CNI plug-in** — provides IP addresses for other CNI plug-ins (e.g. `dhcp` or `static` type configuration within a NAD's `ipam` key).
- **User-Defined Network (UDN)** — simpler alternative to NADs for non-administrator users; OVN-Kubernetes-based; provides configuration validation and status tracking; can serve as a pod's primary or secondary network interface; created by project administrators, scoped to a single namespace, providing network isolation from other namespaces.
- **ClusterUserDefinedNetwork (CUDN)** — created by cluster administrators; joins multiple namespaces into the same UDN-based network (requires cluster-admin privileges).
- **UDN benefits over the pod network** — tenant isolation (per-namespace or shared-via-CUDN isolation from pod network/other UDNs), simpler network configuration (isolation by default reduces need for complex NetworkPolicies), consistent IP addressing (reusable IP subnets across namespaces, e.g. same subnet for isolated dev/test/prod environments).
- **Primary UDN (P-UDN)** — when a UDN is created as primary, all pods in the namespace use it as the primary network interface (replacing the cluster pod network) — all pod traffic uses it by default.
- **Secondary UDN (S-UDN)** — pods use the UDN as a secondary interface; only traffic specific to that network uses it.
- **UDN topology** — supports layer-2 and layer-3 (starting OpenShift 4.18); layer-3 uses the node's local router to connect pods via a transit switch across nodes, each pod gets an IP from its node's subnet (different subnet per node), and migrating pods get a new IP in the destination node's subnet — same topology model as the cluster pod network.
- **k8s.ovn.org/primary-user-defined-network namespace label** — required on a namespace (at creation time only — cannot be added later) to use a UDN/CUDN as the primary network interface for pods in that namespace.
- **UDN pod isolation from default network** — by default, UDN pods are isolated from the default network; the `k8s.ovn.org/open-default-ports` pod annotation opens specific ports for access from the default network (e.g. for monitoring services).
- **NAD naming collisions with CUDN** — creating a CUDN generates a NAD with the same name in each matching namespace; if a NAD with that name already exists elsewhere in the cluster, CUDN creation fails — Red Hat recommends unique names for UDNs/CUDNs cluster-wide.
- **k8s.v1.cni.cncf.io/networks pod annotation** — attaches a pod to one (or more) additional networks by referencing a NAD, UDN, or CUDN name (or a list of maps for more config).
- **k8s.v1.cni.cncf.io/network-status pod annotation** — automatically updated by Multus with the status of all attached networks (default + additional), including interface names (e.g. `net1`) and assigned IPs.
- **k8s.ovn.org/user-defined-network label** — applied to NADs that a UDN/CUDN manages, used to filter/list them via `oc get net-attach-def`.

## Operators
- **Kubernetes NMState operator** — used to customize node network configuration via custom resources.
- **SR-IOV network operator** — configures SR-IOV (Single Root I/O Virtualization) network devices for improved bandwidth/latency on supported platforms/devices; pods can also be attached to SR-IOV-configured networks.

## Commands
| Command | What it does | Key flags/options |
|---|---|---|
| `oc get userdefinednetwork my-udn -o yaml` | Shows the status/conditions of a UserDefinedNetwork resource | `-o yaml` |
| `oc describe clusteruserdefinednetwork cudn_name` | Shows status/conditions of a ClusterUserDefinedNetwork resource | — |
| `oc get net-attach-def -A` | Lists NetworkAttachmentDefinitions cluster-wide | `-A`, `-l k8s.ovn.org/user-defined-network` = filter to UDN/CUDN-managed NADs |
| `oc get pod example -o jsonpath='{.metadata.annotations.k8s\.v1\.cni\.cncf\.io/network-status}'` | Retrieves a pod's attached-network status | `-o jsonpath` (periods in field names must be escaped with `\`) |

## Config / YAML Snippets
NetworkAttachmentDefinition (host device):
```yaml
apiVersion: k8s.cni.cncf.io/v1
kind: NetworkAttachmentDefinition
metadata:
  name: example                    # Network name
spec:
  config: |-
    {
      "cniVersion": "0.3.1",
      "name": "example",             # Must match the metadata.name value
      "type": "host-device",           # Network type
      "device": "ens4",
      "ipam": {                          # Additional network configuration
        "type": "dhcp"
      }
    }
```

Equivalent additional network via Cluster Network Operator config:
```yaml
apiVersion: operator.openshift.io/v1
kind: Network
metadata:
  name: cluster
spec:
  additionalNetworks:
  - name: example                  # Network name
    namespace: example               # Namespace
    rawCNIConfig: |-                   # CNI plug-in config in JSON
      {
        "cniVersion": "0.3.1",
        "name": "example",               # Must match name above
        "type": "host-device",             # Network type
        "device": "ens4",
        "ipam": {                            # Additional network configuration
          "type": "dhcp"
        }
      }
    type: Raw
```

Static IPAM configuration example:
```json
"ipam": {
  "type": "static",
  "addresses": [
    {"address": "192.168.X.X/24"}
  ]
}
```

Namespace with UDN primary-network label:
```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: my-namespace
  labels:
    k8s.ovn.org/primary-user-defined-network: ""   # Required at namespace creation; cannot be added later
```

UserDefinedNetwork custom resource:
```yaml
apiVersion: k8s.ovn.org/v1
kind: UserDefinedNetwork
metadata:
  name: my-udn
  namespace: my-namespace
spec:
  topology: Layer2                  # Network topology
  layer2:
    role: Primary                     # Whether this is the primary interface for pods
    subnets:                            # CIDR subnets: one IPv4 required, IPv6 optional
      - "10.0.0.0/16"
      - "2001:db8::/60"
    ipam:
      lifecycle: Persistent               # Whether IPs persist across reboots/migrations
```

ClusterUserDefinedNetwork custom resource (matchLabels selector):
```yaml
apiVersion: k8s.ovn.org/v1
kind: ClusterUserDefinedNetwork
metadata:
  name: development-udn
spec:
  namespaceSelector:                 # Labels identifying namespaces to join the network
    matchLabels:
      environment: development
  network:
    topology: Layer2                   # Network topology
    layer2:
      role: Primary                       # Whether primary interface for VMs
      subnets:                              # CIDR subnets: IPv4 required, IPv6 optional
      - 10.0.0.0/16
      - 2001:db8::/60
      ipam:
        lifecycle: Persistent                 # Whether IPs persist across reboots/migrations
```

ClusterUserDefinedNetwork with matchExpressions selector:
```yaml
apiVersion: k8s.ovn.org/v1
kind: ClusterUserDefinedNetwork
metadata:
  name: development-udn
spec:
  namespaceSelector:
    matchExpressions:
      - key: kubernetes.io/metadata.name
        operator: In
        values:
          - my-namespace
          - another-project
```

UDN pod opening ports to the default network:
```yaml
apiVersion: v1
kind: Pod
metadata:
  annotations:
    k8s.ovn.org/open-default-ports: |     # Opens specific ports for access from the default network
      - protocol: tcp
        port: 80
      - protocol: udp
        port: 53
```

Deployment attaching to an additional network via Multus:
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: example
  namespace: example
spec:
  selector:
    matchLabels:
      app: example
      name: example
  template:
    metadata:
      annotations:
        k8s.v1.cni.cncf.io/networks: example    # References the NAD/UDN/CUDN name to attach
      labels:
        app: example
        name: example
```

## Comparisons
| NAD Type | Description |
|---|---|
| Host device | Attaches a network interface to a single pod |
| Bridge | Uses/creates a bridge interface; attached pods communicate via the bridge and connected networks |
| IPVLAN | Linux driver-based network attached to an interface; uses fewer MAC addresses |
| MACVLAN | Linux driver-based network attached to an interface |

| Aspect | NetworkAttachmentDefinition (NAD) | User-Defined Network (UDN) |
|---|---|---|
| Target users | More admin/advanced use cases (external networks, specific CNI plug-ins) | Non-administrator users; simpler configuration |
| Validation/status | Not built-in | Configuration validation + status section included |
| Scope | Namespaced | UDN: single namespace; CUDN: multiple namespaces (cluster-admin only) |
| Underlying tech | Various CNI plug-ins | OVN-Kubernetes (creates NADs under the hood) |

| Aspect | Primary UDN (P-UDN) | Secondary UDN (S-UDN) |
|---|---|---|
| Replaces cluster pod network? | Yes — becomes the pod's primary interface | No — used only for traffic specific to that network |
| Default traffic behavior | All pod traffic uses this network by default | Only traffic on this network uses this interface |

## Exam Tips / Gotchas
- The `k8s.ovn.org/primary-user-defined-network` label **must be set at namespace creation** — it **cannot** be added to an existing namespace.
- Creating a namespace with the UDN label but **without** actually creating a UDN in it causes **all pod starts in that namespace to fail** with an `addLogicalPort failed` error.
- From the web console, you can create **only one UDN per namespace** as the primary network interface.
- **Known issue in OpenShift 4.18**: creating a CUDN via the web console assigns it a **random name** instead of the admin-provided name — creating via CLI is unaffected.
- Creating a CUDN generates a NAD with the **same name** in each matching namespace — if a NAD with that name **already exists** elsewhere in the cluster, CUDN creation **fails** — use unique names for UDNs/CUDNs cluster-wide to avoid this.
- Creating a cluster UDN **requires cluster administrator privileges**.
- UDN topology support for **layer-2 and layer-3 starts with OpenShift 4.18**.
- In JSONPath, periods (`.`) are the field-access operator — to access a field **containing** a literal period in its name (e.g. `k8s.v1.cni.cncf.io/network-status`), you must **escape periods with a backslash** (`\.`).
- All pods in the cluster still use the **cluster-wide default network** for cluster-wide connectivity, even when additional networks are attached.

## Glossary
- **Multus**: CNI plug-in that attaches pods to secondary/custom networks.
- **NAD (NetworkAttachmentDefinition)**: namespaced resource defining a secondary network attachment.
- **IPAM**: IP Address Management CNI plug-in providing IPs to other CNI plug-ins.
- **UDN (User-Defined Network)**: OVN-Kubernetes-based custom resource providing a simpler, isolated network for a namespace.
- **CUDN (ClusterUserDefinedNetwork)**: cluster-scoped UDN joining multiple namespaces into one network.
- **P-UDN / S-UDN**: Primary / Secondary User-Defined Network roles for pod network interfaces.
- **SR-IOV**: Single Root I/O Virtualization — hardware-level network device virtualization for improved bandwidth/latency.
