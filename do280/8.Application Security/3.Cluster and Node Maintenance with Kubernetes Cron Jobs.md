## Quick Summary
Covers using Kubernetes Jobs and CronJobs to automate maintenance tasks, the standard Linux cron schedule syntax, and two practical patterns: application-level maintenance (e.g. a scripted WordPress backup) and cluster-level maintenance (e.g. pruning unused images on all nodes via privileged debug pods, driven by a ConfigMap-mounted script).

## Key Concepts
- **Job** — Kubernetes resource specifying a task executed **once**; contains a pod template with at least one container.
- **CronJob** — Kubernetes resource defining a **schedule** to execute a job template; when due, Kubernetes creates a Job resource from the CronJob's template — otherwise Jobs/CronJobs behave as standard Kubernetes resources.
- **Cron schedule syntax** — 5 fields: minute (0-59), hour (0-23), day of month (1-31), month (1-12), day of week (0-7, Sunday = 0 or 7).
- **Common schedule examples** — `0 0 * * *` (daily at midnight), `0 0 * * 7` (weekly, Sunday midnight), `0 * * * *` (hourly), `0 */4 * * *` (every 4 hours).
- **restartPolicy for Jobs** — `Never` shown in job examples; CronJob's job template commonly uses `OnFailure`.
- **YAML folded style (`>`)** — converts newlines to spaces when parsing; used to write multi-line shell command sequences as a single string argument (commands separated by `;`), passed to `bash -xc`.
- **Application maintenance automation** — e.g. periodic backups: activate maintenance mode → export/compress DB → deactivate maintenance mode → copy backup to external storage — implemented as a scheduled CronJob running a maintenance-tool image with a scripted command sequence.
- **Cluster maintenance automation** — e.g. pruning unused container images cluster-wide: a ConfigMap holds a maintenance shell script; a CronJob mounts this ConfigMap as a volume and runs it using an image containing the `oc` CLI (e.g. `origin-cli`), which loops over all nodes and runs `oc debug <node> -- chroot /host ... crictl rmi --prune` to free storage.
- **crictl rmi --prune** — command to clean up unused container images on a node (accessed via `chroot /host` inside a debug pod).
- **Cluster maintenance privilege requirements** — typically require elevated privileges; achieved by assigning a dedicated service account (with the needed privileges) to the Job/CronJob via `spec.serviceAccountName`, or changing it on an existing workload via `oc set serviceaccount`.

## Commands
| Command | What it does | Key flags/options |
|---|---|---|
| `oc create job --dry-run=client -o yaml test --image=... -- curl https://example.com` | Generates the YAML for a Job without creating it | `--dry-run=client`, `-o yaml`, `--image=`, `--` = command |
| `oc create cronjob --dry-run=client -o yaml test --image=... --schedule='0 0 * * *' -- curl https://example.com` | Generates the YAML for a CronJob without creating it | `--dry-run=client`, `-o yaml`, `--image=`, `--schedule=`, `--` = command |
| `oc debug ${NODE} -- chroot /host /bin/bash -xc 'crictl images ; crictl rmi --prune'` | Runs a debug pod on a node and prunes unused container images | `--` = command to run in the debug pod |
| `oc get nodes -o=name` | Lists node names (used to iterate over nodes in a maintenance script) | `-o=name` |
| `oc set serviceaccount` | Changes the service account of an existing workload | — |

## Config / YAML Snippets
Basic Job definition:
```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: test
spec:                        # Job specification
  template:                    # Pod template
    metadata:
    spec:                        # Pod specification
      containers:                  # Pod containers
      - command:                     # Command
        - curl
        - https://example.com
        image: registry.access.redhat.com/ubi9/ubi:9    # Container image
        name: test
        resources: {}
      restartPolicy: Never
```

Basic CronJob definition:
```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: test
spec:
  jobTemplate:                   # Job template
    metadata:
      name: test
    spec:                          # Job specification
      template:                       # Pod template
        metadata:
        spec:                           # Pod specification
          containers:
          - command:                       # Command
            - curl
            - https://example.com
            image: registry.access.redhat.com/ubi9/ubi:9   # Container image
            name: test
            resources: {}
          restartPolicy: OnFailure
  schedule: 0 0 * * *                # Cron job schedule
```

Application maintenance CronJob (WordPress backup example):
```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: wordpress-backup
spec:
  schedule: 0 2 * * 7                # Every Sunday at 2 AM
  jobTemplate:                        # Kubernetes job template
    spec:
      template:                         # Kubernetes pod template
        spec:                             # Kubernetes pod specification
          dnsPolicy: ClusterFirst
          restartPolicy: Never
          containers:                       # Pod container configuration
          - name: wp-cli
            image: registry.io/wp-maintenance/wp-cli:2.7    # Image running the maintenance task
            resources: {}
            command:                             # Command to execute inside the pod
            - bash
            - -xc
            args:                                  # Maintenance commands to execute
            - >
              wp maintenance-mode activate ;
              wp db export | gzip > database.sql.gz ;
              wp maintenance-mode deactivate ;
              rclone copy database.sql.gz s3://bucket/backups/ ;
              rm -v database.sql.gz ;
```

Cluster maintenance ConfigMap (image-pruning script):
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: maintenance
  app: crictl
data:
  maintenance.sh: |
    #!/bin/bash
    NODES=$(oc get nodes -o=name)          # List cluster nodes
    for NODE in ${NODES}                     # Iterate over nodes
    do
      echo ${NODE}
      oc debug ${NODE} -- \                    # Run a debug pod on the node
        chroot /host \
          /bin/bash -xc 'crictl images ; crictl rmi --prune'   # Prune unused images
      echo $?
    done
```

Cluster maintenance CronJob (mounts the script ConfigMap):
```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: image-pruner
spec:
  schedule: 0 * * * *
  jobTemplate:
    spec:
      template:
        spec:
          dnsPolicy: ClusterFirst
          restartPolicy: Never
          containers:
          - name: image-pruner
            image: quay.io/openshift/origin-cli:4.18       # Provides the oc CLI
            resources: {}
            command:
            - /opt/maintenance.sh                             # Path to the mounted script
            volumeMounts:                                       # Mounting the ConfigMap as a volume
            - name: scripts
              mountPath: /opt
          volumes:                                               # Mounting the ConfigMap as a volume
          - name: scripts
            configMap:
              name: maintenance
              defaultMode: 0555
```

## Exam Tips / Gotchas
- CronJobs create a **Job** resource each time they run due — that Job is otherwise a completely standard Kubernetes Job.
- YAML **folded style (`>`)** converts newlines to spaces — this is what allows a multi-line-looking command block to be passed as a **single string argument** to `bash -xc`; commands within it must be separated by `;`.
- Cluster-level maintenance tasks (e.g. pruning images cluster-wide) typically require a **privileged service account** — assign via `spec.serviceAccountName` in the pod definition, or change later with `oc set serviceaccount`.
- `crictl rmi --prune` must be run **inside a debug pod with `chroot /host`** to access and clean node-level image storage.
- Day of week `0` and `7` both represent **Sunday** in the cron schedule.

## Glossary
- **Job**: Kubernetes resource for a one-time task execution.
- **CronJob**: Kubernetes resource that creates Jobs on a defined schedule.
- **jobTemplate**: the CronJob field defining the Job (and its pod template) to create on each scheduled run.
- **YAML folded style (`>`)**: YAML block style that converts newlines to spaces, useful for multi-line shell command strings.
- **crictl rmi --prune**: command removing unused container images on a node.
