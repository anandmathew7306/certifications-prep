## Quick Summary
Covers the operator pattern (custom resources + a controller that manages complex workloads), the distinction between cluster operators (platform services, managed by CVO) and add-on operators (managed by OLM via catalogs), how to inspect cluster operator health, how OLM catalogs/PackageManifests/Subscriptions work, and SDKs available for building custom operators.

## Key Concepts
- **Operator pattern** — reusable way to manage complex workloads (e.g. multi-component apps, or workloads needing automated maintenance like backups/updates) beyond what plain Deployments/StatefulSets/DaemonSets/Jobs/CronJobs can easily handle; admins create Custom Resources (CRs) describing the desired workload, and the operator creates/manages the underlying Kubernetes resources.
- **Custom Resource Definitions (CRDs) + CR watching** — an operator defines CRDs; the operator watches the cluster for CR instances and creates matching Kubernetes resources (e.g. a database CR might cause the operator to create a StatefulSet + PersistentVolume, and a CronJob if a backup schedule/target is specified).
- **Cluster operators** — provide OpenShift's own platform services (e.g. web console, OAuth server).
- **Add-on operators** — supplemental operators managed by the Operator Lifecycle Manager (OLM) that add features to the cluster, distinct from cluster operators (platform services).
- **Other operators** — software from other providers implementing the operator pattern, distributed via manifests, Helm charts, or other mechanisms.
- **Cluster Version Operator (CVO)** — installs and updates cluster operators as part of OpenShift install/update processes; provides `ClusterOperator` type resources reflecting cluster operator status/health.
- **ClusterOperator status conditions** — include AVAILABLE, PROGRESSING, DEGRADED, and a MESSAGE describing the latest condition — useful for diagnosing cluster issues.
- **Operator Lifecycle Manager (OLM)** — helps install/update/remove add-on operators; itself follows the operator pattern (provides CRs to manage operators via the Kubernetes API).
- **Operator catalog** — container image providing metadata (descriptions, available versions) about installable operators; sources for OLM to discover operators.
- **Default OpenShift catalogs** — Red Hat (packaged/shipped/supported by Red Hat), Certified (supported by independent software vendors), Community (community-developed, unofficial support), Marketplace (commercial operators purchasable via Red Hat Marketplace — **deprecated**, planned for removal starting RHOCP 4.22; use the Certified catalog version or contact vendors instead).
- **Custom/mirrored catalogs** — administrators can create their own catalogs or mirror catalogs for offline/disconnected clusters.
- **PackageManifest** — resource type the OLM creates for each available operator (used by the web console to display available operators/installation wizard).
- **Subscription CR** — used (along with other CRs) to install operators without the web console wizard.
- **OLM-managed vs. cluster operator lifecycle** — CVO installs/updates cluster operators in alignment with the overall cluster version; OLM lets administrators install/update/remove add-on operators **independently** from cluster updates.
- **Two workload sets per operator** — (1) the operator's own workload, managed by the OLM; (2) the workloads associated with the operator's custom resources, managed by the operator itself.
- **Operator SDK** — tools to develop operators using Go or Ansible; also supports packaging Helm charts as operators.
- **Java Operator SDK** — tools to develop operators using Java; includes a Quarkus extension for developing operators with the Quarkus framework.

## Operators
- **Cluster Version Operator (CVO)** — installs and updates cluster operators as part of OpenShift install/update.
- **Operator Lifecycle Manager (OLM)** — manages installation, update, and removal of add-on operators; provides CRs (e.g. Subscription) for operator management.
- *(Cluster operators / add-on operators in general are the subject of this page rather than named individually — see Key Concepts for the categories.)*

## Comparisons
| Aspect | Cluster Operators | Add-on Operators (OLM-managed) |
|---|---|---|
| Purpose | Provide OpenShift platform services (e.g. web console, OAuth server) | Add supplemental features to the cluster |
| Managed by | Cluster Version Operator (CVO) | Operator Lifecycle Manager (OLM) |
| Lifecycle | Installed/updated in alignment with cluster version | Installed/updated/removed independently of cluster updates |
| Status resource | `ClusterOperator` | `PackageManifest` (availability), `Subscription` (install/manage) |

| Catalog | Support Level |
|---|---|
| Red Hat | Packaged, shipped, and supported by Red Hat |
| Certified | Supported by independent software vendors |
| Community | Community-developed, no official support |
| Marketplace | Commercial, purchasable via Red Hat Marketplace — **deprecated**, planned removal from RHOCP 4.22 |

## Exam Tips / Gotchas
- The **Marketplace catalog is deprecated** and Red Hat plans to **remove it starting from RHOCP 4.22** — use the Certified catalog version of these operators, or contact the vendor directly.
- **CVO** manages cluster operators (platform services) **in lockstep with cluster version**; **OLM** manages add-on operators **independently** — know this distinction for lifecycle-related questions.
- A cluster maintains **two separate workload sets per operator**: the operator's own workload (OLM-managed) and the CR-derived workloads (operator-managed).
- `oc get clusteroperator` output's MESSAGE column reflects the **latest condition** — useful first stop for diagnosing cluster operator issues.

## Glossary
- **Operator pattern**: approach where a controller watches custom resources and manages the underlying Kubernetes resources for a complex workload.
- **CRD (Custom Resource Definition)**: defines a new resource type an operator uses to describe its managed workload.
- **CVO**: Cluster Version Operator — installs/updates cluster operators as part of cluster install/update.
- **OLM**: Operator Lifecycle Manager — installs/updates/removes add-on operators.
- **PackageManifest**: OLM-created resource representing an available operator in a catalog.
- **Subscription (CR)**: resource used to install/manage an operator via OLM.
- **Operator catalog**: container image providing metadata about installable operators.
