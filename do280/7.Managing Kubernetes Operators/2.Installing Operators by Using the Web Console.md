## Quick Summary
Covers using the OpenShift web console (OperatorHub / Installed Operators pages) to install, configure, view, use, and troubleshoot operators managed by the Operator Lifecycle Manager (OLM), including install wizard options (update channel, installation mode, installed namespace, update approval) and CSV/Subscription resources.

## Key Concepts
- **OperatorHub page** — (Operators → OperatorHub) lists available operators; filterable by category, source, provider, subscription requirement, etc.
- **Update channel** — a defined stream of versions (e.g. `stable`, `fast`) that an operator subscription follows to receive upgrades.
- **Installation mode** — "All namespaces on the cluster (default)" configures the operator to monitor **all** namespaces for its custom resources; suitable for most operators; can be combined with self-service features, RBAC, and network policies to control usage.
- **Installed namespace** — the namespace where the OLM installs the **operator workload itself**; some operators default to `openshift-operators`, others suggest a dedicated namespace; typically only cluster administrators need access to the operator workload (users may still need access to the workloads the operator manages).
- **Installation mode vs. installed namespace** — distinct, related settings: installation mode = which namespaces are **monitored** for CRs; installed namespace = where the **operator's own workload** runs.
- **Update approval** — default is automatic updates when new versions are available; can be set to manual to prevent automatic updates.
- **Monitoring option** — shown for operators that include monitoring in their definition; enabling monitoring from **non-Red Hat operators is not supported**.
- **Subscription and OperatorGroup resources** — created by the web console based on wizard selections when installing an operator.
- **ClusterServiceVersion (CSV)** — every version of an operator has a CSV; the OLM uses CSV info to install the operator and updates the CSV's `status` key with installation info; CSVs are namespaced; operators installed in "all namespaces" mode have a CSV present in **every** namespace.
- **Operator details page tabs** — Details (CSV info), YAML (CSV in YAML), Subscription (change update channel/approval; links to install plans; approve install plans for manual updates), Events (operator-related events); plus per-custom-resource-type tabs and an "All instances" tab aggregating all CR types the operator defines.
- **Creating custom resources** — via the custom resource tabs on Installed Operators; supports YAML view (editor with starting template + schema documentation, same info as `oc explain`) or Form view (individual fields, may include dropdowns/help text, but might not expose every possible option).
- **Operator Deployments field** — on the Operator details page; shows the operator's own workload(s) — starting point for troubleshooting; operators may also create further workloads based on user-provided custom resources.
- **Troubleshooting starting points** — CSV/Subscription/install plan status and conditions (installation issues); Kubernetes workload status (deployments/statefulsets), pod logs/status, and events (runtime issues).

## Exam Tips / Gotchas
- **Installation mode** and **installed namespace** are **distinct** settings — don't confuse "which namespaces the operator watches" with "where the operator's own pod runs."
- Enabling monitoring is **not supported for non-Red Hat operators**, even if the wizard shows the option.
- **CSVs are namespaced** — an operator installed with "All namespaces" mode will show a CSV in every namespace.
- Manual update approval requires you to **approve install plans** from the Subscription tab for updates to actually apply.
- Always **review operator documentation before installing**, since installation mode/namespace support and other options vary per operator.
- When troubleshooting a malfunctioning operator, start with **CSV, Subscription, and install plan** status/conditions for installation issues, and **Operator Deployments** (workload status, pod logs, events) for runtime issues.

## Glossary
- **OperatorHub**: web console page listing available operators for installation.
- **CSV (ClusterServiceVersion)**: namespaced resource representing a specific version of an installed operator; OLM uses it to install/track the operator.
- **Subscription**: resource specifying an operator's update channel and approval strategy.
- **Install plan**: resource representing a pending/approved operator installation or update, used especially with manual approval.
- **Update channel**: named stream of operator versions (e.g. stable, fast) that a subscription follows.
