## Quick Summary
Covers installing/managing operators via the OLM CLI/API resources: catalog sources, package manifests, operator groups, subscriptions, install plans, CSVs — including how to inspect available operators, install via subscription + operator group, manage automatic/manual update approvals, change update channels, and troubleshoot installation/runtime issues.

## Key Concepts
- **Operator installation steps** — locate the operator → review documentation/requirements (update channel, installation mode, target namespace, update approval mode) → create an operator group if needed → create a namespace if needed → create the subscription → review/test the installation.
- **Catalog source** — resource referencing an operator repository; OLM periodically examines catalog sources to retrieve operator info.
- **Package manifest** — created by OLM for each available operator; contains info required to install it (e.g. available channels).
- **Operator group** — defines how OLM presents operators across namespaces; determines which namespaces an operator monitors for CRs.
- **Subscription** — created by cluster administrators to install an operator; specifies channel, package name, source catalog, install plan approval mode, target namespace.
- **Operator (resource)** — created by OLM to store info about an installed operator (including references to its install plan).
- **Install plan** — created by OLM as part of install/update; requires manual approval when the subscription's approval mode is Manual.
- **ClusterServiceVersion (CSV)** — one per operator version; contains the info OLM needs to install that version (including which deployments to create and which CRDs it owns).
- **Manual resource creation requirement** — administrators need only create the **Subscription** and (if needed) the **OperatorGroup** — OLM generates all other resources (package manifest, operator, install plan, CSV) automatically.
- **global-operators operator group** — pre-existing in the `openshift-operators` namespace; operators installed there use this group and monitor **all** namespaces by default.
- **Install mode types (from package manifest)** — e.g. `OwnNamespace`, `SingleNamespace`, `MultiNamespace`, `AllNamespaces` — each marked Supported: true/false per operator, indicating which namespace-targeting patterns the operator allows.
- **spec.installPlanApproval (Subscription field)** — `Automatic` (OLM applies updates as soon as available) or `Manual` (OLM creates an InstallPlan but does not approve it — admin must manually approve).
- **Pending update detection** — `oc get installplan -n <namespace>` shows an APPROVED column; a pending manual-approval update shows `APPROVED: false`.
- **Changing update channel** — patch the Subscription's `spec.channel` field; with Automatic approval this may immediately trigger an update; with Manual approval it may create a new install plan requiring approval.
- **CSV CRD listing** — a CSV's `spec.customresourcedefinitions` field lists the CRDs the operator owns — usable to discover what custom resources an operator provides.
- **Two workload types per operator (troubleshooting relevance)** — (1) the operator's own workload monitoring CRs, and (2) workloads created for individual CR instances; `spec.install.spec.deployments` in the CSV typically lists the deployments OLM creates for #1, but the operator may create further deployments for either category.

## Commands
| Command | What it does | Key flags/options |
|---|---|---|
| `oc get catalogsource -n openshift-marketplace` | Lists available catalog sources | `-n` |
| `oc get packagemanifests` | Lists available operators (package manifests) from configured catalogs | — |
| `oc describe packagemanifest lvms-operator -n openshift-marketplace` | Shows detailed info about an operator (catalog source, channels, CSV, install modes, CRDs, links) | `-n` |
| `oc describe operator file-integrity-operator` | Shows an installed operator resource, including install plan references | — |
| `oc patch installplan install-pmh78 --type merge -p '{"spec":{"approved":true}}' -n openshift-file-integrity` | Approves a pending install plan | `--type merge`, `-p`, `-n` |
| `oc get installplan -n openshift-file-integrity` | Lists install plans and their approval status (CSV, APPROVAL mode, APPROVED true/false) | `-n` |
| `oc patch subscription file-integrity-operator -n openshift-file-integrity --type merge -p '{"spec":{"channel":"<new-channel-name>"}}'` | Changes an operator's update channel | `--type merge`, `-p`, `-n` |
| `oc get csv metallb-operator.v4.18.0-202401151553 -o jsonpath="{.spec.customresourcedefinitions.owned[*].name}{'\n'}"` | Lists the CRDs an operator's CSV owns | `-o jsonpath` |
| `oc explain` | Views documentation/description for a specific CRD | — |

## Config / YAML Snippets
OperatorGroup definition:
```yaml
apiVersion: operators.coreos.com/v1
kind: OperatorGroup
metadata:
  name: name
  namespace: namespace            # Operators follow the group in their deployed namespace
spec:
  targetNamespaces:                 # Namespaces the operator monitors for CRs (or use spec.selector for label-based selection)
  - namespace
```

Subscription definition:
```yaml
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: lvms-operator
  namespace: openshift-storage       # Namespace for the operator workload
spec:
  channel: stable-4.18                 # Update channel (from oc describe packagemanifest)
  name: lvms-operator                    # Package manifest to subscribe to
  source: gls-catalog-cs                   # Source catalog (from oc describe packagemanifest)
  installPlanApproval: Automatic             # Automatic or Manual
  sourceNamespace: openshift-marketplace
```

## Comparisons
| Aspect | Automatic (installPlanApproval) | Manual (installPlanApproval) |
|---|---|---|
| Update behavior | OLM applies updates as soon as available | OLM creates an InstallPlan but does NOT approve it |
| Admin action required | None | Must manually approve the InstallPlan (`spec.approved: true`) |
| Channel change effect | May automatically trigger an update | May create a new install plan requiring approval |

| Install Mode | Meaning |
|---|---|
| OwnNamespace | Operator can watch only its own installed namespace |
| SingleNamespace | Operator can watch a single specified namespace |
| MultiNamespace | Operator can watch multiple specified namespaces |
| AllNamespaces | Operator can watch all namespaces in the cluster |

## Exam Tips / Gotchas
- Administrators only need to manually create the **Subscription** (and **OperatorGroup**, if the default doesn't fit) — **all other OLM resources are auto-generated** (package manifest, operator, install plan, CSV).
- The `global-operators` operator group in `openshift-operators` causes operators installed there to **monitor all namespaces** by default.
- Not all operators support all install modes — check the package manifest's **Install Modes** section (e.g. `lvms-operator` supports only `OwnNamespace`/`SingleNamespace`, not `AllNamespaces`).
- With **Manual** install plan approval, a pending update shows `APPROVED: false` in `oc get installplan` — must be patched to `true` to proceed.
- Changing the update channel via `oc patch subscription` can **trigger an immediate update** if approval mode is Automatic, or **create a new install plan** requiring manual approval if Manual.
- Even if OLM installs an operator **successfully**, the operator itself **might not function correctly** — always check both the operator's own workload AND CR-derived workloads when troubleshooting.
- `spec.install.spec.deployments` in the CSV typically lists the operator's **own** workload deployments — but operators can create **additional** deployments beyond what's listed there (for either their own operation or from custom resource instances).

## Glossary
- **Catalog source**: resource referencing an operator repository.
- **Package manifest**: OLM-generated resource with install info for an available operator.
- **OperatorGroup**: defines the namespace scope an operator monitors.
- **Subscription**: admin-created resource specifying how to install/update an operator.
- **Install plan**: OLM resource representing an install/update process, requiring approval when manual.
- **CSV (ClusterServiceVersion)**: per-version resource containing operator install info, including owned CRDs and deployments.
- **installPlanApproval**: Subscription field controlling Automatic vs Manual update approval.
